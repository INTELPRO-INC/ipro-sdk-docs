# 疑難排解

依畫面上的訊息、工具列與側邊欄的狀態，以及作業系統，列出 IPRO Workbench 常見的狀況與處理方式。訊息照畫面原文列出，「…」是會依應用程式、連接埠或大小而變的部分。

## 畫面上的訊息 { #messages }

IDE 在每一步失敗時都會跳出說明與處理按鈕。下表依訊息列出原因與處理方式。

| 畫面上的訊息 | 原因 | 怎麼做 |
|---|---|---|
| 開發板在 … 沒有回應 | 探棒排線沒接好、開發板沒電，或連接埠選錯 | 檢查線材與電源，按 **選擇連接埠** 或 **重試** |
| … 正被其他程式使用，IntelProCube 無法開啟 | 另一個序列埠監看或終端機開著同一個連接埠 | 關掉那個程式後按 **重試** |
| … 尚未建置 | 還沒有韌體可以燒錄 | 按 **建置並燒錄** |
| 燒錄需要 IntelProCube，但找不到它 | 沒有安裝 IntelProCube | 按 **安裝 IntelProCube**，或 **瀏覽…** 指定已有的 |
| … 編譯失敗。第一個錯誤在 … | 程式碼有錯 | 按 **前往錯誤**；「問題」面板列出所有錯誤。也可以按 **請 AI 修正** |
| CMake 無法設定 … | `.config` 或 `CMakeLists.txt` 有誤 | 看 **IPRO Build** 輸出，修正後按 **重新設定並建置** |
| 缺少工具鏈或建置工具 | 開發環境還沒補齊 | 按 **補齊環境** |
| … 的 pins.yaml 有錯誤，所以沒有產生 app_pins.c | 腳位設定有衝突，或訊號不在那支腳上 | 按 **開啟腳位設定**，依「問題」逐項修正後按 **儲存並產生** |
| 板子啟動的是 … 建置的韌體，不是剛燒錄的 … | 燒錄沒有真正寫進板子 | 看 **IPRO Flash** 輸出，按 **重新燒錄** |
| … 超出記憶體預算 | 某個記憶體區段超過 `ipro.build.memoryBudget` 的上限 | 按 **記憶體分佈** 找出大的符號，或按 **預算設定** 調整上限 |
| … 的分割表用到 …，但這個探棒上的板子只有 … 的 Flash | 選的分割表比板子的 Flash 大 | 按 **分割表** 改選，或確認 `.config` 的 Flash 大小 |
| IntelProCube 沒有 …，也就是 … 燒錄要用的分割表；少了它，板子燒完會開不了機。 | IntelProCube 的版本沒有這塊板子要用的分割表（IPRO6S EVK 需要 0.7.0.1 以上的 `partition_cfg_fw_direct.toml`） | 按 **安裝 IntelProCube**，或在「開發環境」的 IntelProCube 一列改選 0.7.0.1 以上的版本，再燒錄一次 |
| mfg 與 FW 使用同一塊空間…（分割表與 AI 模型畫面的檢查結果） | 1M 分割表沒有給 AI 模型的獨立空間 | 在「分割表」選有獨立 mfg 的分割表（例如應用程式附的那份） |
| 板子沒有回應。它跑的是 MFG 韌體嗎？ | RF 測試時，板子跑的不是 MFG 韌體，或監看沒開 | 燒入 MFG 韌體，開監看後按 **檢查韌體** |
| 「測試」檢視沒有結果 | 板子沒有重新開機，或應用程式沒有使用 Unity 測試框架 | 確認監看接在探棒的 UART 連接埠後，按 **在板子上執行測試** |
| 板子沒有回應 wifi_state。請燒錄帶有 Wi-Fi 指令與 iperf 的應用程式… | Wi-Fi 傳輸速率：板子上的應用程式沒有 Wi-Fi 指令，或監看開在別的連接埠 | IPRO6S EVK 燒錄 `platform/ipro6_demo`；在工具頁的「板子」選這塊板子的連接埠 |
| 網路名稱要 1 到 32 個字元，而且不能有空白…／密碼要 8 到 63 個字元，而且不能有空白。 | 板子的指令列不接受空白 | 改用沒有空白的網路名稱與密碼（必要時在無線基地台上另設一個網路） |
| 板子沒有連上 …。請檢查名稱與密碼。 | 名稱或密碼打錯，或該網路不是 2.4 GHz | 修正後再按 **加入網路** |
| 這台電腦在板子的網路（…）上沒有位址。 | 電腦和板子不在同一個 Wi-Fi 網路 | 讓電腦連上同一個網路（基地台模式是連上板子建立的網路），再按 **執行測試** |
| 板子沒有連到這台電腦的 TCP 連接埠 5001。可能是這台電腦的防火牆擋住了連入的連線… | 板子送、電腦收時，電腦的防火牆擋住連入的連線（Windows 的預設） | 讓防火牆允許連入 TCP 5001（見 [Wi-Fi 傳輸速率：執行測試](measure.md#iperf-run)），或改用電腦送、板子收 |
| 這台電腦連不上板子的 iperf 伺服器…／板子上前一次的 iperf 還在執行… | 板子的 iperf 伺服器還在等待連線 | 按 **重置板子**，板子重新開機後重新加入網路 |
| 板子沒有重新啟動。監看是否接在 IPRO Debug Probe 的主控台連接埠？ | 監看開在 CCI 或其他連接埠 | 按工具列的開發板，**選擇連接埠…** 改回探棒的 UART |

## 工具列與側邊欄的狀態 { #status }

| 看到的狀態 | 怎麼做 |
|---|---|
| 工具列顯示琥珀色的「無探棒」 | IDE 找不到 IPRO 除錯探棒。檢查 USB 線，盡量直接接電腦；探棒接上後幾秒內會自動出現。 |
| 狀態列顯示「環境：N 項待處理」 | 按一下開啟首頁，依橫幅按 **補齊環境**。 |
| 「開發板」顯示「執行中：其他韌體」 | 板子上的不是目前應用程式最近一次建置的韌體。要執行目前的程式，請燒錄。 |
| IPRO6S EVK 的「開發板」沒有「執行中：…」一行 | 正常。IPRO6 系列的板子開機時不印建置時間，IDE 無法核對板子上的韌體；請以 **IPRO Flash** 的 `[All Success]` 與監看的開機訊息確認（見[和 IPRO7 系列不同的地方](flash.md#ipro6s-differences)）。 |

## macOS 特有的狀況 { #macos }

| 狀況 | 怎麼做 |
|---|---|
| 第一次開啟時說無法驗證開發者 | 到「系統設定 → 隱私權與安全性」，按 **仍要打開**（見[安裝](install.md#install)）。 |
| 「開發環境」出現「macOS 隔離標記」 | 工具是用瀏覽器或聊天軟體下載的，執行時會被系統擋下。按該列的鎖頭圖示，確認後移除標記。 |
| CMake 或建置程式顯示找不到 | macOS 的建置工具不由 IDE 安裝。在終端機執行 `xcode-select --install` 與 `brew install cmake ninja` 後，按 **重新檢查**。 |
| 燒錄中途失敗，`Device not configured` | 探棒在 USB 上斷線（線材、集線器或供電）。換線或直接接電腦，再按 **重試**。 |

## Windows 特有的狀況 { #windows }

| 狀況 | 怎麼做 |
|---|---|
| 安裝時顯示「Windows 已保護您的電腦」 | 按 **其他資訊**，確認應用程式名稱是 IPRO-Workbench 後按 **仍要執行**。 |
| 用其他序列埠工具時打不開 COM 埠 | Windows 的 COM 埠同時只能給一個程式使用。先關閉 IPRO Monitor，再開其他工具；用完後關掉它，IDE 才能燒錄。 |
| 「配合此工具鏈的 SDK」顯示需要調整 | IPRO SDK 2.2 在 Windows 上建置前需要幾項主機修正。按 **補齊環境**（或該列的 **讓 SDK 配合此工具鏈**），IDE 會自動處理。 |
| Wi-Fi 傳輸速率：板子送、電腦收時沒有結果 | Windows 防火牆預設擋下連入的連線。新增一條允許 TCP 連接埠 5001 的輸入規則（見 [Wi-Fi 傳輸速率：執行測試](measure.md#iperf-run)），或改用電腦送、板子收。 |
| Python 一列顯示沒有 kconfiglib | 在命令提示字元執行 `python -m pip install kconfiglib windows-curses`，再按 **重新檢查**。 |
| 程式碼編輯器提示要下載 clangd | 程式碼導覽使用 clangd。依提示讓它下載即可，或在「開發環境」的 clangd 一列按修復。 |

## 收集問題資訊 { #collect }

回報問題給 INTELPRO 時，請附上：

1. IDE 的版本：選「說明 → 關於」。
2. 出問題那一步的輸出：在「輸出」面板選 **IPRO Build**、**IPRO Flash** 或 **IPRO Setup**，全選後複製。
3. 板子的輸出：在 IPRO Monitor 頁籤按 **儲存監看輸出…**，或附上 `build/logs` 裡的監看記錄。
4. 當機時，附上 `build/crash` 裡的當機傾印資料夾。
