統一建構 CLI（build_freertos.sh）

./build_freertos.sh 位於 SDK 根目錄，是 Release SDK 內建的統一開發入口。它可以將多個 action 串接成一條指令，依序執行。

指令格式 
./build_freertos.sh [actions...] [options] <project>

Actions

Action 說明
build 建構專案（未指定 action 時的預設值）
clean 清除建構目錄
flash 燒錄韌體到開發板
monitor 開啟序列埠監控
size 顯示 ELF 大小與各記憶體區域用量
test 建構 + 燒錄 + 監控，並等待自動測試結果 pattern

選項

選項 說明 預設值
-p, --port PORT 序列埠裝置路徑（flash / monitor / test 使用） 請依實際裝置指定（如 /dev/cu.usbserial-XXXX）
-t, --timeout SEC monitor / test 的逾時秒數 30
-w, --wait-for PAT monitor 等待的正規表達式 pattern -
-d, --defconfig FILE 使用替代 defconfig（建構輸出於 build_<name>/） -
-j, --jobs N 平行建構任務數 -
-v, --verbose 顯示完整建構輸出 -
-l, --list 列出所有可用專案 -
-h, --help 顯示說明 -

常用範例

統一 CLI 範例 
# 列出所有可用專案
./build_freertos.sh -l

# 建構（預設 action）
./build_freertos.sh platform/ipro7_demo

# 清除後重新建構
./build_freertos.sh clean build platform/ipro7_demo

# 建構 → 燒錄 → 監控（完整開發循環）
./build_freertos.sh build flash monitor bluetooth/ble/ipro_ble_remote

# 顯示 ELF 大小與各記憶體區域用量
./build_freertos.sh size platform/ipro7_demo
flash 與 test 需要另行取得的 IntelProCube 命令列工具（設定 IPRO_FLASH_TOOL 或將工具目錄加入 PATH）。monitor 與 test 使用隨附的 tools/serial_monitor.py，以 115200 鮑開啟 -p 指定的序列埠並先送出 reboot，於 -t 秒後結束；主控台為其他鮑率時，請直接執行 serial_monitor.py 並指定 --baud。

燒錄工具

⚠️ IntelProCube v0.6.3 命令列工具（ipro_iot_tool.exe、ipro_iot_tool_macos、ipro_iot_tool_linux）未包含於 IPRO SDK V2.1.0，請向 INTELPRO 取得。./build_freertos.sh flash <project> 會使用 IPRO_FLASH_TOOL 指定的工具，或 PATH 上對應主機的工具。

IPRO SDK 使用 IntelProCube 命令列工具將編譯好的韌體燒錄到開發板的 Flash 記憶體中。

基本用法

燒錄韌體 
# 於 IntelProCube 目錄執行（Linux 為 ipro_iot_tool_linux，Windows 為 ipro_iot_tool.exe）
# 序列埠路徑請依實際接上的裝置調整
./ipro_iot_tool_macos --chipname ipro7 --chip-variant IPRO7 \
    --port /dev/cu.usbserial-XXXX \
    --baudrate 921600 \
    --firmware <SDK>/apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.bin

# IPRO7AI Reef EVK（2 MB Flash）
./ipro_iot_tool_macos --chipname ipro7 --chip-variant IPRO7AI \
    --port /dev/cu.usbserial-XXXX \
    --baudrate 921600 \
    --pt chips/ipro7/partition/partition_cfg_2M.toml \
    --firmware <SDK>/apps/platform/ipro7ai_reef_demo/build/build_out/ipro7ai_reef_demo_IPRO7.bin

參數說明

參數 說明 範例值
--chipname 目標晶片型號 ipro7
--chip-variant 板型的 Flash 腳位配置：IPRO7（flash pin 0x2）或 IPRO7AI（0x9，IPRO7AI EVK／Reef EVK） IPRO7
--port 序列埠裝置路徑 /dev/cu.usbserial-XXXX（macOS，依實際裝置而定）
/dev/ttyUSB0（Linux）
--firmware 韌體二進位檔路徑 apps/.../build/build_out/*.bin
--baudrate 燒錄傳輸速率 921600
--pt 分割表；IPRO7AI Reef EVK 使用 2 MB 分割表 chips/ipro7/partition/partition_cfg_2M.toml
⚠️ 工具沒有 --flash-pin 選項，且燒錄失敗時也會以 0 結束；請以輸出中的 [All Success] 判斷結果（./build_freertos.sh flash 已自動檢查）。build_freertos.sh 呼叫工具時不帶 --chip-variant 與 --pt；IPRO7AI EVK 與 Reef EVK 請直接執行工具並指定 --chip-variant IPRO7AI，或依應用 README 調整工具設定檔中的 flash pin。

進入下載模式

燒錄前需要讓開發板進入下載模式。./build_freertos.sh flash 會先以 tools/serial_monitor.py（115200 鮑）送出 reboot_dl；主控台為其他鮑率或韌體沒有 shell 時，請手動送出指令，或依開發板手冊以 BOOT 腳位進入下載模式：

進入下載模式 
# 主控台 115200 鮑的韌體
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --send reboot_dl --timeout 2

# 主控台 921600 鮑的韌體（macOS）
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --baud 921600 --send reboot_dl --timeout 2
⚠️ macOS 上必須使用 /dev/cu.* 裝置路徑，不要使用 /dev/tty.*，否則會因為等待 DCD 訊號而無限阻塞。

序列埠監控

V2.1.0 隨附 tools/serial_monitor.py：以 Python 標準函式庫的 termios 開啟序列埠（不需 pyserial），可送出一行指令、等待正規表達式 pattern，並將輸出存檔。適用 macOS 與 Linux；Windows 請使用 Extension 的 IPRO: Serial Monitor 或其他序列埠終端。

序列埠監控範例 
# 監看 60 秒（預設 115200 鮑）
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --timeout 60

# 送出 reboot 並等待測試結果
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --send reboot \
    --wait-for "ALL TESTS PASSED|SOME TESTS FAILED" --timeout 30

# 921600 鮑並存檔（macOS）
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --baud 921600 --timeout 60 --log console.log
選項 說明 預設值
--baud鮑率115200
--timeout監看秒數30
--send開始監看前送出的指令（例如 reboot、reboot_dl）-
--wait-for等待的正規表達式 pattern，符合即結束-
--log將原始輸出存檔-

結束碼：符合含 PASSED 的 pattern 為 0，符合其他 pattern 為 1，逾時為 2，無法開啟序列埠為 3。

主控台鮑率

FreeRTOS 應用的主控台鮑率由各應用的 CONFIG_PLATFORM_UART_BAUDRATE 決定，預設 115200；IPRO7AI Reef EVK 的主控台位於 U6 連接器。下列應用使用 921600：ipro7ai_evk_demo、ipro7ai_evk_launcher、ipro7ai_evk_rps、ipro_meeting_poc、ipro7_uvc_cam、ipro_epd_el036。Zephyr 映像（ipro7_evb、ipro7ai_evk）的主控台為 UART0 2,000,000 鮑。

macOS 以外的主機上，serial_monitor.py 只支援至 230400 鮑；921600 或 2,000,000 鮑請改用其他序列埠終端。macOS 使用 /dev/cu.*；燒錄前停止監看以釋放序列埠。

Zephyr 工具（tools/zephyr）

自 V2.1.0 起，SDK 同時是 Zephyr v4.4.0 模組，支援 ipro7_evb（IPRO7 EVB）與 ipro7ai_evk（IPRO7AI EVK）。tools/zephyr/ 提供下列腳本；完整說明見 Zephyr RTOS。

腳本 用途
bootstrap.sh在 zephyr-workspace/ 建立 west 工作區：下載 Zephyr v4.4.0 及 west.yml 列出的模組，並套用 zephyr/patches.yml；-w DIR 指定位置，IPRO_TOOLCHAIN 指定工具鏈路徑
build.sh建構 Zephyr 應用：-b ipro7_evb（預設）或 ipro7ai_evk，-p 全新建構，-d 建構目錄；應用可為路徑或 zephyr/samples/ 下的範例名稱
flash.sh以 IntelProCube 命令列工具燒錄 zephyr.bin（--build-dir 或 .bin 路徑、--port），燒錄前經 serial_monitor.py 送出 reboot_dl
monitor.sh以 2,000,000 鮑開啟 UART0 主控台（--port、--baud、--timeout）
ci_build.sh建構範例矩陣（全新建構、警告視為錯誤）並列出映像大小；以 -b 指定 ipro7_evb 或 ipro7ai_evk，-q 只建構 hello_world 與 blinky
Zephyr 快速開始 
tools/zephyr/bootstrap.sh          # west 工作區建於 zephyr-workspace/
source zephyr-workspace/env.sh     # ZEPHYR_BASE、CROSS_COMPILE、west
cd zephyr-workspace
west build -b ipro7_evb zephyr/samples/hello_world
west build -b ipro7_evb ../zephyr/samples/periph_smoke -d build/smoke
west flash                         # IntelProCube 命令列工具：$IPRO_FLASH_TOOL 或 PATH

首次執行 bootstrap.sh 會從 GitHub 下載 Zephyr 與模組，需要 Python 3.10+、CMake 3.20 以上、Ninja、git、dtc 及 IPRO RISC-V 工具鏈（/opt/toolchain/riscv_ipro7）。

west flash 預設透過 IPRO7 CMSIS-DAP probe 進入下載模式；沒有 probe 時使用 west flash -- --boot shell（由執行中映像的 reboot_dl 進入）或 --boot manual。序列埠以 --port 或 $IPRO_SERIAL_PORT 指定，未指定時使用唯一存在的 USB 序列埠。Zephyr 主控台為 UART0 2,000,000 鮑，與 FreeRTOS 應用不同；以 tools/zephyr/monitor.sh --port /dev/cu.usbserial-XXXX --timeout 60 指定監看秒數開啟。

板上測試

SDK 已包含 apps/test/ipro_unit_test/，測試 HAL 與共用元件。建置後以另行取得的燒錄工具寫入對應板子，再由序列埠確認 ALL TESTS PASSED 或 SOME TESTS FAILED。

make -C apps/test/ipro_unit_test

tools/board_test.sh 未隨附。./build_freertos.sh test ipro_unit_test 會建構、燒錄（需另行取得的 IntelProCube 命令列工具）、送出 reboot 並等待上述結果；結束碼 0 為通過、1 為失敗、2 為逾時（-t 調整秒數，預設 30）。

交付包中的 AI、ISP、RF、LC3 與低功耗框架函式庫以預編譯 .a 提供、不含原始碼；可正常連結，但無法於庫內進行原始碼層級單步除錯。

GDB 除錯

⚠️ OpenOCD 配置檔（tools/openocd/）未包含於 IPRO SDK V2.1.0，請洽 INTELPRO 取得。

IPRO SDK 支援透過 OpenOCD + GDB 進行 JTAG 除錯。IPRO7 的 JTAG 腳位為 GPIO0（TMS）、GPIO1（TDI）、GPIO2（TCK）、GPIO9（TDO）。

啟動 OpenOCD

啟動 OpenOCD 伺服器 
# 使用 SDK 提供的 OpenOCD 配置檔
# （通用 RISC-V JTAG 設定，IPRO6 / IPRO7 皆適用）
openocd -f tools/openocd/openocd_ipro6.cfg

# 啟動成功後會顯示：
# >>> Ready for GDB on port 12021

連接 GDB

啟動 GDB 並連接 
# 使用 SDK 工具鏈中的 GDB
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-gdb \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf

# 在 GDB 中連接 OpenOCD（連接埠由配置檔中的 gdb_port 指定，預設 12021）
(gdb) target remote :12021
(gdb) monitor reset halt
⚠️ 配置檔未定義 flash bank，無法在 GDB 中以 load 燒寫 XIP Flash（0x13000000）。韌體燒錄請使用燒錄工具；GDB 用於中斷點、單步執行與記憶體檢視。

常用 GDB 指令

指令 說明
b main 在 main 函式設定中斷點
b file.c:42 在指定檔案行號設定中斷點
c 繼續執行
s / n 單步進入 / 單步跳過
p variable 列印變數值
x/16xw 0x11010000 檢視記憶體內容（16 個 word）
bt 顯示呼叫堆疊
info reg 顯示暫存器狀態

當機分析

⚠️ parse_backtrace.py 未包含於 IPRO SDK V2.1.0，請洽 INTELPRO 取得。即使沒有此工具，也可以使用工具鏈內建的 addr2line 手動解析（見下方）。

當韌體發生異常（exception）時，異常處理程式會輸出異常 PC、SP（含所屬堆疊範圍）、saved s0(fp) / ra 與堆疊內容傾印。parse_backtrace.py 可以將這些位址轉換為對應的原始碼檔案與行號。

使用方式

從檔案解析 
# 從檔案讀取當機日誌
python3 tools/parse_backtrace.py \
    /opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf \
    backtrace.txt
從管線輸入 
# 從剪貼簿或管線輸入
cat backtrace.txt | python3 tools/parse_backtrace.py \
    /opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf

參數說明

參數 說明
toolchain_prefix 工具鏈前綴路徑（含尾部 -）
elf_file 對應的 ELF 檔案（包含除錯符號）
backtrace_file 當機日誌檔案（選擇性，可從 stdin 讀取）

手動解析（addr2line）

異常輸出中落在程式碼區段（例如 Flash 0x13000000 起）的位址，可以直接用工具鏈內建的 addr2line 轉為函式名稱與原始碼位置：

addr2line 手動解析 
# 將單一位址轉為函式名稱與原始碼位置
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-addr2line \
    -e apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf \
    -f -C 0x1301c148
💡 解析需要帶有除錯符號的 ELF 檔案（.elf），不是燒錄用的 .bin 檔。ELF 檔案位於 build/build_out/ 目錄。

建構分析

使用 ./build_freertos.sh size <project>（IPRO SDK V2.1.0 內建）可以檢視韌體的記憶體使用情況，幫助您了解韌體佔用了多少 Flash 與 RAM。

使用方式

記憶體分析 
# 顯示 ELF 大小與各 section 用量（需先完成 build）
./build_freertos.sh size platform/ipro7_demo

輸出包含整體大小摘要與各 section 的細項分佈：

  • text - 程式碼區段（存放於 Flash）
  • data - 已初始化資料（佔用 Flash + RAM）
  • bss - 未初始化資料（僅佔用 RAM）
  • 各 section（如 .text、.data、.bss 等）的大小與位址

IPRO7 記憶體配置

區域 大小 起始位址
Flash 依板型而定（例：IPRO7AI Reef EVK 為 2 MB） 0x13000000
PSRAM 8 MB 0x1e000000
OCRAM 256 KB 0x11010000
HBNRAM 4 KB 0x20090000

OTA 封裝（create_ota.py）

tools/create_ota.py 將合併韌體映像封裝為 boot2 OTA 格式。輸入必須是含 boot header 的合併映像，例如 IntelProCube 命令列工具產生的 chips/ipro7/img_create_iot/whole_img.bin，不是 SDK 建構輸出的 .bin；輸入格式不符時腳本會停止。

建立 OTA 套件 
# 預設以 XZ 壓縮，輸出 whole_img.xz.ota
python3 tools/create_ota.py <IntelProCube>/chips/ipro7/img_create_iot/whole_img.bin

# 不壓縮並指定輸出檔
python3 tools/create_ota.py whole_img.bin --raw -o firmware.ota

--fw-ver 可設定寫入 OTA 標頭的韌體版本字串。

macOS 開發注意事項

在 macOS 上進行開發時，有一些平台特定的注意事項需要留意。

序列埠裝置

⚠️ macOS 上務必使用 /dev/cu.* 而非 /dev/tty.*。tty.* 裝置會等待 DCD（Data Carrier Detect）訊號，導致程式無限阻塞。
作業系統 序列埠裝置路徑
macOS /dev/cu.usbserial-XXXX（依實際裝置而定）
Linux /dev/ttyUSB0

綁定 CMake

V2.1.0 的 tools/cmake/ 隨附 Linux x86-64 CMake，無法在 macOS 原生執行。請安裝 macOS CMake 3.19+（例如 brew install cmake）並加入 PATH；POSIX 主機的 project.build 優先選用系統 CMake。

常見問題與解決方案

問題 原因 解決方案
序列埠程式阻塞不動 使用了 /dev/tty.* 改用 /dev/cu.*
cat 序列埠輸出不完整 macOS 緩衝問題 使用 tools/serial_monitor.py、外部序列埠終端或 Extension Monitor
"Resource busy" 錯誤 stty -f 佔用序列埠 關閉佔用序列埠的程式，使用 Python 方案
CMake 無法執行 cmake (PATH) 為 Linux x86-64 ELF 使用 brew install cmake

序列埠開啟建議旗標

開發流程

./build_freertos.sh -l
./build_freertos.sh clean build ipro_ble_remote
./build_freertos.sh size ipro_ble_remote

建置完成後，以另行取得的 IntelProCube 命令列工具燒錄（或執行 ./build_freertos.sh flash），再用 tools/serial_monitor.py 或序列埠終端確認輸出。Zephyr 應用請改用 west 與 tools/zephyr/。VS Code 可在確認實際 SDK 與工具路徑後，依序使用 IPRO: Build、IPRO: Flash 與 IPRO: Serial Monitor。
