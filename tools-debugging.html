工具與除錯

⚠ Release SDK 注意事項：以下工具未包含在 Release SDK v1.0.1 中：燒錄工具（tools/ipro_iot_tool_lite/）、串口監控（tools/serial_monitor.py）、板級測試腳本（tools/board_test.sh）、當機解析工具（tools/parse_backtrace.py）與 OpenOCD 配置檔（tools/openocd/）。如有需要請聯絡原廠取得。Release SDK 內建的統一開發入口為 SDK 根目錄的 ./build_freertos.sh。

IPRO SDK 提供了完整的開發工具鏈，涵蓋從建構、燒錄、監控到除錯的完整開發週期。

概述

典型的嵌入式開發流程如下：

開發流程 
編輯程式碼 → 建構 → 燒錄 → 監控 → 除錯 → 重複
  Edit    → Build → Flash → Monitor → Debug → Repeat

SDK 提供的開發工具如下：

工具 路徑 用途 Release SDK v1.0.1
統一建構 CLI ./build_freertos.sh 建構、清除、燒錄、監控、大小分析與測試的統一入口 內含
綁定 CMake tools/cmake/ 建構系統使用的 CMake（Linux x86-64） 內含
Kconfig 解析腳本 tools/script/parse_kconfig_dynamic.py 建構系統解析 .config / Kconfig 設定 內含
燒錄工具 tools/ipro_iot_tool_lite/ 將韌體燒錄到開發板 Flash 未內含（請聯絡原廠）
串口監控 tools/serial_monitor.py 串口通訊與日誌擷取 未內含（請聯絡原廠）
板級測試 tools/board_test.sh 自動化建構、燒錄與測試 未內含（請聯絡原廠）
當機分析 tools/parse_backtrace.py 將當機位址轉為原始碼位置 未內含（請聯絡原廠）
OpenOCD 配置 tools/openocd/ JTAG 除錯介面配置 未內含（請聯絡原廠）

統一建構 CLI（build_freertos.sh）

./build_freertos.sh 位於 SDK 根目錄，是 Release SDK 內建的統一開發入口。它可以將多個 action 串接成一條指令，依序執行。

指令格式 
./build_freertos.sh [actions...] [options] <project>

Actions

Action 說明
build 建構專案（未指定 action 時的預設值）
clean 清除建構目錄
flash 燒錄韌體到開發板
monitor 開啟串口監控
size 顯示 ELF 大小與各記憶體區域用量
test 建構 + 燒錄 + 監控，並等待自動測試結果 pattern

選項

選項 說明 預設值
-p, --port PORT 串口裝置路徑（flash / monitor / test 使用） 請依實際裝置指定（如 /dev/cu.usbserial-XXXX）
-t, --timeout SEC monitor / test 的逾時秒數 30
-w, --wait-for PAT monitor 等待的正規表達式 pattern -
-d, --defconfig FILE 使用替代 defconfig（建構輸出於 build_<name>/） -
-j, --jobs N 平行建構任務數 -
-v, --verbose 顯示完整建構輸出 -
-l, --list 列出所有可用專案 -
-h, --help 顯示說明 -

常用範例

統一 CLI 範例 
# 列出所有可用專案
./build_freertos.sh -l

# 建構（預設 action）
./build_freertos.sh platform/ipro7_demo

# 清除後重新建構
./build_freertos.sh clean build platform/ipro7_demo

# 建構 → 燒錄 → 監控（完整開發循環）
./build_freertos.sh build flash monitor bluetooth/ble/ipro_ble_remote

# 顯示 ELF 大小與各記憶體區域用量
./build_freertos.sh size platform/ipro7_demo
⚠️ flash、monitor 與 test action 會呼叫 tools/ipro_iot_tool_lite/ 與 tools/serial_monitor.py。這兩個工具未包含於 Release SDK v1.0.1，請聯絡原廠取得，放置於上述路徑後即可直接使用。

燒錄工具

⚠️ ipro_iot_tool_lite 未包含於 Release SDK v1.0.1，請聯絡原廠取得。取得後放置於 tools/ipro_iot_tool_lite/，./build_freertos.sh flash <project> 即會自動呼叫。

IPRO SDK 使用 ipro_iot_tool_lite 將編譯好的韌體燒錄到開發板的 Flash 記憶體中。

基本用法

燒錄韌體 
# 串口路徑請依實際接上的裝置調整
tools/ipro_iot_tool_lite/ipro_iot_tool_lite \
    --chipname ipro7 \
    --port /dev/cu.usbserial-XXXX \
    --firmware apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.bin \
    --baudrate 921600 \
    --flash-pin 0x02

參數說明

參數 說明 範例值
--chipname 目標晶片型號 ipro7
--port 串口裝置路徑 /dev/cu.usbserial-XXXX（macOS，依實際裝置而定）
/dev/ttyUSB0（Linux）
--firmware 韌體二進位檔路徑 apps/.../build/build_out/*.bin
--baudrate 燒錄傳輸速率 921600
--flash-pin Flash 控制腳位 0x02

進入下載模式

燒錄前需要讓開發板進入下載模式。可以透過串口發送 reboot_dl 指令：

進入下載模式 
# 透過串口監控工具發送指令
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --send reboot_dl --timeout 1
⚠️ macOS 上必須使用 /dev/cu.* 裝置路徑，不要使用 /dev/tty.*，否則會因為等待 DCD 訊號而無限阻塞。

串口監控

⚠️ serial_monitor.py 未包含於 Release SDK v1.0.1，請聯絡原廠取得。取得後放置於 tools/serial_monitor.py，./build_freertos.sh monitor <project> 即會自動呼叫。

serial_monitor.py 是一個基於 Python3 termios 的串口監控工具，不需要安裝 pyserial 等額外依賴。

基本監控

基本串口監控 
# 預設 115200 baud；串口路徑依實際裝置而定
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX

發送指令並等待回應

發送指令並等待特定輸出 
# 發送 reboot 並等待測試結果
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX \
    --send reboot \
    --timeout 30 \
    --wait-for "ALL TESTS PASSED|SOME TESTS FAILED"

參數說明

參數 說明
PORT 串口裝置路徑（位置參數）
--baud RATE 鮑率（預設 115200，macOS 上支援至 921600）
--send CMD 連線後發送的指令
--timeout SEC 逾時秒數（預設 30）
--wait-for PATTERN 等待匹配的正規表達式（支援 | 分隔多個模式）
--log FILE 將輸出儲存至檔案

板上 Shell 指令

指令 說明
reboot 正常重啟開發板
reboot_dl 重啟並進入下載模式（用於燒錄）

自動化測試

⚠️ board_test.sh 與 ipro_unit_test 測試專案皆未包含於 Release SDK v1.0.1，如需完整板級測試環境請聯絡原廠取得。Release SDK 內建的等效指令為 ./build_freertos.sh test <project>。

board_test.sh 整合了建構、燒錄與測試的完整流程，適用於自動化驗證與本地開發。

完整測試流程

完整建構、燒錄與測試 
# 完整流程：建構 → 燒錄 → 串口擷取 → 結果解析
tools/board_test.sh --project apps/test/ipro_unit_test

選項說明

選項 說明 預設值
--project PATH 專案目錄路徑 apps/test/ipro_unit_test
--port PORT 串口裝置路徑 請依實際裝置指定（如 /dev/cu.usbserial-XXXX）
--skip-build 跳過建構步驟 -
--skip-flash 跳過燒錄步驟 -
--timeout SEC 串口監控逾時秒數 30
--report DIR 產生測試報告至指定目錄 不產生報告

退出碼

退出碼 意義
0 所有測試通過（ALL TESTS PASSED）
1 部分測試失敗（SOME TESTS FAILED）
2 逾時 - 未偵測到測試結果

Release SDK 內建等效指令

build_freertos.sh test 
# 建構 + 燒錄 + 監控，並等待「ALL TESTS PASSED|SOME TESTS FAILED」輸出
./build_freertos.sh test <project>

快速重測（不重新建構與燒錄）

快速重測 
# 僅重啟開發板並擷取測試結果
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX \
    --send reboot \
    --timeout 30 \
    --wait-for "ALL TESTS PASSED|SOME TESTS FAILED"
💡 設定 CONFIG_TEST_AUTO_RUN=y（在 .config 中）可以讓測試在開機時自動執行，無需手動觸發。

GDB 除錯

⚠️ OpenOCD 配置檔（tools/openocd/）未包含於 Release SDK v1.0.1，請聯絡原廠取得。

IPRO SDK 支援透過 OpenOCD + GDB 進行 JTAG 除錯。IPRO7 的 JTAG 腳位為 GPIO0（TMS）、GPIO1（TDI）、GPIO2（TCK）、GPIO9（TDO）。

啟動 OpenOCD

啟動 OpenOCD 伺服器 
# 使用 SDK 提供的 OpenOCD 配置檔
# （通用 RISC-V JTAG 設定，IPRO6 / IPRO7 皆適用）
openocd -f tools/openocd/openocd_ipro6.cfg

# 啟動成功後會顯示：
# >>> Ready for GDB on port 12021

連接 GDB

啟動 GDB 並連接 
# 使用 SDK 工具鏈中的 GDB
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-gdb \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf

# 在 GDB 中連接 OpenOCD（連接埠由配置檔中的 gdb_port 指定，預設 12021）
(gdb) target remote :12021
(gdb) monitor reset halt
⚠️ 配置檔未定義 flash bank，無法在 GDB 中以 load 燒寫 XIP Flash（0x13000000）。韌體燒錄請使用燒錄工具；GDB 用於中斷點、單步執行與記憶體檢視。

常用 GDB 指令

指令 說明
b main 在 main 函式設定中斷點
b file.c:42 在指定檔案行號設定中斷點
c 繼續執行
s / n 單步進入 / 單步跳過
p variable 列印變數值
x/16xw 0x11010000 檢視記憶體內容（16 個 word）
bt 顯示呼叫堆疊
info reg 顯示暫存器狀態

當機分析

⚠️ parse_backtrace.py 未包含於 Release SDK v1.0.1，請聯絡原廠取得。即使沒有此工具，也可以使用工具鏈內建的 addr2line 手動解析（見下方）。

當韌體發生異常（exception）時，異常處理程式會輸出異常 PC、SP（含所屬堆疊範圍）、saved s0(fp) / ra 與堆疊內容傾印。parse_backtrace.py 可以將這些位址轉換為對應的原始碼檔案與行號。

使用方式

從檔案解析 
# 從檔案讀取當機日誌
python3 tools/parse_backtrace.py \
    /opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf \
    backtrace.txt
從管線輸入 
# 從剪貼簿或管線輸入
cat backtrace.txt | python3 tools/parse_backtrace.py \
    /opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf

參數說明

參數 說明
toolchain_prefix 工具鏈前綴路徑（含尾部 -）
elf_file 對應的 ELF 檔案（包含除錯符號）
backtrace_file 當機日誌檔案（選擇性，可從 stdin 讀取）

手動解析（addr2line）

異常輸出中落在程式碼區段（例如 Flash 0x13000000 起）的位址，可以直接用工具鏈內建的 addr2line 轉為函式名稱與原始碼位置：

addr2line 手動解析 
# 將單一位址轉為函式名稱與原始碼位置
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-addr2line \
    -e apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf \
    -f -C 0x1301c148
💡 解析需要帶有除錯符號的 ELF 檔案（.elf），不是燒錄用的 .bin 檔。ELF 檔案位於 build/build_out/ 目錄。

建構分析

使用 ./build_freertos.sh size <project>（Release SDK v1.0.1 內建）可以檢視韌體的記憶體使用情況，幫助您了解韌體佔用了多少 Flash 與 RAM。

使用方式

記憶體分析 
# 顯示 ELF 大小與各 section 用量（需先完成 build）
./build_freertos.sh size platform/ipro7_demo

輸出包含整體大小摘要與各 section 的細項分佈：

  • text - 程式碼區段（存放於 Flash）
  • data - 已初始化資料（佔用 Flash + RAM）
  • bss - 未初始化資料（僅佔用 RAM）
  • 各 section（如 .text、.data、.bss 等）的大小與位址

IPRO7 記憶體配置

區域 大小 起始位址
Flash 1 MB 0x13000000
PSRAM 8 MB 0x1e000000
OCRAM 256 KB 0x11010000
HBNRAM 4 KB 0x20090000

macOS 開發注意事項

在 macOS 上進行開發時，有一些平台特定的注意事項需要留意。

串口裝置

⚠️ macOS 上務必使用 /dev/cu.* 而非 /dev/tty.*。tty.* 裝置會等待 DCD（Data Carrier Detect）訊號，導致程式無限阻塞。
作業系統 串口裝置路徑
macOS /dev/cu.usbserial-XXXX（依實際裝置而定）
Linux /dev/ttyUSB0

綁定 CMake

tools/cmake/ 內綁定的 CMake 為 Linux x86-64 ELF 二進位檔，無法在 macOS 上執行。macOS 開發請改用 brew install cmake 安裝系統 CMake。

常見問題與解決方案

問題 原因 解決方案
串口程式阻塞不動 使用了 /dev/tty.* 改用 /dev/cu.*
cat 串口輸出不完整 macOS 緩衝問題 使用 serial_monitor.py
"Resource busy" 錯誤 stty -f 佔用串口 關閉佔用程序，使用 Python 方案
綁定 CMake 無法執行 tools/cmake/ 為 Linux x86-64 ELF 使用 brew install cmake

串口開啟建議旗標

Python 串口開啟範例 
import os

# 正確的串口開啟方式（macOS，路徑依實際裝置而定）
fd = os.open("/dev/cu.usbserial-XXXX", os.O_RDWR | os.O_NOCTTY | os.O_NONBLOCK)

開發者工作流程

以下是日常開發中常用的指令與流程。

完整建構與燒錄（統一 CLI）

標準開發流程 
# 建構（預設 action）
./build_freertos.sh platform/ipro7_demo

# 建構 → 燒錄 → 監控 一條指令完成
./build_freertos.sh build flash monitor platform/ipro7_demo

手動逐步操作

逐步建構、燒錄與監控 
# 1. 建構專案
make -C apps/platform/ipro7_demo

# 2. 燒錄到開發板（燒錄與監控工具需向原廠取得）
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --send reboot_dl --timeout 1
tools/ipro_iot_tool_lite/ipro_iot_tool_lite \
    --chipname ipro7 \
    --port /dev/cu.usbserial-XXXX \
    --firmware apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.bin \
    --baudrate 921600 \
    --flash-pin 0x02

# 3. 監控輸出
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX

快速重測（不重新建構）

僅重啟開發板 
# 重啟並等待結果
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX \
    --send reboot \
    --timeout 30 \
    --wait-for "ALL TESTS PASSED|SOME TESTS FAILED"

乾淨建構

清除後重新建構 
# 使用統一 CLI
./build_freertos.sh clean build platform/ipro7_demo

# 或使用 make
make -C apps/platform/ipro7_demo clean
make -C apps/platform/ipro7_demo
