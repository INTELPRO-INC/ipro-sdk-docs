工具與除錯

V2.0.1 隨附建置 CLI、Kconfig 輔助腳本、Linux x86-64 CMake 及 Android 示範原始碼；燒錄工具、串口監看腳本、板測腳本、當機解析工具與 OpenOCD 配置需另行取得。

IPRO SDK 提供了完整的開發工具鏈，涵蓋從建構、燒錄、監控到除錯的完整開發週期。

Online Installer 3.4.0 依元件清單下載；固定版 3.3.0 安裝包內含 SDK 1.2.1。截至 2026-09-10，元件清單亦仍選用 SDK 1.2.1。V2.0.1 請由正式 Release 下載，並明確切換至解壓後的新目錄。安裝與版本選擇

概述

典型的嵌入式開發流程如下：

開發流程 
編輯程式碼 → 建構 → 燒錄 → 監控 → 除錯 → 重複
  Edit    → Build → Flash → Monitor → Debug → Repeat

SDK 提供的開發工具如下：

統一建構 CLI（build_freertos.sh）

./build_freertos.sh 位於 SDK 根目錄，是 Release SDK 內建的統一開發入口。它可以將多個 action 串接成一條指令，依序執行。

指令格式 
./build_freertos.sh [actions...] [options] <project>

Actions

Action 說明
build 建構專案（未指定 action 時的預設值）
clean 清除建構目錄
flash 燒錄韌體到開發板
monitor 開啟串口監控
size 顯示 ELF 大小與各記憶體區域用量
test 建構 + 燒錄 + 監控，並等待自動測試結果 pattern

選項

選項 說明 預設值
-p, --port PORT 串口裝置路徑（flash / monitor / test 使用） 請依實際裝置指定（如 /dev/cu.usbserial-XXXX）
-t, --timeout SEC monitor / test 的逾時秒數 30
-w, --wait-for PAT monitor 等待的正規表達式 pattern -
-d, --defconfig FILE 使用替代 defconfig（建構輸出於 build_<name>/） -
-j, --jobs N 平行建構任務數 -
-v, --verbose 顯示完整建構輸出 -
-l, --list 列出所有可用專案 -
-h, --help 顯示說明 -

常用範例

統一 CLI 範例 
# 列出所有可用專案
./build_freertos.sh -l

# 建構（預設 action）
./build_freertos.sh platform/ipro7_demo

# 清除後重新建構
./build_freertos.sh clean build platform/ipro7_demo

# 建構 → 燒錄 → 監控（完整開發循環）
./build_freertos.sh build flash monitor bluetooth/ble/ipro_ble_remote

# 顯示 ELF 大小與各記憶體區域用量
./build_freertos.sh size platform/ipro7_demo
flash、monitor 與 test 動作需額外安裝工具，V2.0.1 未附脚本所引用的串口監看工具。

燒錄工具

⚠️ ipro_iot_tool_lite 未包含於 Release SDK v2.0.1，請聯絡原廠取得。取得後放置於 tools/ipro_iot_tool_lite/，./build_freertos.sh flash <project> 即會自動呼叫。

IPRO SDK 使用 ipro_iot_tool_lite 將編譯好的韌體燒錄到開發板的 Flash 記憶體中。

基本用法

燒錄韌體 
# 串口路徑請依實際接上的裝置調整
tools/ipro_iot_tool_lite/ipro_iot_tool_lite \
    --chipname ipro7 \
    --port /dev/cu.usbserial-XXXX \
    --firmware apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.bin \
    --baudrate 921600 \
    --flash-pin 0x02

參數說明

參數 說明 範例值
--chipname 目標晶片型號 ipro7
--port 串口裝置路徑 /dev/cu.usbserial-XXXX（macOS，依實際裝置而定）
/dev/ttyUSB0（Linux）
--firmware 韌體二進位檔路徑 apps/.../build/build_out/*.bin
--baudrate 燒錄傳輸速率 921600
--flash-pin Flash 控制腳位 0x02

進入下載模式

燒錄前需要讓開發板進入下載模式。可以透過串口發送 reboot_dl 指令：

進入下載模式 
# 另行安裝；埠名與鮑率請依韌體設定調整
python3 -m pip install pyserial
python3 -m serial.tools.miniterm /dev/cu.usbserial-XXXX 115200
⚠️ macOS 上必須使用 /dev/cu.* 裝置路徑，不要使用 /dev/tty.*，否則會因為等待 DCD 訊號而無限阻塞。

串口監控

V2.0.1 未隨附 tools/serial_monitor.py。建置腳本仍引用該路徑，因此 monitor／test 動作需額外取得腳本。可使用 Extension 的 IPRO: Serial Monitor 或串口終端工具。

鮑率以所選應用及板型配置為準；macOS 使用 /dev/cu.*。燒錄前停止監看以釋放串口。

板上測試

SDK 已包含 apps/test/ipro_unit_test/，測試 HAL 與共用元件。建置後以另行取得的燒錄工具寫入對應板子，再由串口確認 ALL TESTS PASSED 或 SOME TESTS FAILED。

make -C apps/test/ipro_unit_test

tools/board_test.sh 與 tools/serial_monitor.py 未隨附。建置 CLI 的 test 動作仍依賴外部燒錄／監看工具，單靠原始碼包無法完成自動上板測試。

依 PREBUILT-ARCHIVES-STRIPPED.txt，交付包中的 AI、ISP、RF、LC3 與低功耗框架函式庫已移除除錯資訊；可正常連結，但無法於庫內進行原始碼層級單步除錯。

GDB 除錯

⚠️ OpenOCD 配置檔（tools/openocd/）未包含於 Release SDK v2.0.1，請聯絡原廠取得。

IPRO SDK 支援透過 OpenOCD + GDB 進行 JTAG 除錯。IPRO7 的 JTAG 腳位為 GPIO0（TMS）、GPIO1（TDI）、GPIO2（TCK）、GPIO9（TDO）。

啟動 OpenOCD

啟動 OpenOCD 伺服器 
# 使用 SDK 提供的 OpenOCD 配置檔
# （通用 RISC-V JTAG 設定，IPRO6 / IPRO7 皆適用）
openocd -f tools/openocd/openocd_ipro6.cfg

# 啟動成功後會顯示：
# >>> Ready for GDB on port 12021

連接 GDB

啟動 GDB 並連接 
# 使用 SDK 工具鏈中的 GDB
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-gdb \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf

# 在 GDB 中連接 OpenOCD（連接埠由配置檔中的 gdb_port 指定，預設 12021）
(gdb) target remote :12021
(gdb) monitor reset halt
⚠️ 配置檔未定義 flash bank，無法在 GDB 中以 load 燒寫 XIP Flash（0x13000000）。韌體燒錄請使用燒錄工具；GDB 用於中斷點、單步執行與記憶體檢視。

常用 GDB 指令

指令 說明
b main 在 main 函式設定中斷點
b file.c:42 在指定檔案行號設定中斷點
c 繼續執行
s / n 單步進入 / 單步跳過
p variable 列印變數值
x/16xw 0x11010000 檢視記憶體內容（16 個 word）
bt 顯示呼叫堆疊
info reg 顯示暫存器狀態

當機分析

⚠️ parse_backtrace.py 未包含於 Release SDK v2.0.1，請聯絡原廠取得。即使沒有此工具，也可以使用工具鏈內建的 addr2line 手動解析（見下方）。

當韌體發生異常（exception）時，異常處理程式會輸出異常 PC、SP（含所屬堆疊範圍）、saved s0(fp) / ra 與堆疊內容傾印。parse_backtrace.py 可以將這些位址轉換為對應的原始碼檔案與行號。

使用方式

從檔案解析 
# 從檔案讀取當機日誌
python3 tools/parse_backtrace.py \
    /opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf \
    backtrace.txt
從管線輸入 
# 從剪貼簿或管線輸入
cat backtrace.txt | python3 tools/parse_backtrace.py \
    /opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf

參數說明

參數 說明
toolchain_prefix 工具鏈前綴路徑（含尾部 -）
elf_file 對應的 ELF 檔案（包含除錯符號）
backtrace_file 當機日誌檔案（選擇性，可從 stdin 讀取）

手動解析（addr2line）

異常輸出中落在程式碼區段（例如 Flash 0x13000000 起）的位址，可以直接用工具鏈內建的 addr2line 轉為函式名稱與原始碼位置：

addr2line 手動解析 
# 將單一位址轉為函式名稱與原始碼位置
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-addr2line \
    -e apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf \
    -f -C 0x1301c148
💡 解析需要帶有除錯符號的 ELF 檔案（.elf），不是燒錄用的 .bin 檔。ELF 檔案位於 build/build_out/ 目錄。

建構分析

使用 ./build_freertos.sh size <project>（Release SDK v2.0.1 內建）可以檢視韌體的記憶體使用情況，幫助您了解韌體佔用了多少 Flash 與 RAM。

使用方式

記憶體分析 
# 顯示 ELF 大小與各 section 用量（需先完成 build）
./build_freertos.sh size platform/ipro7_demo

輸出包含整體大小摘要與各 section 的細項分佈：

  • text - 程式碼區段（存放於 Flash）
  • data - 已初始化資料（佔用 Flash + RAM）
  • bss - 未初始化資料（僅佔用 RAM）
  • 各 section（如 .text、.data、.bss 等）的大小與位址

IPRO7 記憶體配置

區域 大小 起始位址
Flash 1 MB 0x13000000
PSRAM 8 MB 0x1e000000
OCRAM 256 KB 0x11010000
HBNRAM 4 KB 0x20090000

macOS 開發注意事項

在 macOS 上進行開發時，有一些平台特定的注意事項需要留意。

串口裝置

⚠️ macOS 上務必使用 /dev/cu.* 而非 /dev/tty.*。tty.* 裝置會等待 DCD（Data Carrier Detect）訊號，導致程式無限阻塞。
作業系統 串口裝置路徑
macOS /dev/cu.usbserial-XXXX（依實際裝置而定）
Linux /dev/ttyUSB0

綁定 CMake

V2.0.1 的 tools/cmake/ 隨附 Linux x86-64 CMake，無法在 macOS 原生執行。請安裝 macOS CMake 3.19+（例如 brew install cmake）並加入 PATH；POSIX 主機的 project.build 優先選用系統 CMake。

常見問題與解決方案

問題 原因 解決方案
串口程式阻塞不動 使用了 /dev/tty.* 改用 /dev/cu.*
cat 串口輸出不完整 macOS 緩衝問題 使用外部串口終端或 Extension Monitor
"Resource busy" 錯誤 stty -f 佔用串口 關閉佔用程序，使用 Python 方案
CMake 無法執行 cmake (PATH) 為 Linux x86-64 ELF 使用 brew install cmake

串口開啟建議旗標

Python 串口開啟範例 
import os

# 正確的串口開啟方式（macOS，路徑依實際裝置而定）
fd = os.open("/dev/cu.usbserial-XXXX", os.O_RDWR | os.O_NOCTTY | os.O_NONBLOCK)

./build_freertos.sh -l
./build_freertos.sh clean build ipro_ble_remote
./build_freertos.sh size ipro_ble_remote
