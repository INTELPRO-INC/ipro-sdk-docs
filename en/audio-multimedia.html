Audio & Multimedia

IPRO SDK provides comprehensive audio and multimedia capabilities, including LE Audio Bluetooth audio, USB audio devices, camera image processing, and video streaming. This page covers the architecture, APIs, and reference applications for each subsystem.

Overview

The IPRO7 SoC integrates multiple audio and multimedia hardware accelerators. Combined with the SDK software stack, the following features are supported:

LE Audio

LE Audio (BLE 5.2+)

  • LC3 codec (liblc3)
  • Unicast (CIS) & Broadcast (BIS)
  • BAP / CAP / VCP / MCP profiles
  • Auracast broadcast audio
USB

USB Audio (UAC)

  • USB Audio Class device
  • USB-to-BLE audio bridge
  • CherryUSB integration
  • Low-latency audio transfer
CAM

Camera & Video

  • ISP image signal processing
  • MJPEG hardware encoding
  • UVC USB camera device

LE Audio Pipeline

LE Audio is the next-generation Bluetooth audio standard introduced in BLE 5.2. It uses ISO Channels (Isochronous Channels) to transmit audio data, replacing the traditional Classic Audio A2DP/HFP approach.

Transmit Pipeline

1
Audio Input
AUADC / I2S PCM samples
2
LC3 Encode
Audio encode 16-320 kbps
3
ISO Channel
CIS or BIS isochronous
4
BLE PHY
2M PHY wireless TX

Receive Pipeline

1
BLE PHY
2M PHY wireless RX
2
ISO Channel
CIS or BIS reassembly
3
LC3 Decode
Audio decode PCM recovery
4
Audio Output
DAC / I2S speaker out

Key Specifications

FeatureDescription
CodecLC3 (provided by the prebuilt liblc3 library)
Bitrate16 - 320 kbps (LE Audio commonly 16-124 kbps per channel)
Sample Rate8 / 16 / 24 / 32 / 48 kHz
ChannelsMono, Stereo
Latency< 20ms end-to-end
TransportCIS (Unicast), BIS (Broadcast)

Unicast Audio (CIS)

Connected Isochronous Stream (CIS) provides point-to-point bidirectional audio transport, suitable for headsets, hearing aids, and other scenarios requiring a stable connection.

CIS (LC3 Audio Stream)
Unicast Client (Phone)
BAP Initiator VCP Controller MCS Server CAP Initiator

BAP Unicast Flow

Basic Audio Profile (BAP) manages audio stream establishment and control. The unicast connection flow is as follows:

1
Discover PACS
Query audio capabilities
2
PAC Records
Return codec/sample rate
3
Configure ASE
Configure stream endpoint
4
Establish CIS
Create isochronous channel
5
Enable Stream
Start audio transmission

Headset-Side Example Code

BAP Server Init (apps/bluetooth/le_audio/ipro_le_audio_headset/src/bap_server.c) 
/* Register BAP Unicast Server callbacks */
static const struct bt_bap_unicast_server_cb unicast_server_cb = {
    .config = bap_server_config,
    .reconfig = bap_server_reconfig,
    .qos = bap_server_qos,
    .enable = bap_server_enable,
    .start = bap_server_start,
    .metadata = bap_server_metadata,
    .disable = bap_server_disable,
    .stop = bap_server_stop,
    .release = bap_server_release,
};

int bap_server_init(void)
{
    /* Initialize PACS service (must precede ASCS) */
    bt_pacs_init();

    /* Register LC3 sink audio capability */
    bt_pacs_cap_register(BT_AUDIO_DIR_SINK, &lc3_sink_cap);

    /* Set audio location and audio contexts */
    bt_pacs_set_location(BT_AUDIO_DIR_SINK, BT_AUDIO_LOCATION_FRONT_LEFT);
    bt_pacs_set_supported_contexts(BT_AUDIO_DIR_SINK,
                                   BT_AUDIO_CONTEXT_TYPE_MEDIA |
                                   BT_AUDIO_CONTEXT_TYPE_CONVERSATIONAL |
                                   BT_AUDIO_CONTEXT_TYPE_UNSPECIFIED);

    /* Register Unicast Server callbacks with ASCS */
    bt_bap_unicast_server_register_cb(&unicast_server_cb);

    return 0;
}

Broadcast Audio (BIS)

Broadcast Isochronous Stream (BIS) provides one-to-many unidirectional audio transport. Receivers do not need to establish a connection to listen. This is the foundation of Auracast technology.

BIS Architecture

Broadcast Source
BAP Source Audio Encoder BIG Management
Broadcast Sink 1
Broadcast Sink 2
Broadcast Sink N
BIS (Connectionless) -- Use cases: walkie-talkie, PA system, hearing aids, tour guides

Broadcast Source Example

BIS Source (apps/bluetooth/le_audio/ipro_le_audio_bis_source/src/app_broadcast_source.c) 
/* Create Broadcast Source (BAP layer)
 * Full flow: bt_le_ext_adv_create → bt_le_per_adv_set_param
 *           → bt_bap_broadcast_source_create → bt_bap_broadcast_source_start */
static int create_broadcast_source(void)
{
    struct bt_bap_broadcast_source_create_param create_param = {
        .params_count = 1,
        .params = &subgroup_param,
        .qos = &qos,
        .packing = BT_ISO_PACKING_SEQUENTIAL,
        .encryption = false,
    };

    int err = bt_bap_broadcast_source_create(&create_param, &source);
    if (err) {
        IPRO_LOGE(LOG_TAG, "Broadcast source create failed: %d", err);
        return err;
    }

    /* Start broadcasting (bound to the extended advertising set) */
    err = bt_bap_broadcast_source_start(source, adv);
    return err;
}

Broadcast Sink Example

BIS Sink (apps/bluetooth/le_audio/ipro_le_audio_bis_sink/src/app_broadcast.c) 
/* The Broadcast Sink on the IPRO blestack does not use the
 * bt_bap_broadcast_sink_* APIs. The receive flow is:
 * Scan → PA sync (raw HCI) → BIG sync → ISO receive
 *
 *   1. bt_le_scan_start() scans for the Broadcast Audio
 *      Announcement (UUID 0x1852)
 *   2. PA sync via the HCI LE_Periodic_Advertising_Create_Sync command
 *      (bt_hci_cmd_create / bt_hci_cmd_send_sync,
 *       opcode BT_HCI_OP_LE_PER_ADV_CREATE_SYNC)
 *   3. After the BIGInfo report arrives, call bt_iso_big_sync()
 *      to sync to the BIG
 *   4. Receive ISO audio data through bt_iso_chan_ops and decode
 */

/* ISO channel callbacks: receive BIS audio data */
static struct bt_iso_chan_ops bis_chan_ops = {
    .connected    = bis_connected_cb,
    .disconnected = bis_disconnected_cb,
    .recv         = bis_recv_cb,      /* LC3 audio in → decode → output */
};

/* Scan for the broadcast source */
static void scan_for_broadcast(void)
{
    bt_le_scan_start(BT_LE_SCAN_PASSIVE, scan_recv_cb);
}

LC3 Codec

LC3 (Low Complexity Communication Codec) is the mandatory codec for LE Audio. It delivers better audio quality than SBC at lower bitrates. The SDK ships the LC3 codec as the prebuilt library components/3rdparty/liblc3; blestack/src/audio/codec.c handles LE Audio codec capability and configuration parsing.

  • Sample Rate: 8 / 16 / 24 / 32 / 48 kHz
  • Bitrate: 16 - 320 kbps (common LE Audio presets are 16 - 124 kbps per channel)
  • Frame Duration: 7.5ms or 10ms per the LE Audio standard; the bundled liblc3 additionally supports 2.5ms and 5ms
  • Channels: Mono, Stereo
  • Advantage: Matches SBC 328 kbps quality at just 160 kbps
About Opus: The SDK also includes the Opus codec (components/3rdparty/opus), used by networked voice-streaming applications (for example, speech synthesis playback in ipro_voice_assistant). It is not used for LE Audio ISO channel audio — LE Audio always uses LC3.

/* Called by CherryUSB when the USB host opens the audio stream

void usbd_audio_open(uint8_t intf)
{
    /* Start isochronous DMA; send silence until audio data is available */
}

    /* USB host closed the audio stream */

/* Initialize USB Audio device */
int app_uac_init(const app_uac_config_t *config)
{
    usbd_desc_register(uac_descriptor);
    usbd_add_interface(usbd_audio_init_intf(&s_intf0, 0x0100, s_entity_table, 1));
    usbd_add_interface(usbd_audio_init_intf(&s_intf1, 0x0100, s_entity_table, 1));
    usbd_add_endpoint(&s_audio_in_ep);
    usbd_event_register_callback(uac_event_handler);
    usbd_initialize();
    return 0;
}

Audio Hardware

The IPRO7 SoC integrates multiple audio hardware peripherals, accessible through a unified HAL layer:

HardwareFunctionHAL HeaderDescription
AUADC Audio ADC hal_auadc.h Built-in audio analog-to-digital converter for direct microphone connection
DAC Digital-to-Analog Converter hal_dac.h Audio output to speaker or headphone
I2S Inter-IC Sound hal_i2s.h Digital audio interface for connecting external audio codec chips
DMA Direct Memory Access hal_dma.h Zero CPU-overhead audio data transfer

Audio Hardware Data Flow

Audio Hardware Data Paths 
Recording Path (Input):
  Microphone → AUADC → DMA → Memory Buffer → LC3 Encoder / USB

Playback Path (Output):
  LC3 Decoder / USB → Memory Buffer → DMA → DAC → Speaker

External Codec Path:
  External Codec ↔ I2S ↔ DMA ↔ Memory Buffer

Audio Output Abstraction Layer

components/audio provides a unified audio output abstraction layer, audio_output, which drives DAC, I2S, UAC, and PCM dump backends through the same API. It is the output interface used by the LE Audio reference applications. The same component also provides audio_capture (AUADC + DMA audio capture) and mp3_decoder (MP3 decoding):

Audio Output Abstraction (components/audio/include/audio_output.h) 
#include "audio_output.h"

audio_output_cfg_t cfg = {
    .type        = AUDIO_OUTPUT_DAC,            /* DAC / UAC / I2S / DUMP */
    .mode        = AUDIO_OUTPUT_MODE_STREAMING,
    .sample_rate = 48000,
    .channels    = 2,
};

audio_output_t *out = audio_output_create(&cfg);
audio_output_start(out);
audio_output_write(out, pcm, samples);   /* interleaved int16_t PCM */
audio_output_stop(out);
audio_output_destroy(out);

Embedded AI voice-conversation gateway reference application (apps/multimedia/ipro_agora_sentino): captures speech through an AMIC microphone, encodes it with Opus, connects over Ethernet (RMII) or USB NCM, and holds two-way voice conversations with a cloud real-time audio streaming (RTC) service. It also supports LCD status display and USB CDC text output. This application integrates a third-party RTC SDK; contact the vendor for integration details.

ipro_voice_assistant

AI voice assistant reference application (apps/network/ipro_voice_assistant): captures speech with audio_capture (AMIC microphone) and VAD voice detection, connects over Ethernet (RMII) for cloud speech recognition and AI conversation, then decodes the Opus (Ogg) reply and plays it through the DAC — demonstrating the full "capture → recognize → converse → synthesize and play" audio chain.

Network connectivity: The two applications above connect via Ethernet (RMII) or USB NCM. The IPRO7 itself has no Wi-Fi; for Wi-Fi connectivity, pair it with an IPRO6 companion chip (SDIO interface).
