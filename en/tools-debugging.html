Tools & Debugging

Release SDK Notice: V1.2.1 includes build_freertos.sh, build helper scripts and tools/serial_monitor.py. Install CMake separately. The flash tool, board-test script, crash parser and OpenOCD configurations are not included.

The IPRO SDK provides an integrated toolchain covering the complete development cycle: build, flash, monitor, and debug.

Full Windows installer: Installer 3.3.0 provides SDK V1.2.1, extension 3.3.0, GCC, CMake, Ninja, Python, IntelProCube and bundled OpenOCD. The standalone SDK archive has a smaller scope; statements below about omitted tools refer to that archive. Installation and independent updates · Extension guide

Development Cycle

Unified Build CLI (build_freertos.sh)

./build_freertos.sh lives at the SDK root and is the unified development entry point bundled with the Release SDK. Multiple actions can be chained in a single command and are executed in order.

Command Format 
./build_freertos.sh [actions...] [options] <project>

Actions

Action Description
build Build the project (default when no action is given)
clean Clean the build directory
flash Flash the binary to the board
monitor Open the serial monitor
size Show ELF size and memory region usage
test Build + flash + monitor, waiting for the auto-test result pattern

Options

Option Description Default
-p, --port PORT Serial device path (used by flash / monitor / test) Set per your actual device (e.g. /dev/cu.usbserial-XXXX)
-t, --timeout SEC Timeout in seconds for monitor / test 30
-w, --wait-for PAT Regex pattern the monitor waits for -
-d, --defconfig FILE Use an alternate defconfig (build output goes to build_<name>/) -
-j, --jobs N Number of parallel build jobs -
-v, --verbose Show full build output -
-l, --list List all available projects -
-h, --help Show help -

Common Examples

Unified CLI Examples 
# List all available projects
./build_freertos.sh -l

# Build (default action)
./build_freertos.sh platform/ipro7_demo

# Clean, then rebuild
./build_freertos.sh clean build platform/ipro7_demo

# Build → flash → monitor (full development cycle)
./build_freertos.sh build flash monitor bluetooth/ble/ipro_ble_remote

# Show ELF size and memory region usage
./build_freertos.sh size platform/ipro7_demo
⚠️ The flash action still requires the separately supplied flash tool. The monitor action can use the bundled tools/serial_monitor.py.

Flash Tool

⚠️ ipro_iot_tool_lite is not included in Release SDK v1.2.1 — contact the vendor to obtain it. Once placed at tools/ipro_iot_tool_lite/, ./build_freertos.sh flash <project> will invoke it automatically.

The IPRO SDK uses ipro_iot_tool_lite to flash compiled firmware to the development board's Flash memory.

Basic Usage

Flash Firmware 
# Adjust the serial port path to match your actual device
tools/ipro_iot_tool_lite/ipro_iot_tool_lite \
    --chipname ipro7 \
    --port /dev/cu.usbserial-XXXX \
    --firmware apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.bin \
    --baudrate 921600 \
    --flash-pin 0x02

Parameters

Parameter Description Example
--chipname Target chip model ipro7
--port Serial device path /dev/cu.usbserial-XXXX (macOS, depends on your device)
/dev/ttyUSB0 (Linux)
--firmware Firmware binary path apps/.../build/build_out/*.bin
--baudrate Flash transfer baud rate 921600
--flash-pin Flash control pin 0x02

Entering Download Mode

The board must be in download mode before flashing. Send the reboot_dl command via serial:

Enter Download Mode 
# Send reboot_dl command via serial monitor
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --send reboot_dl --timeout 1
⚠️ On macOS, you must use /dev/cu.* device paths. Do not use /dev/tty.* as it will block indefinitely waiting for the DCD signal.

Serial Monitor

V1.2.1: tools/serial_monitor.py is included for POSIX systems (Linux/macOS). Its termios/fcntl imports are unavailable in native Windows Python.

serial_monitor.py is a Python3 termios-based serial monitor that requires no external dependencies such as pyserial.

Basic Monitoring

Basic Serial Monitoring 
# Default baud rate: 115200; serial port path depends on your device
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX

Send Commands and Wait for Output

Send Command and Wait for Pattern 
# Send reboot and wait for test results
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX \
    --send reboot \
    --timeout 30 \
    --wait-for "ALL TESTS PASSED|SOME TESTS FAILED"

Parameters

Parameter Description
PORT Serial device path (positional argument)
--baud RATE Baud rate (default 115200; supported: 9600, 19200, 38400, 57600, 115200, 230400)
--send CMD Command to send after connecting
--timeout SEC Timeout in seconds (default 30)
--wait-for PATTERN Regex pattern to wait for (supports | for multiple patterns)
--log FILE Save output to a log file

Board Shell Commands

Command Description
reboot Normal board reset
reboot_dl Reset and enter download mode (for flashing)

Automated Testing

⚠️ Neither board_test.sh nor the ipro_unit_test project is included in Release SDK v1.2.1 — contact the vendor for the full board-test environment. The equivalent command bundled with the Release SDK is ./build_freertos.sh test <project>.

board_test.sh integrates the full build, flash, and test workflow, suitable for automated verification and local development.

Full Test Cycle

Full Build, Flash, and Test 
# Full cycle: build → flash → serial capture → result parsing
tools/board_test.sh --project apps/test/ipro_unit_test

Options

Option Description Default
--project PATH Project directory path apps/test/ipro_unit_test
--port PORT Serial device path Set per your actual device (e.g. /dev/cu.usbserial-XXXX)
--skip-build Skip the build step -
--skip-flash Skip the flash step -
--timeout SEC Serial monitor timeout in seconds 30
--report DIR Generate test report in the specified directory Disabled

Exit Codes

Exit Code Meaning
0 All tests passed (ALL TESTS PASSED)
1 Some tests failed (SOME TESTS FAILED)
2 Timeout - no test result detected

Equivalent Command in the Release SDK

build_freertos.sh test 
# Build + flash + monitor, waiting for "ALL TESTS PASSED|SOME TESTS FAILED"
./build_freertos.sh test <project>

Quick Retest (No Rebuild or Reflash)

Quick Retest 
# Reboot the board and capture test results only
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX \
    --send reboot \
    --timeout 30 \
    --wait-for "ALL TESTS PASSED|SOME TESTS FAILED"
💡 Set CONFIG_TEST_AUTO_RUN=y in your .config file to have tests run automatically on boot without manual triggering.
See PREBUILT-ARCHIVES-STRIPPED.txt: AI, ISP, RF, LC3 and low-power framework archives in this package have no debug information. They can be linked, but source-level stepping inside them is unavailable.

GDB Debugging

⚠️ The OpenOCD configurations (tools/openocd/) are not included in Release SDK v1.2.1 — contact the vendor to obtain them.

The IPRO SDK supports JTAG debugging through OpenOCD + GDB. The IPRO7 JTAG pins are GPIO0 (TMS), GPIO1 (TDI), GPIO2 (TCK), and GPIO9 (TDO).

Start OpenOCD

Start OpenOCD Server 
# Use the SDK-provided OpenOCD configuration
# (generic RISC-V JTAG setup, valid for both IPRO6 and IPRO7)
openocd -f tools/openocd/openocd_ipro6.cfg

# On success it prints:
# >>> Ready for GDB on port 12021

Connect GDB

Launch GDB and Connect 
# Use the SDK toolchain's GDB
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-gdb \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf

# Inside GDB, connect to OpenOCD
# (the port is set by gdb_port in the config file, default 12021)
(gdb) target remote :12021
(gdb) monitor reset halt
⚠️ The configuration files define no flash bank, so load inside GDB cannot program the XIP Flash (0x13000000). Use the flash tool to program firmware; GDB is for breakpoints, single-stepping, and memory inspection.

Common GDB Commands

Command Description
b main Set breakpoint at main function
b file.c:42 Set breakpoint at a specific file and line
c Continue execution
s / n Step into / Step over
p variable Print variable value
x/16xw 0x11010000 Examine memory (16 words in hex)
bt Show backtrace / call stack
info reg Display register state

Crash Analysis

⚠️ parse_backtrace.py is not included in Release SDK v1.2.1 — contact the vendor to obtain it. Even without this tool, you can resolve addresses manually with the toolchain's built-in addr2line (see below).

When the firmware encounters an exception, the exception handler outputs the exception PC, SP (with its owning stack range), saved s0(fp) / ra, and a stack dump. parse_backtrace.py converts these addresses into source file names and line numbers.

Usage

Parse from File 
# Parse crash log from a file
python3 tools/parse_backtrace.py \
    /opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf \
    backtrace.txt
Parse from Pipe / Stdin 
# Pipe from clipboard or file
cat backtrace.txt | python3 tools/parse_backtrace.py \
    /opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- \
    apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf

Parameters

Parameter Description
toolchain_prefix Toolchain prefix path (including trailing -)
elf_file Corresponding ELF file (with debug symbols)
backtrace_file Crash log file (optional, reads from stdin if omitted)

Manual Analysis (addr2line)

Any address in the exception output that falls within a code region (e.g. Flash starting at 0x13000000) can be resolved to a function name and source location with the toolchain's built-in addr2line:

Manual addr2line Resolution 
# Resolve a single address to a function name and source location
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-addr2line \
    -e apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.elf \
    -f -C 0x1301c148
💡 Parsing requires the ELF file (.elf) with debug symbols, not the .bin file used for flashing. ELF files are located in the build/build_out/ directory.

Build Size Analysis

Use ./build_freertos.sh size <project> (bundled with Release SDK v1.2.1) to inspect firmware memory usage and understand how much Flash and RAM the firmware consumes.

Usage

Memory Size Analysis 
# Show ELF size and per-section usage (run 'build' first)
./build_freertos.sh size platform/ipro7_demo

The output includes an overall size summary and a per-section breakdown:

  • text - Code section (stored in Flash)
  • data - Initialized data (occupies both Flash and RAM)
  • bss - Uninitialized data (occupies RAM only)
  • Size and address of each section (e.g. .text, .data, .bss)

IPRO7 Memory Layout

Region Size Base Address
Flash 1 MB 0x13000000
PSRAM 8 MB 0x1e000000
OCRAM 256 KB 0x11010000
HBNRAM 4 KB 0x20090000

macOS Development Notes

There are several platform-specific considerations when developing on macOS.

Serial Ports

⚠️ On macOS, always use /dev/cu.* instead of /dev/tty.*. The tty.* devices wait for the DCD (Data Carrier Detect) signal, causing programs to block indefinitely.
Operating System Serial Device Path
macOS /dev/cu.usbserial-XXXX (depends on your device)
Linux /dev/ttyUSB0

Bundled CMake

V1.2.1 does not bundle CMake. Install CMake 3.19+ using your system package manager and ensure cmake is on PATH (macOS: brew install cmake).

Common Issues and Solutions

Issue Cause Solution
Serial program hangs Using /dev/tty.* Switch to /dev/cu.*
Incomplete cat output macOS buffering issues Use serial_monitor.py
"Resource busy" error stty -f holding the port Close the holding process; use Python approach
CMake won't run cmake (PATH) is a Linux x86-64 ELF Use brew install cmake

Recommended Serial Port Flags

Python Serial Port Example 
import os

# Correct way to open serial ports on macOS (path depends on your device)
fd = os.open("/dev/cu.usbserial-XXXX", os.O_RDWR | os.O_NOCTTY | os.O_NONBLOCK)

Developer Workflow

Below are common commands and workflows for daily development.

Full Build and Flash (Unified CLI)

Standard Development Workflow 
# Build (default action)
./build_freertos.sh platform/ipro7_demo

# Build → flash → monitor in a single command
./build_freertos.sh build flash monitor platform/ipro7_demo

Manual Step-by-Step

Step-by-Step Build, Flash, and Monitor 
# 1. Build the project
make -C apps/platform/ipro7_demo

# 2. Flash to the development board (flash and monitor tools available from the vendor)
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --send reboot_dl --timeout 1
tools/ipro_iot_tool_lite/ipro_iot_tool_lite \
    --chipname ipro7 \
    --port /dev/cu.usbserial-XXXX \
    --firmware apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.bin \
    --baudrate 921600 \
    --flash-pin 0x02

# 3. Monitor output
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX

Quick Retest (No Rebuild)

Reboot Board Only 
# Reboot and wait for results
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX \
    --send reboot \
    --timeout 30 \
    --wait-for "ALL TESTS PASSED|SOME TESTS FAILED"

Clean Build

Clean and Rebuild 
# Using the unified CLI
./build_freertos.sh clean build platform/ipro7_demo

# Or using make
make -C apps/platform/ipro7_demo clean
make -C apps/platform/ipro7_demo

Automated Test Workflow

One-Command Testing (Build + Flash + Verify) 
# Bundled with the Release SDK: build + flash + monitor, waiting for test results
./build_freertos.sh test <project>

# board_test.sh (not included in Release SDK v1.2.1)
tools/board_test.sh --project apps/test/ipro_unit_test --report test_results/

# Skip build, flash and test only
tools/board_test.sh --project apps/test/ipro_unit_test --skip-build

# Skip build and flash, test only
tools/board_test.sh --project apps/test/ipro_unit_test --skip-build --skip-flash
