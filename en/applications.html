Applications

The IPRO SDK Release provides multiple complete reference applications demonstrating best practices for various features. Each application can be built, flashed, and tested directly.

Unified Build Workflow

Besides running make in each application directory, build_freertos.sh at the SDK root provides a unified entry point that can chain build, flash, and monitor stages:

build_freertos.sh Workflow 
# List all buildable projects
./build_freertos.sh -l

# Build a single application (short name or full path)
./build_freertos.sh ipro_ble_remote build
./build_freertos.sh bluetooth/ble/ipro_ble_remote build

# Full development cycle: build + flash + serial monitor
./build_freertos.sh ipro_ble_remote build flash monitor

Build output goes to apps/<category>/<name>/build/build_out/; the binary name includes a chip suffix, e.g. ipro_ble_remote_IPRO7.bin.

ipro_ble_remote

Interactive BLE remote control application designed for mobile app development with 6 GATT services.

Features

  • 6 GATT Services: LED Control, Button, Environment, UART, PIR Image, OTA Update
  • Mobile Friendly: Complete protocol spec for Android/iOS app development; an Android demo app (ipro_remote_demo.apk) is bundled in the application directory for direct testing
  • Image Transfer: Chunked JPEG transfer over BLE, measured at 101.4 KB/s with MTU 517 (56KB image in 542ms)
  • High-speed OTA: MTU 517 auto-negotiation, 12.3 KB/s transfer speed

Service List

Service UUID Function
LED Control 0xFF10 On/Off, Brightness (0-100%), Blink Mode
Button 0xFF20 Status Notification, Press Count
Environment 0xFF30 Temperature, Humidity (Simulated)
UART 0xFF40 Bidirectional Text Communication
PIR Image 0xFF50 Motion Detection + JPEG Transfer
OTA 0xFF60 Firmware Update (800KB max, 12.3 KB/s)

Build

Build BLE Remote 
make -C apps/bluetooth/ble/ipro_ble_remote

ipro_throughput_test

High-performance BLE throughput test application using native Zephyr bt_* APIs, achieving 999 Kbps between two IPRO7 development boards.

Features

  • Native Zephyr APIs: Direct use of bt_gatt_notify/bt_gatt_write_without_response
  • Dual-Role Support: Slave (Peripheral) and Master (Central) with a custom GATT service for bidirectional transfer
  • Real-time Statistics: Throughput in Kbps updated every second
  • PHY Selection: 1M/2M/Coded
  • DLE Optimization: Data Length Extension 251 bytes, ATT MTU 247 bytes
  • Configurable Connection Interval: 7.5ms ~ 4s

Performance Results

PHY Interval Payload Throughput
1M 7.5 ms 244 B 507 Kbps
2M 7.5 ms 244 B 999 Kbps
2M 15 ms 244 B 984 Kbps
2M 7.5 ms 100 B 610 Kbps
2M 7.5 ms 20 B 187 Kbps

Quick Start

Test Workflow 
# Board 1 (Slave)
tp slave

# Board 2 (Master)
tp master

# Start test after connection (244 bytes, 10 seconds)
tp start 244 10

# Optimize speed
tp phy 2         # Use 2M PHY
tp conn 6 6      # Minimum connection interval

Build

Build Throughput Test 
make -C apps/bluetooth/ble/ipro_throughput_test

ipro_ble_img_capture

BLE image capture application combining PIR motion sensing, ISP image capture, and BLE image transfer, suited for low-power image sensing node development. The GATT service architecture is derived from ipro_ble_remote.

Features

  • PIR-Triggered Capture: PIR sensor GPIO interrupt detects motion, notifies the phone, and triggers image capture
  • Low-Power Cycle: Sleep/wake cycle operation — stays in low-power mode and wakes on motion to capture
  • ISP + JPEG: ISP camera capture with JPEG compression, configurable resolution (QVGA/VGA/720p/1080p)
  • Chunked Image Transfer: Chunk size dynamically adjusted to the negotiated MTU; measured 101.4 KB/s with MTU 517 (56KB image)
  • Image Upload Service: Phones can upload images back to the device, with PAUSE/RESUME flow control
  • OTA Update: Same OTA service as ipro_ble_remote (0xFF60)

Service List

Service UUID Function
PIR Image 0xFF50 Motion Event Notification, Image Capture Control & Chunked Transfer
Image Upload 0xFF70 Phone-to-Device Image Upload (Flow Control)
OTA 0xFF60 Firmware Update

Build

Build BLE Image Capture 
make -C apps/bluetooth/ble/ipro_ble_img_capture

ipro_le_audio_headset

LE Audio Unicast headset reference application built on GAF (Generic Audio Framework), implementing a full-featured wireless headset with bidirectional audio streaming over CIS (Connected Isochronous Stream) against Unicast Client (CAP) sources such as phones and PCs.

Features

  • BAP Unicast Server: Bidirectional audio streaming over CIS (Basic Audio Profile)
  • LC3 Codec: Low Complexity Communication Codec
  • VCP Server: Volume Control Profile — remote volume control from the source device
  • MCP: Media Control Profile — media playback control (reserved for future development)
  • CCP: Call Control Profile — call handling (reserved for future development)

ipro_agora_sentino

Embedded AI voice conversation gateway. Captures speech via a differential AMIC microphone, streams it over the network to the Agora RTC cloud for real-time bidirectional voice conversation with an AI chatbot, with LCD status display and speech-to-text (STT) output over a USB CDC virtual serial port.

Features

  • Real-Time Bidirectional Voice: AMIC capture (16 kHz / 16-bit / mono) → Agora RTC cloud ↔ AI chatbot, with Opus codec handled inside the SDK
  • Audio Output: DAC speaker playback with soft limiter, TPDF dither, and auto-mute
  • Connectivity: Ethernet (RMII) or USB NCM network sharing, lwIP + DHCP
  • LCD Status Display: ILI9341 SPI LCD showing IP, channel, connection state, AI state, volume, and statistics in real time
  • STT Text Output: USB CDC ACM virtual serial port streams recognized text to the host
  • Auto Connect: After boot, automatically initializes the network, obtains a token, joins the RTC channel, and starts the AI conversation

Hardware Connections

Function Interface Description
AMIC Microphone GPIO4 / GPIO7 Differential input (positive/negative)
DAC Output GPIO23 Analog audio output, GPIO22 speaker enable
LCD SPI0 ILI9341 status display
Network RMII / USB NCM Ethernet or USB network sharing

Build Agora Sentino

ipro_voice_assistant

AI voice assistant running on IPRO7, combining real-time voice conversation with a Telegram text chatbot: talk to the AI through a microphone, or send text messages via Telegram.

Features

  • Voice Conversation: AMIC microphone capture → VAD voice detection → speech recognition → AI response → TTS speech synthesis → DAC speaker playback
  • AI Agent: Supports multiple cloud AI providers, with ReAct tool-calling capabilities (web search, scheduled tasks, persistent memory)
  • Telegram Chat: Receives messages via Telegram Bot API long polling and sends AI replies automatically
  • Animated LCD Display: ILI9341 SPI LCD (240×320) showing state animations (idle, listening, thinking, speaking)
  • Persistent Memory: LittleFS file system stores AI persona, user profile, and conversation memory
  • Network Connectivity: Ethernet (RMII) or a 4G LTE modem (PPPoS) — the shipped configuration defaults to LTE; IPRO7 has no built-in Wi-Fi

API Key Setup

The application requires cloud service API keys to operate. Never hardcode keys or commit them to version control — create secrets.h from the bundled template (already listed in .gitignore), or set keys at runtime via shell commands (persisted in LittleFS):

Set API Keys 
# Option 1: Compile-time setup (recommended)
cd apps/network/ipro_voice_assistant
cp secrets.h.example secrets.h
# Edit secrets.h with your keys, then rebuild

# Option 2: Runtime setup via shell commands (no reflash needed)
set_api_key <key>
set_telegram_token <token>

Build

Build Voice Assistant 
make -C apps/network/ipro_voice_assistant

Code Example

GPIO Usage Example 
#include "hal_gpio.h"

void gpio_example(void)
{
    // Configure GPIO as output
    gpio_set_mode(GPIO_PIN_0, GPIO_OUTPUT_MODE);

    // Set output high
    gpio_write(GPIO_PIN_0, 1);

    // Read input
    gpio_set_mode(GPIO_PIN_1, GPIO_INPUT_PP_MODE);
    int value = gpio_read(GPIO_PIN_1);

    // Toggle output
    gpio_toggle(GPIO_PIN_0);
}

Creating New Applications

Follow these steps to create your own application. We recommend copying ipro_ble_remote as a template and modifying it.

Tip: The fastest way is to copy an existing application as a starting point:

cp -r apps/bluetooth/ble/ipro_ble_remote apps/bluetooth/ble/my_app
rm -rf apps/bluetooth/ble/my_app/build

Then change the name in setup_project() on the last line of CMakeLists.txt and the PROJECT_NAME in the Makefile, and keep the copied .config.

Step 1: Create Directory

Applications must live in a category subdirectory under apps/ (apps/<category>/<name>); for example, BLE applications go in apps/bluetooth/ble/.

Create Application Directory 
mkdir -p apps/bluetooth/ble/my_app/include
mkdir -p apps/bluetooth/ble/my_app/src

Step 2: Create CMakeLists.txt

The application CMakeLists.txt is driven by project.build at the SDK root — it does not need cmake_minimum_required() or project(); just use the build functions provided by the SDK:

apps/bluetooth/ble/my_app/CMakeLists.txt 
# Add include directories
__component_add_include_dirs(include)

# Add application source files
# Note: main.c must NOT be added to target_sources, or it will
# cause duplicate symbol errors with --whole-archive linking
target_sources(app PRIVATE
    src/my_module.c
)

# Add the app library to the SDK link list
set_property(GLOBAL APPEND PROPERTY SDK_LIBS app)
# Force whole-archive linking if the app registers shell commands
set_property(GLOBAL APPEND PROPERTY SDK_WHOLE_ARCHIVE_LIBS app)

# Set the main file and finalize project setup
__set_main_file(main.c)
setup_project(my_app)

Step 3: Create Main Program

All FreeRTOS applications share the freertos_app_hooks component, which provides default heap, FreeRTOS hooks, and platform initialization (all weak functions, overridable by defining a non-weak version in your app). main.c only needs the minimal skeleton:

apps/bluetooth/ble/my_app/main.c 
#include "freertos_app_hooks.h"
#include "ipro_log.h"
#include <FreeRTOS.h>
#include <task.h>

#define TAG "MY_APP"

static void app_task(void *params)
{
    IPRO_LOGI(TAG, "My App Started!");

    while (1) {
        IPRO_LOGI(TAG, "Running...");
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

int main(void)
{
    // Platform init: heap + boot2 + log + shell (shared weak defaults)
    ipro_platform_init();

    // Create application task
    xTaskCreate(app_task, "app", 1024, NULL, 5, NULL);

    // Start scheduler
    vTaskStartScheduler();

    while (1) {}
}

Step 4: Create Configuration (.config)

The build system generates generated/autoconf.h from the .config in the application directory — the build fails without a .config. The simplest approach is to copy one from a template application:

Create Configuration 
# Copy the configuration from a template application
cp apps/bluetooth/ble/ipro_ble_remote/.config apps/bluetooth/ble/my_app/.config

Key configuration entries:

  • CONFIG_IPRO7=y — SoC selection
  • CONFIG_CPU_ID="intelpro_ipro7" — toolchain target
  • CONFIG_FREERTOS_SUPPORT=y — RTOS selection

The template application Makefiles include built-in configuration management targets: make defconfig (load default config), make savedefconfig (save current config as defconfig), make show-config (show current config), and make list-defconfigs (list available defconfigs). These targets only become available after copying a template Makefile in Step 5; a new application has no defconfig source file yet — run make savedefconfig first to create one from the current .config.

Step 5: Create Makefile

The application Makefile uses a delegation pattern, handing the build over to project.build at the SDK root. Note that the relative depth of IPRO_SDK_BASE depends on the application location (apps/bluetooth/ble/my_app/ needs 4 levels up). We recommend copying the Makefile from a template application (which includes the full set of configuration management targets) and changing only PROJECT_NAME:

apps/bluetooth/ble/my_app/Makefile 
# Set the SDK root according to the application directory depth
# apps/bluetooth/ble/my_app/ -> 4 levels up
IPRO_SDK_BASE ?= $(abspath ../../../../)
export IPRO_SDK_BASE

PROJECT_PATH ?= $(abspath .)
PROJECT_NAME ?= my_app

all:
	$(MAKE) -C $(IPRO_SDK_BASE) -f project.build PROJECT_PATH=$(CURDIR)

clean:
	$(MAKE) -C $(IPRO_SDK_BASE) -f project.build PROJECT_PATH=$(CURDIR) clean

# Copy the configuration management targets (defconfig / savedefconfig, etc.) from a template application's Makefile
.PHONY: all clean

Step 6: Build

Build New Application 
make -C apps/bluetooth/ble/my_app

# Or use the unified build entry point
./build_freertos.sh my_app build

The build output is located at apps/bluetooth/ble/my_app/build/build_out/my_app_IPRO7.bin.
