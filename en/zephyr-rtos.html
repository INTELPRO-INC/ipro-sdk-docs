Zephyr RTOS

Since IPRO SDK V2.1.0 the SDK is also a Zephyr v4.4.0 module: the same HAL and SoC drivers behind Zephyr's device driver API, so applications can be written for Zephyr directly. The FreeRTOS applications and their build flow are unchanged; see Getting Started.

Overview

  • west.yml at the SDK root makes the SDK the west manifest repository; zephyr/module.yml registers it as a Zephyr module (boards, SoC, device tree and drivers live in zephyr/).
  • The Zephyr drivers sit on top of the SDK HAL, which is compiled in place from bsp/, not copied.
  • Bluetooth LE uses Zephyr's host with the IPRO BLE controller; IEEE 802.15.4 uses Zephyr's driver interface and OpenThread.

Supported boards

Zephyr boardHardware

The ipro6s_evb board files come with the SDK, but IPRO6S is not supported under Zephyr in this release. The IPRO7AI Reef EVK has no Zephyr board definition yet; use the FreeRTOS applications for it.

Set up the workspace

You need Python 3.10 or later, CMake 3.20 or later, Ninja, git, dtc and the IPRO RISC-V toolchain (default /opt/toolchain/riscv_ipro7, override with IPRO_TOOLCHAIN). The first setup needs access to GitHub.

tools/zephyr/bootstrap.sh          # west workspace in zephyr-workspace/
source zephyr-workspace/env.sh     # ZEPHYR_BASE, CROSS_COMPILE, west

bootstrap.sh downloads Zephyr v4.4.0 and the modules west.yml lists (mbedTLS, tf-psa-crypto, OpenThread, MCUboot, LC3, zcbor, picolibc, SEGGER RTT) and applies the Zephyr patches listed in zephyr/patches.yml.

Build, flash and console

cd zephyr-workspace
west build -b ipro7_evb zephyr/samples/hello_world                       # a Zephyr sample
west build -b ipro7_evb ../zephyr/samples/periph_smoke -d build/smoke     # an SDK sample
west flash                                                               # IntelProCube command-line tool
  • west flash uses the IntelProCube command-line tool, named by IPRO_FLASH_TOOL or found on PATH.
  • It enters download mode through the IPRO7 CMSIS-DAP probe by default; without a probe use west flash -- --boot shell (through the running image's reboot_dl) or --boot manual.
  • Name the serial port with --port or IPRO_SERIAL_PORT; with a single USB serial port connected it is picked automatically.
  • The Zephyr console is on UART0 at 2,000,000 baud; tools/zephyr/monitor.sh opens it.

The SDK also carries the IPRO7 configuration for two of Zephyr's own samples:

# BLE heart-rate peripheral
west build -b ipro7_evb zephyr/samples/bluetooth/peripheral_hr -- \
    -DEXTRA_CONF_FILE=$PWD/../zephyr/samples/bt_peripheral_hr/ipro7.conf \
    -DEXTRA_DTC_OVERLAY_FILE=$PWD/../zephyr/samples/bt_peripheral_hr/ipro7.overlay

# OpenThread shell
west build -b ipro7_evb zephyr/samples/net/openthread/shell -- \
    -DEXTRA_CONF_FILE=$PWD/../zephyr/samples/ieee802154_shell/ot.conf \
    -DEXTRA_DTC_OVERLAY_FILE=$PWD/../zephyr/samples/ieee802154_shell/app.overlay

Prebuilt components

Except for the components below, a Zephyr build compiles all SDK code, the HAL included, from source:

  • BLE controller: components/wireless/bluetooth/ipro_ble_controller/lib/
  • RF driver: components/wireless/rf/ipro7_rf/lib/zephyr/
  • IEEE 802.15.4 MAC: components/wireless/ieee802154/lib/zephyr/

The RF and 802.15.4 archives come in two variants each: when the BLE controller is linked, the whole image is built with -fshort-enums, and the build picks the matching variant automatically.

Not supported yet

  • Low-power modes: PDS/HBN are not entered through Zephyr's pm_state, and the BLE controller does not sleep either.
  • Zephyr drivers for the display, camera, audio codec, USB, SD host, Ethernet and NPU (the IPRO7AI EVK's LCD works through Zephyr's own ST7789V driver).

Use the FreeRTOS applications for these; FreeRTOS remains the production RTOS.
