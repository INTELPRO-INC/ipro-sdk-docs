Matter & Thread

Release Status

IPRO SDK V2.0.1 does not include Matter or OpenThread stacks or complete applications. This page describes integration boundaries. It does not establish Matter/Thread certification or provide a runnable Matter build target.

Architecture

Matter is an IP-based application protocol using transports such as Wi-Fi, Ethernet and Thread, with BLE available for commissioning. See the official CSA Matter overview. BLE and TCP/IP components alone do not constitute a Matter integration.

Matter over Thread

Thread is a low-power IPv6 mesh network. Integration requires a compatible IEEE 802.15.4 radio, Thread stack and a Border Router for access to other IP networks. See the Thread Group overview. This release provides no example validating that complete path.

Wi-Fi/Ethernet Transport

IPRO7 has no built-in Wi-Fi. The release includes the paired ipro7_sdio_wifi and ipro6_if_wifi network examples. They establish connectivity but do not implement Matter endpoints, commissioning or credential management.

OpenThread Integration Scope

For Thread, first establish the target SoC/external radio, radio driver, platform abstraction and protocol versions. The SDK’s BLE controller archives are not an OpenThread implementation.

Available References

Validate IPRO6S Wi-Fi with apps/platform/ipro6_demo/, or IPRO7 sockets with the paired SDIO examples. Matter/Thread applications are not among this release’s 31 application configurations.

AI and Network Applications

AI examples use .inm or .tflite models. Sending inference results to a network service requires application-defined formats, buffering and transport. This release includes no Matter NPU embedding streaming example.

Configuration Prerequisites

After obtaining compatible protocol packages, confirm the toolchain, RTOS port, flash/RAM budget, persistent storage, entropy, credentials and OTA design. Adding a Kconfig option cannot enable a stack absent from the release.

Validation Order

Validate board drivers, wireless/Ethernet connectivity, IP transport and secure storage before protocol integration. Then test commissioning, reboot recovery and interoperability. Establish supported versions and certification from the resulting integration.
