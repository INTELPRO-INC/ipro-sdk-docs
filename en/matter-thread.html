Matter & Thread

Release Status

IPRO SDK V2.1.0 does not include a Matter stack or Matter applications. In V2.1.0, Thread is available under Zephyr RTOS only: Zephyr's OpenThread with the IPRO7 IEEE 802.15.4 driver. FreeRTOS applications do not include Thread. This page describes integration boundaries. It does not establish Matter/Thread certification or provide a runnable Matter build target.

Architecture

Matter is an IP-based application protocol using transports such as Wi-Fi, Ethernet and Thread, with BLE available for commissioning. See the official CSA Matter overview. BLE, TCP/IP or Thread components alone do not constitute a Matter integration.

Matter over Thread

Thread is a low-power IPv6 mesh network. Integration requires a compatible IEEE 802.15.4 radio, Thread stack and a Border Router for access to other IP networks. See the Thread Group overview. V2.1.0 provides an OpenThread CLI example under Zephyr RTOS but no Border Router or Matter example, so it cannot validate the complete Matter over Thread path.

Wi-Fi/Ethernet Transport

IPRO7 has no built-in Wi-Fi. Under FreeRTOS, V2.1.0 provides the IPRO7-side example for an IPRO6S SDIO radio (ipro7_sdio_wifi; the IPRO6S-side firmware is not in V2.1.0), its IPRO7AI Reef EVK counterpart with the IPRO6S FIN card (defconfig_wifi_ipro6s of ipro7ai_reef_demo; contact INTELPRO for the FIN-card firmware), the ATBM6162 module probe (ipro_atbm_probe) and Ethernet (the EMAC in ipro7_demo); see Networking. They establish connectivity but do not implement Matter endpoints, commissioning or credential management.

OpenThread (Zephyr RTOS)

In V2.1.0, Thread is available under Zephyr RTOS only: Zephyr's IEEE 802.15.4 driver drives the IPRO7 radio, with Zephyr's OpenThread above it. The RF driver and the 802.15.4 MAC link as prebuilt archives (components/wireless/rf/ipro7_rf/lib/zephyr/, components/wireless/ieee802154/lib/zephyr/). The example is Zephyr's samples/net/openthread/shell with the SDK's zephyr/samples/ieee802154_shell/ot.conf and app.overlay:

cd zephyr-workspace
west build -b ipro7_evb zephyr/samples/net/openthread/shell -d build/ot -- \
    -DEXTRA_CONF_FILE=<SDK>/zephyr/samples/ieee802154_shell/ot.conf \
    -DEXTRA_DTC_OVERLAY_FILE=<SDK>/zephyr/samples/ieee802154_shell/app.overlay

<SDK> is the absolute path of the SDK root. The Zephyr boards are ipro7_evb and ipro7ai_evk; workspace setup, flashing and console settings are in Zephyr RTOS. FreeRTOS applications do not include Thread, and the SDK's BLE controller archives are not an OpenThread implementation.

Available References

Validate IP connectivity with the FreeRTOS applications ipro7_demo (Ethernet), ipro7_sdio_wifi (IPRO6S SDIO radio) or defconfig_wifi_ipro6s of ipro7ai_reef_demo (IPRO6S FIN card); validate Thread with the Zephyr OpenThread shell example. None of the 34 FreeRTOS applications in V2.1.0 is a Matter or Thread application.

AI and Network Applications

AI examples use .inm or .tflite models. Sending inference results to a network service requires application-defined formats, buffering and transport. V2.1.0 includes no Matter NPU embedding streaming example.

Configuration Prerequisites

After obtaining compatible protocol packages, confirm the toolchain, RTOS port, flash/RAM budget, persistent storage, entropy, credentials and OTA design. Adding a Kconfig option cannot enable a stack absent from the release, and Thread is usable under Zephyr RTOS only; no configuration option turns it on in a FreeRTOS application.

Validation Order

Validate board drivers, wireless/Ethernet connectivity, IP transport and secure storage before protocol integration. Then test commissioning, reboot recovery and interoperability. Establish supported versions and certification from the resulting integration.
