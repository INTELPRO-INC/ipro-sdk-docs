Frequently Asked Questions

Quick solutions for common development issues

Build

What is the difference between make -C apps/<project> and build_freertos.sh?

build_freertos.sh is the recommended unified build entry point: it supports chaining actions such as build, flash, and monitor, lists all projects with -l, and resolves short project names automatically. make -C apps/<category>/<project> is the equivalent single-build method, which requires the full nested path.

# Recommended: unified CLI
./build_freertos.sh ipro_ble_remote build

# Chain build + flash + monitor
./build_freertos.sh ipro_ble_remote build flash monitor

# List all buildable projects
./build_freertos.sh -l

# Equivalent single-build method (full nested path required)
make -C apps/bluetooth/ble/ipro_ble_remote

# Clean build
make -C apps/bluetooth/ble/ipro_ble_remote clean

Build output is at apps/<category>/<project>/build/build_out/. Binary names include a chip suffix (e.g., ipro_ble_remote_IPRO7.bin).

Build

What is the .config file format? How to set CONFIG_* variables?

.config uses Linux Kernel Kconfig format. Each application has its own .config, and the build system auto-generates generated/autoconf.h from it.

# Basic format
CONFIG_IPRO7=y                          # Boolean: enabled
CONFIG_CPU_ID="intelpro_ipro7"          # String value
CONFIG_FREERTOS_SUPPORT=y               # RTOS selection
CONFIG_BLUETOOTH_LE_ENABLE=y            # BLE enable
# CONFIG_COMPONENTS_LWIP_ENABLE is not set                # Boolean: disabled

After modifying .config, rebuild is required. Common CONFIG variables include SoC selection (CONFIG_IPRO7), RTOS (CONFIG_FREERTOS_SUPPORT), and component enables (CONFIG_BLUETOOTH_LE_ENABLE, CONFIG_COMPONENTS_LWIP_ENABLE, CONFIG_COMPONENTS_MBEDTLS_ENABLE, etc.).

Build

Getting "toolchain not found" error during compilation?

Ensure the RISC-V toolchain is correctly installed and the path is set:

# Check toolchain path
ls /opt/toolchain/riscv_ipro7/bin/

# If not found, set the correct CROSS_COMPILE path
export CROSS_COMPILE=/your/toolchain/path/bin/riscv64-unknown-elf-

# Or specify in the build command
cmake -DCROSS_COMPILE=/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- ...

Make sure CONFIG_CPU_ID is correctly set in .config, otherwise the toolchain cannot detect architecture flags.

Build

Flash or RAM space insufficient during compilation?

First check the IPRO7 memory layout baseline to identify which region is overflowing:

RegionSizeAddress
FlashBoard-dependent (e.g. 2 MB on the IPRO7AI Reef EVK)0x13000000
PSRAM8 MB0x1e000000
OCRAM256 KB0x11010000
HBNRAM4 KB0x20090000

Optimize through the following methods:

  1. Disable unnecessary features in .config
  2. Use -Os optimization level
  3. Check if unused components are being compiled
# Show ELF size + memory region usage
./build_freertos.sh ipro_ble_remote size

# Check module sizes
riscv64-unknown-elf-size apps/bluetooth/ble/ipro_ble_remote/build/build_out/*.elf

# Detailed analysis
riscv64-unknown-elf-nm --size-sort apps/bluetooth/ble/ipro_ble_remote/build/build_out/*.elf | tail -50

Also check the per-region usage in the linker output, and inspect the .map file under build/build_out/ to find the largest consumers.

Build

How to flash firmware to the board? What if flashing fails?

Use the flash action of build_freertos.sh to build and flash in one step. The flasher is the IntelProCube v0.6.3 command-line tool, obtained separately; set IPRO_FLASH_TOOL to it or put its directory on PATH (the serial port name depends on your device):

# Build + flash + monitor serial output
./build_freertos.sh ipro_ble_remote build flash monitor -p /dev/cu.usbserial-XXXX

If flashing fails, check the following in order:

  1. Look for [All Success] in the tool output: the tool exits 0 even when flashing fails
  2. On macOS, you must use the /dev/cu.* device node, and the serial port name must be correct
  3. Make sure no other program is holding the serial port (check with lsof)
  4. Check the chip variant: --chip-variant IPRO7 for the IPRO7 EVB, IPRO7AI for the IPRO7AI EVK and the Reef (the tool has no --flash-pin option)
  5. If the board does not enter download mode automatically, type reboot_dl in the board shell to reboot into download mode and retry
  6. IPRO7AI Reef EVK: make sure jumper JP1 is fitted and use a 2 MB partition table (the one the application README names)
  7. Check the USB cable and power supply stability
Build

Does V2.1.0 support IPRO6S?

No. Every application in V2.1.0 targets IPRO7 (IPRO7 EVB, IPRO7AI EVK, IPRO7AI Reef EVK). The release ships no IPRO6S applications (ipro6_demo, ipro6_if_wifi and ipro6_btdm_phyrf are provided in V2.0.1 only), no IPRO6S BLE controller libraries and no ipro6_rf. Some IPRO6S driver and Wi-Fi stack sources remain in the tree, but IPRO6S builds are not supported in this release.

For IPRO6S development (BR/EDR A2DP / HFP, on-chip Wi-Fi 6, IPRO6S EVB) use V2.0.1.

BLE

How to choose the right BLE Controller linkN variant?

Choose the appropriate Controller variant based on your application needs:

LIBACLRoles
link1_periph1Peripheral
link11Central + Peripheral
link22Central + Peripheral
link44Central + Peripheral

Choose CONFIG_IPRO_BLE_CTLR_FEATURE="bt52" for basic BLE or "bt54_iso2" for BLE 5.4 with two ISO streams (CIS/BIS). The latter requires CONFIG_EM_SIZE of at least 32 KB. Keep the host connection limit within controller capacity; preserve the shipped PDM link2 / CONFIG_BT_CONN=1 configuration.

Select the variant via CONFIG_IPRO_BLE_CTLR_LIB in your application's .config:

# Select Controller variant
CONFIG_BT_CTLR_IPRO=y
CONFIG_BT_HOST_IPRO_V44=y
CONFIG_IPRO_BLE_CTLR_LIB="link1"
CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"
CONFIG_IPRO_BLE_CTLR_CFG_DBG=n
CONFIG_BT_CONN=1
CONFIG_EM_SIZE=32

V2.1.0 defaults: Remote uses link1_periph / bt52; Transparent and HID Keyboard use link1 / bt52; Throughput Test uses link2 / bt52; Headset uses link1_periph / bt54_iso2. PDM uses link2 / bt52 with CONFIG_BT_CONN=1. Only link1, link2 and link4 support both Central and Peripheral roles.

BLE

Is the BLE Controller provided as source code or prebuilt libraries?

The BLE Controller is provided only as prebuilt static libraries (.a), selected by ACL count, feature profile and CFG_DBG, under components/wireless/bluetooth/ipro_ble_controller/lib/. Controller source code is not included in the SDK. V2.1.0 provides the 16 IPRO7 libraries only (link1_periph / link1 / link2 / link4 × bt52 / bt54_iso2 × debug / release).

Simply select the variant to link in your application's .config:

# Select Controller variant
CONFIG_BT_CTLR_IPRO=y
CONFIG_BT_HOST_IPRO_V44=y
CONFIG_IPRO_BLE_CTLR_LIB="link1"
CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"
CONFIG_IPRO_BLE_CTLR_CFG_DBG=n
CONFIG_BT_CONN=1
CONFIG_EM_SIZE=32

Important

The prebuilt libraries must not be modified. If you need a customized Controller variant (e.g., a different link count or feature combination), please contact INTELPRO for support.

BLE

How does multi-connection work with different role combinations?

IPRO SDK uses a unified connection pool model. For example with link4, the 4 connections can be any Central/Peripheral combination:

  • 4 Peripherals (passive connections)
  • 4 Centrals (active connections)
  • 2 Central + 2 Peripheral (mixed)
  • Any other combination within the total connection limit

A device can simultaneously advertise and scan, for Relay, Mesh-like topologies, and other advanced scenarios.

Phone cannot discover the BLE device?

Check the following items:

  1. Confirm Advertising is started
  2. Verify Advertising Data is correctly configured
  3. Ensure correct Service UUIDs are included
  4. Check if RF is working properly

static const struct bt_data ad[] = {

bt_le_adv_start(BT_LE_ADV_CONN_FAST_1, ad, ARRAY_SIZE(ad),
                NULL, 0);
BLE

LE Audio has noise or stuttering?

Audio quality issues may come from:

  • Improper ISO Interval configuration
  • LC3 codec parameter mismatch
  • Buffer underrun/overrun
  • RF interference or weak signal
// Recommended LE Audio parameters (48_4 configuration set):
// 48kHz sampling rate, 10ms frame duration, 120 octets per frame
// ipro_bt_host provides the matching macro (include/bluetooth/audio/lc3.h):
BT_CODEC_LC3_CONFIG_48_4(loc, stream_context)

For the complete codec configuration flow, refer to the LE Audio headset example: apps/bluetooth/le_audio/ipro_le_audio_headset.

BLE

BLE pairing (bonding) information is not persisted, or the Controller fails to link?

Bluetooth Host bonding keys are persisted through the Settings backend. NVDS stores controller configuration and does not by itself persist host bonds. Follow the PDM or headset example:

CONFIG_BT_SMP=y
CONFIG_BT_SETTINGS=y
CONFIG_EASYFLASH4=y

After bt_enable() completes, call settings_load_subtree("bt") and check its result before advertising. Retain the example’s flash partition and storage initialization. If reflashing erases the store, remove the old bond on the peer and pair again.

BLE

How to optimize BLE throughput?

Key settings for higher BLE data throughput:

  1. Switch to 2M PHY
  2. Enable DLE (Data Length Extension)
  3. Negotiate a larger ATT MTU
  4. Use a shorter connection interval

The SDK throughput test example (apps/bluetooth/ble/ipro_throughput_test) achieves up to 999 Kbps measured with 2M PHY + DLE, and serves as a reference implementation for parameter tuning.

BLE

How to perform OTA firmware upgrade?

The ipro_ble_remote example (apps/bluetooth/ble/ipro_ble_remote) includes a built-in OTA GATT service, providing a complete reference implementation for transferring and updating firmware over BLE that you can adopt in your own application.

V2.1.0 includes tools/create_ota.py, which packs a combined firmware image into the boot2 .xz.ota format. Under Zephyr RTOS, MCUboot is built through sysbuild (zephyr/samples/mcuboot_app) and images are uploaded over BLE with MCUmgr SMP (zephyr/samples/ble_ota); see Zephyr RTOS.

Debug

What is the difference between cu.* and tty.* serial ports on macOS?

On macOS, each serial device has two device nodes (the serial port name below depends on your device):

  • /dev/cu.* (Calling Unit) - You must use this device. Does not wait for DCD signal, opens immediately.
  • /dev/tty.* (Teletype) - Waits for DCD signal, causing the program to hang.
# Bundled with V2.1.0; the baud rate is the app's CONFIG_PLATFORM_UART_BAUDRATE (115200 when unset)
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --baud 115200 --timeout 60

# Or install pyserial separately
python3 -m pip install pyserial
python3 -m serial.tools.miniterm /dev/cu.usbserial-XXXX 115200
Debug

Getting "Resource busy" error on serial port?

This is usually because another program (including stty) is holding the serial port. Solutions:

  1. Check and close programs using the port: lsof /dev/cu.usbserial-XXXX (the serial port name depends on your device)
  2. Avoid using stty -f, which keeps the port busy
  3. Use one serial monitor at a time (tools/serial_monitor.py, an external terminal or the extension monitor)

The monitor and test actions of build_freertos.sh also open the serial port. Stop the active monitor before flashing or opening another terminal.

How to analyze Hard Fault?

Hard Fault is usually caused by:

  • Null pointer access
  • Stack overflow
  • Unaligned memory access
  • Illegal instruction
# Use addr2line to parse backtrace
# The ELF name includes a chip suffix (e.g., ipro_ble_remote_IPRO7.elf)
riscv64-unknown-elf-addr2line -e apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.elf 0x12345678
RF

How to adjust CFO (Carrier Frequency Offset)?

CFO issues usually have two causes:

  1. rf_kcal not executed: Check RF_CAL_STATE_CTRL register
  2. XTAL frequency deviation: Adjust capcode

Adjust the XTAL capcode with the AON driver API (bsp/drivers/ipro7_soc/std_drv/inc/drv_aon.h):

// Adjust XTAL capcode
// Negative CFO (frequency too low): Decrease capcode
// Positive CFO (frequency too high): Increase capcode
AON_Set_Xtal_CapCode(70, 70);          // Set capcode (in / out)

uint8_t cap = AON_Get_Xtal_CapCode();  // Read back current capcode
RF

How to configure TX Power?

IPRO7 supports TX Power from -3dBm to +10dBm (1dB step):

// The parameter is the target power (dBm); the function
// automatically picks the closest power table entry
rf_set_tx_power(10);   // +10dBm (maximum)
rf_set_tx_power(0);    // 0dBm
rf_set_tx_power(-3);   // -3dBm (minimum)

For more advanced RF tuning (e.g., custom power tables), please contact INTELPRO for support.

RF

Does IPRO7 support Wi-Fi?

IPRO7 itself does not include Wi-Fi. V2.1.0 provides these networking options:

  • IPRO6S as the SDIO Wi-Fi radio: ipro7_sdio_wifi is the IPRO7-side SDIO host example (ipronet_host, lwIP netif iproeth0, DHCP, iperf); the IPRO6S-side ipro6_if_wifi is not in V2.1.0 - use V2.0.1 or contact INTELPRO.
  • ATBM6162 SDIO module: ipro_atbm_probe (module bring-up probe).
  • IPRO6S FIN card on the IPRO7AI Reef EVK (SDIO): the host side is ipro7ai_reef_demo with defconfig_wifi_ipro6s (Wi-Fi and an RTSP camera stream). The IPRO6S firmware for the FIN card is not in V2.1.0; contact INTELPRO.
  • Ethernet: ipro_enc28j60_test (ENC28J60 over SPI) and the IPRO7 EMAC (RMII) in ipro7_demo.

For IPRO6S development itself, use V2.0.1.

RTOS

Which RTOSes does the SDK support? Is the BLE Host Zephyr?

The SDK uses FreeRTOS as its main operating system; all 34 applications in V2.1.0 are built with FreeRTOS:

# Every application's .config uses
CONFIG_FREERTOS_SUPPORT=y

The BLE Host protocol stack (GAP, GATT, L2CAP, SMP, ISO, LE Audio) originates from the Zephyr project, and the application layer uses Zephyr-style bt_* callback APIs -- in FreeRTOS applications it runs on top of FreeRTOS, so no Zephyr installation or build is required.

# Build a BLE application (FreeRTOS + Zephyr-based BLE Host)
./build_freertos.sh ipro_ble_remote build

In addition, from V2.1.0 the SDK is also a Zephyr v4.4.0 module: Zephyr applications build with west for the IPRO7 EVB (ipro7_evb) and IPRO7AI EVK (ipro7ai_evk). Zephyr in this release provides no low-power modes and no display, camera, audio codec, USB, SD host, Ethernet or NPU drivers; use FreeRTOS for those. See Zephyr RTOS.

RTOS

Can I use Thread (IEEE 802.15.4) or Matter?

Thread is available under Zephyr RTOS only: Zephyr's IEEE 802.15.4 driver for the IPRO7 radio and OpenThread, with Zephyr's samples/net/openthread/shell plus the SDK's zephyr/samples/ieee802154_shell/ot.conf and app.overlay. The RF driver and the 802.15.4 MAC link as prebuilt libraries.

The FreeRTOS applications in V2.1.0 do not include Thread, and this release does not include Matter. See Zephyr RTOS.

RTOS

How to solve Task Stack Overflow?

Increase the Task stack size:

// FreeRTOS
xTaskCreate(
    task_function,
    "TaskName",
    2048,  // Increase Stack size (words)
    NULL,
    tskIDLE_PRIORITY + 1,
    &task_handle
);

You can also enable Stack monitoring to track usage.
