IPRO SDK VS Code Extension

⚠ Release SDK Notice: This extension is not included in Release SDK v1.0.1. The content below is for reference only. Contact the vendor to obtain the extension (.vsix) and the tools it invokes: the flash tool (tools/ipro_iot_tool_lite/) and the serial monitor (tools/serial_monitor.py).

A VS Code extension designed specifically for IPRO SDK, providing an all-in-one development experience on Windows, macOS, and Linux: build, flash, serial monitoring, Kconfig configuration, and memory analysis.

Overview

The IPRO SDK Extension (v2.1.0) is a single extension that activates automatically when you open a workspace containing build_freertos.sh — no companion extensions required.

Core Capabilities

  • Project overview and switching (Projects / Device / Quick Actions sidebar views)
  • One-click Build / Clean / Flash / Serial Monitor
  • Menuconfig editing (graphical UI + terminal menuconfig)
  • Memory Map visualization and build-time memory analysis
  • Build Profiles (debug / release / size) and batch builds

System Requirements

Item Requirement
VS Code 1.102 or later
Operating System Windows / macOS / Linux
Build Tools CMake (≥ 3.20) + Make or Ninja
Toolchain RISC-V cross-compiler (default /opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-)
Python 3 Required for automatic download-mode entry before flashing and for terminal menuconfig (pip install kconfiglib)

Features

Three-View Sidebar

The Projects view auto-scans all projects in the SDK with Pin-to-top and Recent Projects support; the Device view shows the serial port, SDK and toolchain versions; Quick Actions provides one-click operations.

One-Click Build & Flash

Build / Clean / Flash / Serial Monitor can all be triggered from Quick Actions or keyboard shortcuts, with build results and duration shown in the status bar.

Menuconfig Integration

Four ways to edit Kconfig settings: graphical .config editor, terminal menuconfig, Load Defconfig, and opening .config directly.

Memory Map Visualization

Flash / RAM donut charts, stacked region bars, component treemap, and build-to-build comparison, with CSV or Markdown report export.

Build Profiles

Switch between debug (-O0 -g) / release (-O2) / size (-Os) build configurations with one click, plus multi-project Batch Build support.

Serial Port Auto-Detection

Polls USB serial devices every 3 seconds, updating the status bar and Device view instantly on plug/unplug; macOS automatically lists /dev/cu.usb* devices.

In addition, after a successful build the extension auto-detects compile_commands.json and configures IntelliSense for the C/C++ extension; built-in problem matchers ($ipro-gcc-error, $ipro-gcc-warning, $ipro-linker, $ipro-cmake) make compile and link errors clickable, jumping straight to the source.

Installation Guide

1. Install the Extension

  1. Obtain ipro-sdk-extension-2.1.0.vsix from the vendor
  2. Open the VS Code Extensions panel (Ctrl+Shift+X) and drag the .vsix file into the panel, or install from the command line:
Command-line Installation 
code --install-extension ipro-sdk-extension-2.1.0.vsix

2. Prepare the Toolchain

Install RISC-V Toolchain (macOS / Linux) 
# Download and extract the toolchain to /opt/toolchain/riscv_ipro7/
# The extension uses this path by default — no extra configuration needed

# Verify installation
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-gcc --version

If your toolchain is installed elsewhere, override the cross-compiler prefix with the devtool.toolchainPath setting (e.g., /your/path/bin/riscv64-unknown-elf-).

3. Open the SDK Workspace

  1. Select File → Open Folder... and open the IPRO SDK root directory
  2. Once build_freertos.sh is detected, the extension activates automatically and the IPRO SDK icon appears in the left activity bar
  3. If the SDK is not at the workspace root, run F1 → IPRO SDK: Set SDK Root to set the path manually

Automatic Flash Tool Location

Flashing uses the SDK's built-in tools/ipro_iot_tool_lite/ipro_iot_tool_lite (.exe on Windows). The extension locates it automatically from the SDK root — no separate download or path configuration needed.

Development Workflow

1. Select a Project

  1. Click the IPRO SDK icon in the left activity bar
  2. Click a project in the Projects view (right-click to Pin to top; the 5 most recently used projects are listed below pinned ones)
  3. The project description shows build status and time (e.g., IPRO7 ✓ 2m ago)

2. Configure (Optional)

  • Menuconfig: Edit the project's .config graphically
  • Load Defconfig: Load a default configuration file
  • Open .config: Open the configuration file directly in the text editor
  • Build Profile: Switch between debug / release / size with IPRO SDK: Select Build Profile; the current profile is shown in the status bar

3. Build

Click Build in Quick Actions, or press Ctrl+Shift+B in the editor. The build generator defaults to make and can be switched to ninja via the devtool.generator setting.

Build Output Example 
[Build] [1/45] Building C object ...
[Build] [45/45] Linking C executable ...
Build OK (12.3s)

After the build completes, the firmware file is located at (the apps/ directory uses a nested <category>/<name> structure):

apps/<category>/<name>/build/build_out/<name>_IPRO7.bin

After a successful build, the extension automatically applies compile_commands.json to C/C++ IntelliSense and refreshes the Memory Map panel; compile errors and warnings are clickable in the Problems panel.

4. Batch Build

Run IPRO SDK: Batch Build to select multiple projects and build them sequentially with overall progress tracking — useful for verifying several applications at once.

Other Helper Commands

  • IPRO SDK: New Project: Create a new project from a template
  • IPRO SDK: Dashboard: Open the project overview panel showing build state and firmware size

Flashing & Monitoring

Flashing

  1. Connect the development board via USB
  2. Click Flash in Quick Actions, or press Ctrl+Shift+F in the editor
  3. If no serial port is configured, the extension lists the detected devices for selection (macOS lists /dev/cu.usb*, Linux lists /dev/ttyUSB* and /dev/ttyACM*, Windows lists COM ports)
  4. The extension first sends reboot_dl via tools/serial_monitor.py to put the board into download mode, then invokes ipro_iot_tool_lite to flash

Configuration Parameters

Setting Description Default Value
devtool.serialPort Serial port used for flashing and monitoring Empty (auto-detection + QuickPick selection)
devtool.baudRate Serial transfer rate 921600
devtool.flashPin Flash pin parameter passed to ipro_iot_tool_lite 0x02
devtool.partitionTable Partition table file path (optional, maps to the --pt parameter) Empty
devtool.autoDetectPort Auto-detect serial ports when USB devices are plugged in/out true

The chip name (e.g., ipro7) is filled in automatically from the project configuration — no manual input required.

Flash Progress

Flash progress is shown in the VS Code notification area at the bottom right, passing through four stages:

  1. boot / partition: Writes the bootloader and partition table
  2. Firmware write: Flashes the main firmware with a live percentage
  3. Verify: Firmware verification
  4. Complete: Shows a Flash complete notification

Serial Monitoring

Click Monitor in Quick Actions, or press Ctrl+Shift+S in the editor. The extension opens an integrated terminal and connects to the board using the SDK's built-in tools/serial_monitor.py (automatically sending reboot to restart and capture the full boot log). If the tool is not present in the SDK, it falls back to system utilities (screen on macOS / Linux).

macOS Serial Port

On macOS, you must use /dev/cu.* devices (e.g., /dev/cu.usbserial-XXXX — the actual name depends on your device), not /dev/tty.*. The tty.* devices block waiting for the DCD signal. The extension's auto-detection already lists only cu.* devices.

Memory Map Visualization

Run IPRO SDK: Memory Map (or click Memory Map in Quick Actions) to open the memory analysis panel, which parses the .map file produced by the build:

  • Flash / RAM donut charts: Colored segments show each section's share, with the usage percentage in the center
  • Stacked region bars: Each memory region shows the distribution of .text, .rodata, .data, .bss, and other sections; usage is color-coded (green <70%, yellow 70–85%, red >85%)
  • Component table: Sortable and searchable, with expandable rows showing per-section breakdown for each component
  • Component treemap: Shows the top 20 components by size with proportional rectangles
  • Build comparison: Automatically compares against the previous build, marking deltas (±KB) in red/green
  • Export: One-click export to CSV (component breakdown) or Markdown (full report)

When Flash or RAM usage exceeds the threshold (devtool.memoryThresholdFlash / devtool.memoryThresholdRam, default 85%), the extension proactively shows a warning notification. The panel refreshes automatically after a successful build.

For IPRO7's memory layout reference: Flash 1 MB, PSRAM 8 MB, OCRAM 256 KB. See Hardware Specifications for details.

FAQ

Q1: The sidebar shows "No IPRO SDK detected"

Problem: The extension cannot find the SDK.

Solution:

  1. Verify the opened workspace contains build_freertos.sh at the SDK root
  2. Or run F1 → IPRO SDK: Set SDK Root to set the SDK path manually (written to the devtool.sdkRoot setting)

Q2: Toolchain not found

Problem: Build fails because riscv64-unknown-elf-gcc cannot be found.

Solution:

  1. Verify the toolchain is installed at the default path /opt/toolchain/riscv_ipro7/bin/
  2. If installed elsewhere, set the cross-compiler prefix via the devtool.toolchainPath setting (e.g., /your/path/bin/riscv64-unknown-elf-)

Q3: Serial port not listed or connection failed

Problem: No serial port found when flashing or monitoring, or the connection fails.

Solution:

  1. Verify the USB cable is connected and the driver is working, then run IPRO SDK: Select Serial Port to re-select
  2. Close other programs occupying the serial port (terminals, other monitoring tools)
  3. On macOS, make sure you selected a /dev/cu.* device
  4. Verify devtool.autoDetectPort is enabled, and wait about 3 seconds after plugging in USB for auto-detection to update

Q4: "Binary not found" when flashing

Problem: The firmware file does not exist.

Solution:

  1. Run Build first (Ctrl+Shift+B)
  2. Verify <name>_IPRO7.bin exists under apps/<category>/<name>/build/build_out/

Q5: "Flash tool (ipro_iot_tool_lite) not found in SDK tools/"

Problem: The flash tool cannot be found in the SDK.

Solution:

  1. Verify tools/ipro_iot_tool_lite/ipro_iot_tool_lite exists under the SDK root
  2. This tool is not included in Release SDK v1.0.1 — contact the vendor to obtain it, then place it at the path above

CLI Tools Integration

In addition to the VS Code Extension GUI, you can also use command-line tools directly for development. The apps/ directory uses a nested <category>/<name> structure, so make -C requires the full path; use ./build_freertos.sh -l to list all projects.

Build

Command-line Build 
# List all projects
./build_freertos.sh -l

# Recommended build method (full nested path)
make -C apps/bluetooth/ble/ipro_ble_remote

# Or using build_freertos.sh (accepts the project name)
./build_freertos.sh ipro_ble_remote build

# Clean build
make -C apps/bluetooth/ble/ipro_ble_remote clean

Flash Tool

The SDK's built-in flash tool is at tools/ipro_iot_tool_lite/ipro_iot_tool_lite (not OpenOCD):

Command-line Flash (macOS / Linux) 
# Serial port name depends on your device (use /dev/cu.* on macOS)
tools/ipro_iot_tool_lite/ipro_iot_tool_lite \
    --chipname ipro7 \
    --port /dev/cu.usbserial-XXXX \
    --firmware apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.bin \
    --baudrate 921600 --flash-pin 0x02

macOS Serial Port

On macOS, you must use /dev/cu.usbserial-XXXX (cu.* — the actual name depends on your device), not /dev/tty.*. The tty.* devices block waiting for the DCD signal.

Automated Testing

Use board_test.sh for a complete build, flash, serial monitoring, and test result parsing workflow:

Automated Board Testing 
# Full test cycle (build + flash + monitor + parse results)
tools/board_test.sh --project apps/test/ipro_unit_test

# Exit codes: 0=pass, 1=fail, 2=timeout

Keyboard Shortcuts

The extension provides three dedicated shortcuts (the editor must be focused):

Function Shortcut Description
Build Ctrl+Shift+B Build the currently selected project
Flash Ctrl+Shift+F Flash firmware to the development board
Serial Monitor Ctrl+Shift+S Open the serial monitor
Open Command Palette Ctrl+Shift+P or F1 Standard VS Code (search "IPRO SDK" to list all commands)
Extensions Panel Ctrl+Shift+X Standard VS Code
