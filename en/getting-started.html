Getting Started

This guide will walk you through setting up the IPRO SDK Release package and building your first application.

Release SDK Notice: The source archive omits the flash tool, board-test scripts and VS Code extension. For separately versioned Windows tools, see Installation & Updates.

Online Installer 3.4.0 reads the component catalog; the fixed 3.3.0 installer bundles SDK 1.2.1. As of 2026-09-10, the catalog also selects SDK 1.2.1. Obtain V2.0.1 from its release page and select its extracted directory explicitly. Installation and version selection

SDK V2.0.1

Download IPRO-SDK-V2.0.1 (2026-09-09) for source, the Android microphone demo APK and the matching test firmware. The source package contains 31 application configurations; use the shipped configuration for your board.

Extract IPRO-SDK-V2.0.1.tar.gz into a new directory and verify VERSION.txt. Obtain the matching RISC-V toolchain separately; the release README specifies GCC 14. The catalog's Windows GCC 13.1.1 package is declared for SDK 1.2.1, so do not assume that declaration covers 2.0.1.

Prerequisites

Before starting, ensure your development environment meets the following requirements:

Hardware Requirements

  • IPRO7 Development Board (EVB)
  • USB Cable (for flashing and serial communication)

Software Requirements

  • Operating System: Linux (Ubuntu 20.04+ recommended) or macOS
  • Toolchain: RISC-V GCC Cross Compiler (/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-*)
  • Build Tools: CMake 3.19+, Ninja, Make
  • Python: Python 3.8+ (for development tools and scripts)
  • tar: For extracting the SDK release package
Install Basic Tools (Ubuntu/Debian) 
# Install build tools
sudo apt update
sudo apt install -y cmake ninja-build python3 python3-pip git

# Verify installation
cmake --version
ninja --version
python3 --version
Install Basic Tools (macOS) 
# Install via Homebrew
brew install cmake ninja python3 git

# Verify installation
cmake --version
ninja --version
python3 --version

Installation

1. Extract the Release SDK Package

Note: This is the Release version of the SDK package; you do not need Git to obtain the source code. Simply extract the release package you received.
Extract Release SDK 
# Extract the SDK release package
# Enter the extracted release directory
cd IPRO-SDK-V2.0.1
cat VERSION.txt

2. Setup Toolchain

IPRO SDK uses a RISC-V cross compiler. The default path is /opt/toolchain/riscv_ipro7/.

Verify Toolchain 
# Verify toolchain exists
ls /opt/toolchain/riscv_ipro7/bin/

# You should see files like:
# riscv64-unknown-elf-gcc
# riscv64-unknown-elf-g++
# riscv64-unknown-elf-objcopy
# ...

# Verify the compiler runs
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-gcc --version
Note: If your toolchain is in a different location, specify the CROSS_COMPILE parameter during build, e.g.: CROSS_COMPILE=/your/path/bin/riscv64-unknown-elf-.

Quick Start Build

Traditional FreeRTOS development approach, suitable for developers familiar with FreeRTOS.

Use Make Build (Recommended)

Make Build 
# Build BLE Remote application
make -C apps/bluetooth/ble/ipro_ble_remote

# Build LE Audio Headset application
make -C apps/bluetooth/le_audio/ipro_le_audio_headset

# Build IPRO7 Demo application
make -C apps/platform/ipro7_demo

# Clean build
make -C apps/bluetooth/ble/ipro_ble_remote clean

Use Build Script

FreeRTOS Build Script 
# Build BLE Remote application
./build_freertos.sh ipro_ble_remote build

# Build platform demo application
./build_freertos.sh ipro7_demo build

Manual CMake Build

CMake Build Commands 
# Configure project (nested apps require CONFIG_APP_CATEGORY)
cmake -S . -B apps/bluetooth/ble/ipro_ble_remote/build \
    -G "Ninja" \
    -DIPRO_SDK_BASE=$(pwd) \
    -DCONFIG_BUILD_PORJECT=ipro_ble_remote \
    -DCONFIG_APP_CATEGORY=bluetooth/ble \
    -DCMAKE_PREFIX_PATH=$(pwd)/cmake \
    -DCUSTOM_CONFIG_DIR=$(pwd)/apps/bluetooth/ble/ipro_ble_remote \
    -DCONFIG_APPS=1 \
    -DCROSS_COMPILE=/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-

# Execute build
cmake --build apps/bluetooth/ble/ipro_ble_remote/build

Let's build and verify the BLE Remote application.

Step 1: Build Application

Build BLE Remote 
make -C apps/bluetooth/ble/ipro_ble_remote

Step 2: Check Build Output

Check Output Files 
# List build artifacts
ls -la apps/bluetooth/ble/ipro_ble_remote/build/build_out/

# You should see (all artifact names include the chip suffix):
# ipro_ble_remote_IPRO7.bin  - Binary flash file
# ipro_ble_remote_IPRO7.elf  - ELF executable
# ipro_ble_remote_IPRO7.map  - Memory map file
# lib/                       - Component static libraries
Success! If the build completes without errors, you have successfully set up the IPRO SDK development environment.

Kconfig Configuration System

The SDK uses a Linux kernel-style Kconfig system to manage project configuration. Each application has its own .config file, and the build system automatically generates a generated/autoconf.h header file.

Configuration File Hierarchy

  • Root config: Kconfig - aggregates all option definitions (pulls in lower-level Kconfig files via source)
  • Per-layer option definitions: bsp/Kconfig and components/Kconfig - option definitions for the BSP and middleware components
  • App config: apps/<category>/<project>/.config - the complete build configuration for each application, from which generated/autoconf.h is generated at build time

Common Configuration Options

.config Example 
# SoC selection
CONFIG_IPRO7=y
CONFIG_CPU_ID="intelpro_ipro7"

# RTOS selection
CONFIG_FREERTOS_SUPPORT=y

# Wireless features
CONFIG_BLUETOOTH_LE_ENABLE=y

# BLE controller prebuilt library variant selection
CONFIG_BT_CTLR_IPRO=y
CONFIG_BT_HOST_IPRO_V44=y
CONFIG_IPRO_BLE_CTLR_LIB="link2"
CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"
CONFIG_IPRO_BLE_CTLR_CFG_DBG=n
CONFIG_BT_CONN=2
CONFIG_EM_SIZE=32

# Component enables
CONFIG_LWIP=y
CONFIG_MBEDTLS=y
Tip: CONFIG_CPU_ID must be correctly set in .config for the toolchain to detect the proper architecture flags. cmake/toolchain.cmake auto-detects vendor GCC vs standard GCC and adjusts compiler flags accordingly.

Flashing Firmware

Release SDK Notice: The flash tool ipro_iot_tool_lite and the automated test script board_test.sh are not included in this Release SDK package. To obtain the flash tool, please contact IntelPro for the full development tool suite.

Serial Port Tips (General Knowledge)

macOS Note: Serial ports must use /dev/cu.* devices, not /dev/tty.*. The tty.* devices block waiting for the DCD signal. Linux users should use /dev/ttyUSB0 or similar devices.

Serial Monitoring

V2.0.1 does not include tools/serial_monitor.py. The CLI still references that path, so its monitor and test actions need the separate helper. Use the extension's IPRO: Serial Monitor or a serial terminal instead.

Choose the console baud rate from the selected application and board configuration. On macOS use /dev/cu.*. Stop monitoring before flashing to release the port.

Board Testing

The SDK includes apps/test/ipro_unit_test/ for HAL and shared-component tests. Build it, flash the matching board with the separate flash tool, then inspect the console for ALL TESTS PASSED or SOME TESTS FAILED.

make -C apps/test/ipro_unit_test

Neither tools/board_test.sh nor tools/serial_monitor.py is bundled. The build CLI's test command also requires those external flash / monitor tools; it is not a complete test environment by itself.

Debugging Setup

Using GDB

Start GDB Debugging 
# Use RISC-V GDB for debugging (the ELF name includes the chip suffix)
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-gdb \
    apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.elf

Serial Debugging

Most applications support real-time debugging via serial CLI. After connecting to the serial port, use the following commands:

  • reboot - Normal reset
  • reboot_dl - Enter download mode (for reflashing)
Note: Install the VS Code extension separately. Follow the Extension guide to configure SDK, toolchain and debugger paths.

Troubleshooting

macOS Serial Port Issues (General Knowledge)

Note: Use an external serial terminal; the monitor helper is absent from V2.0.1.
Problem Solution
Serial connection unresponsive or blocked Use /dev/cu.* instead of /dev/tty.*. The tty.* devices block waiting for the DCD signal.
cat command shows no output cat has buffering issues with serial ports on macOS. Use a dedicated serial terminal tool (e.g., minicom, screen, or picocom) instead.
Serial port shows "Resource busy" Ensure no other program is using the port (e.g., stty, other serial monitors). Try unplugging and replugging the USB cable if needed.

Toolchain Issues

Problem Solution
Toolchain not found Verify that /opt/toolchain/riscv_ipro7/bin/ exists and contains riscv64-unknown-elf-gcc.
Toolchain in a different path Set the CROSS_COMPILE environment variable to point to the correct path.

Build Errors

Problem Solution
Architecture flag detection fails Ensure CONFIG_CPU_ID is correctly set to "intelpro_ipro7" in the .config file.
CMake configuration errors Try cleaning the build directory: make -C apps/<project> clean, then rebuild.
CI CMake does not work on macOS V2.0.1 requires a separately installed CMake 3.19+ on PATH; use a build for your host OS.
