AI & NPU

⚠ Release SDK Notice: AI/NPU components are only partially included in Release SDK v1.0.1 (ai/ source code available, ISP algorithm is prebuilt library). Full AI development tools must be obtained separately.

IPRO7AI features a built-in 0.1 TOPS Neural Processing Unit (NPU) designed for edge AI inference. Combined with the IPROAI inference framework and YOLOv8 post-processing engine, it enables object detection, image classification, and keyword spotting at low power consumption.

NPU Architecture

The IPRO7 NPU works in tandem with the RISC-V CPU, supporting a hybrid execution mode. Each layer is automatically dispatched to the optimal execution device based on its operator type:

AI System Architecture 
┌──────────────────────────────────────────────────┐
│              Application Layer                    │
│      ipro7_demo  │  Custom App                    │
├──────────────────────────────────────────────────┤
│          IPROAI Framework (components/ai/)        │
│   iproai_core  │  iproai_inst  │  postprocess    │
│   Model Load   │  Layer Sched  │  YOLOv8 / NMS   │
├──────────────────────────────────────────────────┤
│         Execution Backend                         │
│   ┌─────────────────┐  ┌──────────────────────┐  │
│   │   CPU Backend    │  │    NPU Backend       │  │
│   │   Softmax, YOLO  │  │    Conv, Pool, FC    │  │
│   │   Route, Reshape │  │    DW-Conv, MatMul   │  │
│   │   NMSIS DSP Ops  │  │    Activation (HW)   │  │
│   └─────────────────┘  └──────────────────────┘  │
├──────────────────────────────────────────────────┤
│         Memory / DMA Interface                    │
│   PSRAM (8 MB)   │  OCRAM (256 KB)  │  Flash     │
└──────────────────────────────────────────────────┘

Supported Operators

The NPU hardware accelerates the following operators. All other operators fall back to CPU execution:

Backend Supported Operators
NPU Convolution, Depthwise Conv, MaxPool, AvgPool, Fully Connected, MatMul, Activation (ReLU/ReLU6/Leaky)
CPU Softmax, YOLO, Route, Shortcut, Upsample, Reshape, Transpose, Pad, ArgMax, Resize Bilinear, SSD, Gather, Mean, Dequantize
Activations Leaky, ReLU, Linear, ReLU6, Mish, ELU, Logistic, Swish, GELU, Tanh, PReLU

Quantization Format

IPROAI uses INT8 fixed-point (fixed_point_t = int8_t) for inference. It supports TFLite-style per-channel quantization parameters (multiplier + shift), allowing direct conversion from TensorFlow Lite quantized models.

.blai Model Format

IPROAI uses a custom .blai binary model format. The model file contains the following sections:

  • Header (32 bytes): 8 uint32 fields recording the size of each section
  • CPU instruction section: Layer definitions, connectivity, quantization parameters
  • NPU instruction section: NPU hardware instructions (16 bytes each)
  • Weights section: INT8 quantized weight data
  • Bias section: INT32 bias data
  • Multiplier/Shift section: Per-channel quantization parameters

Model Loading Methods

Load from SD Card 
/* Model stored on SD card at /sdcard/ai_model/person_pet_detect.blai */
iproai_model_hdl_t hdl = iproai_create();
uint8_t *buf = load_file_to_buffer("/sdcard/ai_model/person_pet_detect.blai");
IPROAI_Status_e status = iproai_load_model_from_buffer(hdl, buf);
vPortFree(buf);  /* Buffer can be freed after loading */
Load from Flash Partition 
/* Model burned to the "mfg" partition; the model blob starts at partition base + 0x1000 */
uint32_t flash_addr, part_size;
hal_boot2_partition_addr_active("mfg", &flash_addr, &part_size);

uint8_t *buf = pvPortMalloc(model_size);
flash_read(flash_addr + 0x1000, buf, model_size);

iproai_model_hdl_t hdl = iproai_create();
iproai_load_model_from_buffer(hdl, buf);
vPortFree(buf);

Models live in the swappable mfg partition, separate from the firmware. The AI model field of the official flashing tool can update the model independently — no firmware rebuild or re-flash required.

IPROAI Framework

IPROAI is the custom AI inference framework in the IPRO SDK, located at components/ai/. It provides model loading, layer scheduling, NPU acceleration, and post-processing capabilities.

Core API

IPROAI Core API (iproai_core.h) 
/* Create a model instance */
iproai_model_hdl_t iproai_create(void);

/* Load .blai model from memory buffer */
IPROAI_Status_e iproai_load_model_from_buffer(iproai_model_hdl_t hdl, const uint8_t *buffer);

/* Get model input resolution */
IPROAI_Status_e iproai_getInputResolution(iproai_model_hdl_t hdl, uint32_t *width, uint32_t *height);

/* Set source image resolution (for coordinate mapping) */
IPROAI_Status_e iproai_setSourceResolution(iproai_model_hdl_t hdl, uint32_t width, uint32_t height);

/* Get input buffer address (for filling image data) */
uint8_t* iproai_getInputBuffer(iproai_model_hdl_t hdl);

/* Get output buffer address */
uint8_t* iproai_getOutputBuffer(iproai_model_hdl_t hdl, uint32_t *size);

/* Run inference (synchronous, blocks until completion) */
IPROAI_Status_e iproai_startCompute(iproai_model_hdl_t hdl);

/* Get network info (for post-processing) */
struct iproai_net_info_t *iproai_getNetInfo(iproai_model_hdl_t hdl);

/* Set inference result callback */
IPROAI_Status_e iproai_setResultCB(iproai_model_hdl_t hdl, iproai_inference_cb cb);

/* Free model resources */
IPROAI_Status_e iproai_free(iproai_model_hdl_t hdl);

Note: iproai_load_model_from_file(), declared in the header, is currently not implemented (it always returns IPROAI_STATUS_INVALID_INPUT). Read the model into memory via filesystem APIs first, then load it with iproai_load_model_from_buffer() — exactly as in the SD card example above.

Low-Power PIR-Triggered AI Camera Design Pattern

An on-device AI camera design pattern validated on the SDK, integrating a PIR sensor, ISP, NPU inference, and USB UVC output:

  • PIR triggers wakeup → ISP captures a 640×360 ARGB frame → NPU inference → results reported to the host over SPI/USB
  • The YOLOv8 detection model is loaded once at boot and stays resident in PSRAM; it is retained across low-power sleep, so no reload is needed on wakeup
  • A command-mode variant also exists: an external host MCU initiates capture and inference requests over an SPI master/slave protocol — useful when IPRO7AI is embedded as a co-processor in a larger system
The complete turnkey AI camera reference design (including the low-power firmware and production configuration) is not included in Release SDK v1.0.1 — please contact the vendor to obtain it.

NPU Embedding Video Streaming over Thread

An autoencoder running on the NPU compresses a 640×320 RGB frame into a 400-byte embedding (a compression ratio above 1500:1) for UDP streaming over Thread (IEEE 802.15.4); the receiver decodes it back on its own NPU and presents the result as a UVC webcam — enabling video at roughly 2–3 fps over a 250 kbps low-power mesh network. See Matter & Thread: NPU Embedding Video Streaming for the architecture and transport design.

The embedding video streaming reference applications (ipro_embed_*) are not included in Release SDK v1.0.1 — contact the vendor to obtain them.

Development Guide

Adding AI Inference to Your Application

Complete Inference Example 
#include <iproai_core.h>
#include <iproai_def.h>
#include "hal_npu.h"
#include "detect/yolov8_person_pet_detect.h"

static iproai_model_hdl_t g_hdl = NULL;

int my_ai_init(const uint8_t *model_data)
{
    /* Step 1: Enable NPU clock */
    GLB_PER_Clock_UnGate(GLB_AHB_CLOCK_MM);

    /* Step 2: Create model instance */
    g_hdl = iproai_create();
    if (!g_hdl) return -1;

    /* Step 3: Load model */
    IPROAI_Status_e status = iproai_load_model_from_buffer(g_hdl, model_data);
    if (status != IPROAI_STATUS_NO_ERROR) return -2;

    return 0;
}

int my_ai_inference(uint32_t image_addr)
{
    /* Step 4: Set external image address (NPU reads directly) */
    NPU_Img_Ext_Addr_Cfg(image_addr);

    /* Step 5: Run inference */
    IPROAI_Status_e status = iproai_startCompute(g_hdl);
    if (status != IPROAI_STATUS_NO_ERROR) return -1;

    /* Step 6: Post-processing */
    struct iproai_net_info_t *net = iproai_getNetInfo(g_hdl);
    uint8_t *data_buf = iproai_getInputBuffer(g_hdl);

    yolov8_config_t yolo_cfg;
    yolov8_result_t result;

    yolov8_person_pet_init(&yolo_cfg, net);
    yolov8_person_pet_process(&yolo_cfg, net, data_buf, &result);
    yolov8_person_pet_print_results(&result);
    yolov8_person_pet_deinit(&yolo_cfg);

    return result.num_detections;
}

Memory Considerations

  • PSRAM is required: CONFIG_AI_SUPPORT automatically enables CONFIG_USE_PSRAM. Model weights and intermediate results are stored in the 8 MB PSRAM.
  • Model size: Typical YOLOv8 models are 200 KB - 2 MB in .blai format
  • Inference buffers: Inference requires additional intermediate buffers (automatically managed). Ensure sufficient heap space is available.
  • Activation memory budget: The NPU activation buffer is roughly "input pixels × 64 bytes", capped by the 8 MB PSRAM. Estimate the activation footprint before increasing input resolution.
  • Sleep retention: PSRAM retains its contents during low-power sleep, so the model does not need to be reloaded after wakeup.

Optimization Tips

  • Use NPU-accelerated layers: Ensure Conv / Pool / FC layers run on NPU to avoid unnecessary CPU fallback
  • Reduce model size: Use smaller input resolution, fewer channels, or prune unnecessary classes
  • Enable PSRAM sleep retention: Avoid reloading the model after every wakeup cycle
  • Use External Buffer mode: Use NPU_Img_Ext_Addr_Cfg() to let NPU read ISP output directly, reducing memory copies
  • Pre-allocate memory pools: YOLOv8 post-processing uses mem_pool for pre-allocated buffers to avoid dynamic allocation during inference
  • Review profiling output: Per-layer execution time (per-layer profiling) is printed by default; set CONFIG_AI_DEBUG=y to additionally view operator execution details and per-layer instructions

Cloud LLM Agent

⚠ Release SDK Notice: The ai_client component is not included in Release SDK v1.0.1; this section is a capability showcase. Please contact the vendor to obtain this component.

In addition to on-device NPU inference, IPRO SDK ships a full cloud LLM agent framework in components/ai_client/. It wraps multiple providers behind a unified interface, includes a built-in ReAct tool-calling loop, and runs directly on IPRO7AI — letting you combine BLE and sensor data with conversational LLM agents in IoT products. Note that IPRO7AI itself has no Wi-Fi: network connectivity can be provided through the built-in Ethernet (RMII EMAC), or via the IPRO6 companion chip (SDIO Wi-Fi expansion, available separately), with HTTPS traffic sent via lwIP + mbedTLS.

Supported Providers

Each provider is implemented as an ai_provider_t handling request building, HTTP transport, and streaming response parsing. Application code only picks a provider and supplies an API key.

  • Anthropic Claude — ai_provider_claude (ai_claude.h)
  • OpenAI — ai_provider_openai (ai_openai.h)
  • Google Gemini — ai_provider_gemini (ai_gemini.h)
  • MiniMax — ai_provider_minimax (ai_minimax.h)

ReAct Loop & Tool Calls

ai_agent_process() drives the full reason-act-observe loop: model returns a tool_call → SDK invokes ai_tool_dispatch_fn → result is appended to history → model is re-invoked, until AI_CLIENT_MAX_TOOL_DEPTH (default 5) is reached or a final text reply is produced. Tool schemas are supplied via three format fields (Anthropic tools_json / OpenAI tools_json_openai / Gemini tools_json_gemini); MiniMax reuses the OpenAI format:

Minimal integration 
#include "ai_agent.h"
#include "ai_claude.h"

static int my_tool_dispatch(const char *name, const char *input,
                            char *output, uint32_t size)
{
    if (strcmp(name, "read_temperature") == 0) {
        snprintf(output, size, "{\"temp_c\":%.1f}", sensor_read_temp());
        return 0;
    }
    return -1;
}

void ask_ai(const char *user_text)
{
    ai_agent_ctx_t ctx = {
        .provider      = &ai_provider_claude,
        .api_key       = CONFIG_CLAUDE_API_KEY,
        .model         = "claude-sonnet-4-5",
        .system_prompt = "You are an embedded assistant.",
        .user_text     = user_text,
        .tools_json    = TOOLS_SCHEMA_ANTHROPIC,
        .tools_count   = 1,
        .tool_dispatch = my_tool_dispatch,
    };

    char reply[1024];
    if (ai_agent_process(&ctx, reply, sizeof(reply)) == 0) {
        printf("AI: %s\n", reply);
    }
}

A streaming variant, ai_agent_process_streaming(), is also available: the reply is delivered sentence-by-sentence through a callback, and the on_preflight callback exposes intermediate text before tool execution. It automatically falls back to the synchronous ai_agent_process() if the provider lacks streaming support.
