Networking

IPRO7 is the main application SoC in the system, handling application logic, NPU inference, and BLE connectivity. It does not include a Wi-Fi radio. The IPRO SDK integrates the lwIP TCP/IP stack and the mbedTLS cryptographic library, providing two paths to network connectivity:

  • Ethernet (EMAC) — IPRO7 features a built-in Ethernet MAC controller that pairs with lwIP for wired networking. Release SDK v1.0.1 includes full source code and reference applications.
  • Wi-Fi (via IPRO6 companion chip) — Wi-Fi 6 (802.11ax) is provided by an IPRO6-series connectivity companion chip, bridged to IPRO7's lwIP stack over an SDIO interface. The complete solution is available separately; please contact the vendor.

The SDK also provides LTE modem PPP dial-up (components/network/lte_modem/, UART AT interface) as a WAN option besides EMAC.

Network Configuration

Enable networking features in your application's .config file:

.config - Network Configuration 
# Enable lwIP TCP/IP stack
CONFIG_COMPONENTS_LWIP_ENABLE=y
CONFIG_COMPONENTS_LWIP_APP_ENABLE=y

# Enable ping command (network diagnostics)
CONFIG_PING=y

# Enable Ethernet (EMAC)
CONFIG_ETHERNET=y

# Enable mbedTLS encryption support
CONFIG_COMPONENTS_MBEDTLS_ENABLE=y
Tip: The configuration above matches apps/platform/ipro7_demo in the Release SDK — you can use that project's .config as a starting point.

lwIP Integration

The IPRO SDK integrates lwIP (Lightweight IP) as its TCP/IP stack, providing a standard BSD Socket API that allows developers to use familiar socket programming interfaces.

Socket API Example

TCP Client Connection 
#include <lwip/sockets.h>
#include <lwip/netdb.h>

int tcp_client_example(const char *host, uint16_t port)
{
    struct sockaddr_in server_addr;
    int sock;

    /* Create TCP socket */
    sock = socket(AF_INET, SOCK_STREAM, 0);
    if (sock < 0) {
        printf("Socket creation failed\r\n");
        return -1;
    }

    /* DNS resolve hostname */
    struct hostent *hp = gethostbyname(host);
    if (!hp) {
        printf("DNS resolution failed: %s\r\n", host);
        close(sock);
        return -1;
    }

    /* Connect to server */
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(port);
    memcpy(&server_addr.sin_addr, hp->h_addr, hp->h_length);

    if (connect(sock, (struct sockaddr *)&server_addr,
                sizeof(server_addr)) < 0) {
        printf("Connection failed\r\n");
        close(sock);
        return -1;
    }

    /* Send data */
    const char *msg = "Hello from IPRO7!";
    send(sock, msg, strlen(msg), 0);

    /* Receive response */
    char buf[256];
    int len = recv(sock, buf, sizeof(buf) - 1, 0);
    if (len > 0) {
        buf[len] = '\0';
        printf("Received: %s\r\n", buf);
    }

    close(sock);
    return 0;
}
UDP Send Example 
#include <lwip/sockets.h>

int udp_send_example(const char *dest_ip, uint16_t port)
{
    int sock = socket(AF_INET, SOCK_DGRAM, 0);
    if (sock < 0) return -1;

    struct sockaddr_in dest;
    memset(&dest, 0, sizeof(dest));
    dest.sin_family = AF_INET;
    dest.sin_port = htons(port);
    inet_aton(dest_ip, &dest.sin_addr);

    const char *data = "UDP packet from IPRO7";
    sendto(sock, data, strlen(data), 0,
           (struct sockaddr *)&dest, sizeof(dest));

    close(sock);
    return 0;
}

Ethernet (EMAC)

The IPRO7 features a built-in EMAC (Ethernet MAC) controller. Paired with an external Ethernet PHY, it provides wired networking suitable for gateways, industrial controllers, and other applications requiring a wired connection. This is the recommended primary networking path in Release SDK v1.0.1.

EMAC Initialization with lwIP 
#include <hal_emac.h>
#include <hal_ethernetif.h>
#include <lwip/tcpip.h>

static struct netif emac_netif;

static void emac_netif_setup(void *arg)
{
    struct netif *netif = (struct netif *)arg;
    ip4_addr_t ipaddr, netmask, gw;

    /* Use DHCP (set addresses to zero) */
    ip_addr_set_zero(&ipaddr);
    ip_addr_set_zero(&netmask);
    ip_addr_set_zero(&gw);

    /* Register network interface */
    netif_add(netif, &ipaddr, &netmask, &gw,
              NULL, ethernetif_init, tcpip_input);
    netif_set_default(netif);
    ethernet_link_status_updated(netif);

    /* Start DHCP client */
    netifapi_dhcp_start(netif);
}

void emac_init(void)
{
    memset(&emac_netif, 0, sizeof(emac_netif));
    tcpip_init(emac_netif_setup, &emac_netif);
}

To enable Ethernet, set CONFIG_ETHERNET=y in your .config. The driver is located at bsp/drivers/ipro7_soc/std_drv/src/drv_emac.c. The reference application apps/platform/ipro7_demo runs the emac_lwip command automatically at boot to perform the flow above.

Security (mbedTLS)

The IPRO SDK integrates the mbedTLS 2.28 LTS library, providing TLS/DTLS secure communication and various cryptographic algorithms.

Features

  • TLS 1.2 - Secure TCP connection encryption
  • DTLS 1.2 - Secure UDP communication (for CoAP and similar protocols)
  • X.509 Certificates - Server and client certificate verification
  • Symmetric Encryption - AES-128/192/256, ChaCha20-Poly1305
  • Hash Functions - SHA-256, SHA-384, SHA-512
  • Asymmetric Encryption - RSA, ECDSA, ECDH (secp256r1, secp384r1)
  • Random Number Generation - CTR-DRBG
  • Hardware Acceleration - Hardware-accelerated bignum operations (CONFIG_MBEDTLS_BIGNUM_USE_HW=y)
TLS Client Connection Example 
#include "mbedtls/net_sockets.h"
#include "mbedtls/ssl.h"
#include "mbedtls/entropy.h"
#include "mbedtls/ctr_drbg.h"

int tls_connect_example(const char *hostname, const char *port)
{
    mbedtls_net_context server_fd;
    mbedtls_ssl_context ssl;
    mbedtls_ssl_config conf;
    mbedtls_entropy_context entropy;
    mbedtls_ctr_drbg_context ctr_drbg;

    /* Initialize */
    mbedtls_net_init(&server_fd);
    mbedtls_ssl_init(&ssl);
    mbedtls_ssl_config_init(&conf);
    mbedtls_entropy_init(&entropy);
    mbedtls_ctr_drbg_init(&ctr_drbg);

    /* Seed the random number generator */
    mbedtls_ctr_drbg_seed(&ctr_drbg, mbedtls_entropy_func,
                          &entropy, NULL, 0);

    /* TCP connection */
    mbedtls_net_connect(&server_fd, hostname, port,
                        MBEDTLS_NET_PROTO_TCP);

    /* TLS configuration */
    mbedtls_ssl_config_defaults(&conf, MBEDTLS_SSL_IS_CLIENT,
                                MBEDTLS_SSL_TRANSPORT_STREAM,
                                MBEDTLS_SSL_PRESET_DEFAULT);
    mbedtls_ssl_conf_rng(&conf, mbedtls_ctr_drbg_random, &ctr_drbg);
    mbedtls_ssl_setup(&ssl, &conf);
    mbedtls_ssl_set_hostname(&ssl, hostname);

    /* Bind socket */
    mbedtls_ssl_set_bio(&ssl, &server_fd,
                        mbedtls_net_send, mbedtls_net_recv, NULL);

    /* Perform TLS handshake */
    int ret = mbedtls_ssl_handshake(&ssl);
    if (ret != 0) {
        printf("TLS handshake failed: -0x%04X\r\n", -ret);
        goto cleanup;
    }

    /* Send data over TLS */
    const char *request = "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n";
    mbedtls_ssl_write(&ssl, (const unsigned char *)request,
                      strlen(request));

cleanup:
    mbedtls_ssl_close_notify(&ssl);
    mbedtls_net_free(&server_fd);
    mbedtls_ssl_free(&ssl);
    mbedtls_ssl_config_free(&conf);
    mbedtls_entropy_free(&entropy);
    mbedtls_ctr_drbg_free(&ctr_drbg);
    return ret;
}

mbedTLS Configuration Files

mbedTLS features can be customized through configuration header files. The SDK provides sample configurations:

  • components/crypto/mbedtls/mbedtls_sample_config.h - General-purpose sample configuration
  • components/crypto/mbedtls/kvs_webrtc_mbedtls_config.h - WebRTC-specific configuration
  • Applications can provide a custom mbedtls_config.h to enable/disable specific algorithms

HTTP Client

⚠ Release SDK Notice: The high-level HTTP/HTTPS client component components/http_client/ is not included in Release SDK v1.0.1. The content below is for architectural reference only — please contact the vendor if you need this component.

components/http_client/ is a high-level HTTP/HTTPS client component built on top of lwIP and mbedTLS, eliminating the need to manage sockets and TLS handshakes manually:

  • Connection pool - Reuses TCP/TLS connections, reducing repeated handshake costs
  • TLS support - HTTPS requests (uses mbedTLS internally)
  • Multipart encoding - File/form upload support
  • Keep-alive and timeout management - Tunable

In Release SDK v1.0.1, the reference application apps/network/ipro_voice_assistant does not use this component. Instead, it performs TLS/HTTPS communication with its own in-app HTTP/TLS implementation (src/net/iva_http_client.c, src/net/iva_tls.c, also built on lwIP and mbedTLS), which can serve as a reference for implementing your own HTTPS client.

Wi-Fi (via IPRO6 Companion Chip)

⚠ Release SDK Notice: The SDIO Wi-Fi bridge solution (including the IPRO7-side sdiowifi bridge component, the IPRO6-side firmware, and the host-side reference design) is not included in Release SDK v1.0.1. The content below is for architectural reference only — please contact the vendor for the complete solution.

The IPRO7 itself does not include a Wi-Fi radio. Products requiring Wi-Fi connectivity use a dual-chip architecture: IPRO7 as the main application SoC, paired with an IPRO6-series connectivity companion chip that provides Wi-Fi 6 (802.11ax) connectivity.

Dual-Chip Wi-Fi Architecture
IPRO7 (Host)
App / NPU / BLE
lwIP netif ↔ SDH
(data plane into lwIP)
SDIO 4-bit
IPRO6 (Wi-Fi Companion)
Wi-Fi 6 (802.11ax)
SDIO network bridge FW
(STA assoc / auth)
  • Physical interface - IPRO7 acts as the SDIO host using its built-in SDH (SDIO Host) controller; IPRO6 acts as the SDIO slave.
  • Data plane - Wi-Fi packets are bridged over SDIO into a lwIP network interface on the IPRO7 side, so applications use the same Socket API as EMAC with no changes.
  • Control plane - Wi-Fi connection management (scanning, authentication, roaming) is handled by the IPRO6-side firmware.
  • SDK component - The components/network/sdiowifi/ SDIO network bridge component is not included in Release SDK v1.0.1; the complete solution (bridge component, IPRO6-side firmware, and host-side reference design) is available from the vendor.

To evaluate the dual-chip Wi-Fi solution (hardware reference design, IPRO6 firmware, production support), please contact the vendor.
