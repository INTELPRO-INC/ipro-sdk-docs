架構概覽

IPRO SDK 採用清晰的分層架構設計，提供高度模組化與可移植性，讓開發者能夠快速建構穩定的嵌入式應用。本頁詳細介紹 SDK 的系統架構、晶片規格、建構流程與元件組成。

系統總覽

SDK 的整體架構由五個主要層次組成，從上至下分別為應用層、元件層、RTOS 層、BSP 層與硬體層：

Applications (apps/)
bluetooth/ble/ bluetooth/le_audio/ multimedia/ network/ platform/ipro7_demo
Components (components/)
BLE 5.4 LE Audio lwIP mbedTLS CherryUSB Audio AI EVFS LittleFS FatFS Shell LC3
RTOS (FreeRTOS)
FreeRTOS FreeRTOS POSIX OSAL
BSP (bsp/)
HAL Drivers Board Config Linker Scripts Startup
Hardware (IPRO7)
RISC-V RV32IMAFC BLE Radio NPU

每一層都有明確的職責邊界：

  • 應用層：自包含的專案，每個專案擁有獨立的 .config 和 CMakeLists.txt
  • 元件層：可重用的中間件，透過 Kconfig 選項啟用或停用
  • RTOS 層：提供任務排程、同步原語與計時器服務
  • BSP 層：硬體抽象層與驅動程式，屏蔽不同晶片的差異
  • 硬體層：IPRO 系列 SoC 平台

晶片變體

IPRO SDK 支援多款晶片，涵蓋高效能物聯網到超低功耗場景：

晶片 核心架構 主頻 Flash RAM 特殊功能
IPRO7 RISC-V RV32IMAFC 192 MHz 1 MB（on-chip，可選外掛 SPI flash 擴充至 2/4/8 MB） 8 MB PSRAM + 256 KB OCRAM BLE 5.4, LE Audio, ISP, 0.1 TOPS NPU
IPRO6 (legacy) RISC-V - - - 前代 SoC，可作為 IPRO7 的 Wi-Fi 連網 companion 晶片（BSP 中保留部分參考，本版不含 IPRO6 應用）
提示：IPRO7 為目前主力開發平台，SDK 中大部分範例與文件皆以 IPRO7 為主。透過 Kconfig 中的 CONFIG_IPRO7=y 或 CONFIG_IPRO6=y 選擇目標晶片。外掛 flash 容量以 CONFIG_IPRO7_FLASH_2M/4M/8M 選擇。

雙晶片架構

IPRO7 不內建 Wi-Fi。需要 Wi-Fi 連網的產品採用雙晶片架構：IPRO7 作為主控 SoC，負責應用邏輯、AI/NPU 推論、BLE、音訊與周邊控制；Wi-Fi 連網由 IPRO6 companion 晶片透過 SDIO 介面提供。

雙晶片連網架構 
┌──────────────────────────────┐          ┌──────────────────────────┐
│        IPRO7（主控 SoC）      │          │  IPRO6（連網 companion）  │
│  應用邏輯 / AI・NPU / BLE     │   SDIO   │                          │
│  音訊 / ISP / 周邊控制        │◄────────►│         Wi-Fi            │
└──────────────────────────────┘          └──────────────────────────┘
提示：IPRO7 本身內建 EMAC 乙太網路 MAC，不需 companion 晶片即可透過有線乙太網路搭配 lwIP 連網（如 ipro_voice_assistant 參考應用）。Wi-Fi 雙晶片參考設計請聯絡原廠取得。

配置系統（Kconfig）

SDK 使用 Linux kernel 風格的 Kconfig 系統管理專案配置。每個應用擁有自己的 .config 檔案，建構時自動生成 build/include/generated/autoconf.h 供 C 程式碼使用。

配置層次

  1. 選項定義：根 Kconfig 與各元件的 Kconfig - 定義所有可用選項
  2. 專案預設值：apps/<project>/defconfig - 專案預設配置，由 make defconfig 載入
  3. 實際建構配置：apps/<project>/.config - 應用專屬配置（最高優先級）
defconfig 工作流程 
cd apps/bluetooth/ble/ipro_ble_remote

# 由專案 defconfig 生成 .config
make defconfig

# 修改 .config 後，將最小化配置存回 defconfig
make savedefconfig

關鍵配置選項

.config 範例 
# SoC 選擇
CONFIG_IPRO7=y
CONFIG_CPU_ID="intelpro_ipro7"

# RTOS 選擇
CONFIG_FREERTOS_SUPPORT=y

# 無線功能
CONFIG_BLUETOOTH_LE_ENABLE=y

# 元件啟用
CONFIG_LWIP=y
CONFIG_MBEDTLS=y

# 測試自動執行
CONFIG_TEST_AUTO_RUN=y

配置與程式碼的關係

build/include/generated/autoconf.h（自動生成） 
/* 由 Kconfig 自動生成，請勿手動編輯 */
#define CONFIG_IPRO7 1
#define CONFIG_CPU_ID "intelpro_ipro7"
#define CONFIG_FREERTOS_SUPPORT 1
#define CONFIG_BLUETOOTH_LE_ENABLE 1
#define CONFIG_LWIP 1
提示：CONFIG_CPU_ID 必須在 .config 中正確設定，cmake/toolchain.cmake 才能偵測到正確的架構旗標。工具鏈偵測邏輯會自動區分 vendor GCC（含 _xxldsp DSP 擴充指令）與標準 GCC，並據此調整編譯旗標。

應用程式結構

每個應用程式都是 apps/ 下的獨立目錄，包含建構與配置所需的所有檔案：

典型應用程式結構 
apps/<category>/<project>/
├── .config              # Kconfig 配置（可由 make defconfig 自 defconfig 生成）
├── defconfig            # 專案預設配置
├── Kconfig              # 專案專屬 Kconfig 選項
├── Makefile             # Make 建構入口
├── CMakeLists.txt       # CMake 建構定義
├── main.c               # 應用程式入口點
├── src/                 # 原始碼目錄
├── include/             # 標頭檔目錄
└── build/               # 建構輸出（自動生成）
    ├── include/
    │   └── generated/
    │       └── autoconf.h   # 由 .config 生成的 C 標頭
    └── build_out/
        └── <project>_IPRO7.bin  # 最終二進位檔

最小 main.c 骨架

所有 FreeRTOS 應用共用 components/os/freertos/freertos_app_hooks.{c,h} 元件，heap、FreeRTOS hooks（idle/tick/stack-overflow/malloc-failed）與 assert 皆以 weak symbol 形式提供預設實作，應用程式的 main.c 不需要重複這些樣板程式碼：

最小 main.c 
#include "freertos_app_hooks.h"
#include <FreeRTOS.h>
#include <task.h>

static void app_task(void *arg)
{
    /* 應用程式主邏輯 */
    for (;;) {
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

int main(void)
{
    ipro_platform_init();   /* heap + boot2 + log + shell 初始化 */
    xTaskCreate(app_task, "app", 1024, NULL, 5, NULL);
    vTaskStartScheduler();
    while (1) {}
}
提示：若需客製某個 hook（例如 vApplicationIdleHook），直接在應用程式原始碼中定義同名的非 weak 版本即可，連結器會自動採用，不需修改共用元件。

控制器變體（linkN 命名）

控制器使用統一連線池設計，以 linkN 命名（取代舊的 mXsY 命名）：

變體 BLE 版本 說明

預建函式庫

BLE 控制器以預建 .a 靜態函式庫形式提供，共包含 13 種變體，位於各自的 btblecontroller_ipro7_<variant>/ 目錄中。本發行版不包含控制器原始碼與建構腳本，CONFIG_BLE_FORCE_SOURCE_BUILD 在本發行版中不支援；應用程式透過 Kconfig 選擇所需的控制器變體即可。

提示：預建函式庫檔案命名為 libbtblecontroller_ipro7_<variant>.a，建構系統會根據 .config 中的設定自動連結對應的變體。

LE Audio 應用框架

LE Audio 應用採用三層框架設計：

  • Mediator（協調器）：統籌管理所有元件與狀態機
  • Applets（可重用元件）：封裝 BLE Profile 功能（GAF, BAP, VCP, MCP, CAP）
  • Intermediaries（協定橋接）：連接不同協定層的資料流

BSP 與驅動

Board Support Package 位於 bsp/ 目錄，提供硬體抽象與週邊驅動：

  • bsp/hal/ - 硬體抽象層 API
  • bsp/hal/lp_framework/ - 低功耗框架（PDS/HBN 睡眠模式管理，以預建函式庫形式提供）
  • bsp/drivers/ - 週邊驅動程式
  • bsp/board/ - 板級配置（腳位映射、時脈設定）
  • bsp/common/ - 啟動程式碼、連結腳本、共用程式碼
