Matter & Thread 開發指南

IPRO SDK 支援 Matter 1.5 統一智慧家庭協定以及 Thread 1.4 低功耗網狀網路，讓您的裝置能夠與 Apple Home、Google Home、Amazon Alexa 等生態系統無縫互通。

概述

Matter 是由 Connectivity Standards Alliance (CSA) 推動的統一智慧家庭標準，旨在解決物聯網裝置之間的互通性問題。IPRO SDK 提供完整的 Matter 與 Thread 支援：

Matter 1.5

  • CSA 統一智慧家庭標準
  • 多生態系統互通
  • 安全的裝置配網與控制
  • Data Model / Interaction Model

Thread 1.4

  • IEEE 802.15.4 低功耗網狀網路
  • 自我修復拓撲
  • IPv6 原生支援
  • FTD / MTD / RCP 裝置類型

多傳輸層

  • Matter over Thread（低功耗）
  • Matter over Wi-Fi（需 IPRO6 companion 晶片）
  • BLE 配網通道
  • Border Router 橋接

Matter 架構

Matter 協定建構在 IP 網路之上，透過 Thread 或 Wi-Fi 作為傳輸層，並使用 BLE 進行裝置配網（Commissioning）。IPRO7 的 Matter 參考設計採用 Matter over Thread；Wi-Fi 傳輸需搭配 IPRO6 companion 晶片（SDIO 介面）：

Matter Data Model

Matter 使用分層式資料模型來描述裝置功能：

概念 說明 範例
Node 一個可定址的 Matter 裝置 一個智慧燈泡
Endpoint Node 上的功能單元 Endpoint 0（Root）、Endpoint 1（Light）
Cluster 一組相關功能的集合 OnOff、LevelControl、ColorControl
Attribute 可讀寫的狀態值 OnOff.onOff、LevelControl.currentLevel
Command 可執行的操作 OnOff.Toggle()、LevelControl.MoveToLevel()

Interaction Model

Matter 裝置之間透過以下交互模式通訊：

  • Read — 讀取屬性值（例如：查詢燈泡是否開啟）
  • Write — 寫入屬性值（例如：設定亮度等級）
  • Invoke — 呼叫命令（例如：Toggle 開關）
  • Subscribe — 訂閱屬性變化通知（例如：監聽溫度變化）

配網流程（Commissioning）

Matter 使用 BLE 作為配網通道，流程如下：

  1. 裝置啟動後進入配網模式，開始 BLE 廣播
  2. 手機 App 掃描 QR Code 或輸入配對碼
  3. 通過 PASE（Passcode-Authenticated Session Establishment）建立安全連線
  4. App 將 Thread/Wi-Fi 網路憑證傳送至裝置
  5. 裝置加入 IP 網路，建立 CASE（Certificate-Authenticated Session Establishment）
  6. 裝置被加入 Matter Fabric，可以被控制

Matter over Thread

Thread 是為低功耗物聯網裝置設計的網狀網路協定。Matter over Thread 適合電池供電的感測器、開關和燈具等裝置。

Thread 使用 IEEE 802.15.4 無線電，與 Wi-Fi/BLE 使用不同的調變方式（同屬 2.4 GHz ISM 頻段）。IPRO7 同時支援 802.15.4 與 BLE 雙無線電；Wi-Fi 連線需搭配 IPRO6 companion 晶片（SDIO 介面）。

裝置角色

角色 類型 說明
Leader FTD 管理路由表與位址分配，每個分區只有一個
Router FTD 轉發封包、維護路由表、支援子裝置
End Device MTD 僅與父路由器通訊，不轉發封包
Sleepy End Device MTD 大部分時間休眠，適合電池裝置
Border Router FTD 橋接 Thread 與 Wi-Fi/Ethernet 網路

典型應用場景

  • 智慧燈泡與燈具（Router / End Device）
  • 門窗感測器（Sleepy End Device）
  • 溫濕度感測器（Sleepy End Device）
  • 智慧開關與插座（Router）
  • 動作感測器（Sleepy End Device）

Matter over Wi-Fi

Matter over Wi-Fi 透過 Wi-Fi 提供直接 IP 連線，適合需要較高頻寬的裝置，無需 Border Router 即可連接家庭網路。本節為協定背景知識，協助您在 Thread 與 Wi-Fi 之間做產品定位的取捨。

注意：IPRO7 本身不具備 Wi-Fi 無線電，IPRO SDK 的 Matter 參考設計為 Matter over Thread。如需 Matter over Wi-Fi 產品形態，需透過 IPRO6 companion 晶片（SDIO 介面）提供 Wi-Fi 連線，請聯絡原廠取得相關方案。

適用場景

  • 智慧攝影機（需要高頻寬影像傳輸）
  • 智慧顯示器
  • 智慧音箱
  • 家電設備（冰箱、洗衣機等）
  • 需要快速回應的控制裝置

Matter over Thread vs Wi-Fi 比較

OpenThread

IPRO SDK 整合了 Google 開源的 OpenThread 實作，提供完整的 Thread 協定棧。原始碼位於 components/wireless/thread/。

OpenThread 元件結構 
components/wireless/thread/
├── CMakeLists.txt              # 建構配置
├── Kconfig                     # 裝置類型選擇（FTD/MTD/RCP）
├── openthread/                 # OpenThread 開源協定棧
│   ├── src/                    # 核心實作
│   │   ├── core/               #   Thread 協定核心
│   │   └── cli/                #   CLI 命令介面
│   ├── include/                # 公開 API 標頭
│   └── examples/               # 範例與平台移植
└── openthread_port/            # IPRO7 平台移植層
    └── Kconfig                 #   平台特定配置選項

裝置類型

透過 Kconfig 選擇 OpenThread 裝置類型：

裝置類型配置 
# Full Thread Device — 可路由、可成為 Leader/Router
CONFIG_OPENTHREAD_FTD=y

# Minimal Thread Device — 僅為 End Device，省電省記憶體
CONFIG_OPENTHREAD_MTD=y

# Radio Co-processor — 802.15.4 射頻由外部主機控制
CONFIG_OPENTHREAD_RADIO=y

OpenThread CLI

啟用 CONFIG_OPENTHREAD_CLI=y 後，可透過序列埠使用 ot 命令進行開發與除錯：

常用 OpenThread CLI 命令 
# 建立新的 Thread 網路
ot dataset init new
ot dataset networkname MyThreadNet
ot dataset channel 15
ot dataset panid 0x1234
ot dataset commit active
ot ifconfig up
ot thread start

# 查詢狀態
ot state                  # 顯示角色：disabled/detached/child/router/leader
ot ipaddr                 # 顯示 IPv6 位址
ot neighbor table         # 顯示鄰居表
ot router table           # 顯示路由表（僅 FTD）

# 網路診斷
ot ping <ipv6_address>    # Ping 另一個裝置
ot child table            # 子裝置列表
ot parent                 # 父裝置資訊

Commissioner 與 Joiner

Thread 使用 Commissioner/Joiner 機制來安全地將新裝置加入網路：

Commissioner 操作（已在網路中的裝置） 
# 啟動 Commissioner
ot commissioner start

# 允許新裝置加入（* 表示接受任何裝置，J01NME 是預共享金鑰）
ot commissioner joiner add * J01NME

# 查看 Commissioner 狀態
ot commissioner state
Joiner 操作（要加入的新裝置） 
# 使用預共享金鑰加入
ot joiner start J01NME

# 等待加入成功訊息後
ot ifconfig up
ot thread start

參考應用

IPRO SDK 提供多個 Matter 與 Thread 參考應用程式：

Matter Lighting App（可用）

實作 Matter On/Off Light 裝置類型，包含開關與亮度控制 Cluster，以 Matter over Thread（Thread MTD）運作，可完成配網並由生態系統控制。

建構 Matter Lighting App 
# 建構
make -C apps/matter/lighting-app/ipro7

# 原始碼位置
apps/matter/lighting-app/ipro7/main.c       # 應用程式進入點
apps/matter/lighting-app/ipro7/.config      # 配置檔

主要功能：

  • OnOff Cluster — 開關控制
  • LevelControl Cluster — 亮度調節（0-254）
  • Matter 配網（BLE Commissioning），開機後於序列埠列印配網 QR Code 與配對碼
  • Thread MTD 連網（Matter over Thread）
  • Vendor ID: 0xFFF1 / Product ID: 0x8005 / Device Type: 256（On/Off Light）
Matter 應用採用 prebuilt libCHIP 整合模式：CHIP 函式庫（ipro7-<variant>.a）由 GN/Ninja 另行建置，SDK 的 CMake 透過 MATTER_CHIP_ROOT / MATTER_OUT_DIR 匯入 prebuilt .a 與產生的標頭，並非純 CMake in-tree 建構。詳見 SDK 內 docs/matter-ipro7-integration.md。

Matter Contact Sensor App（可用）

實作 Matter Contact Sensor 裝置類型（門窗感測器），以 Thread MTD 低功耗模式運作，由 GPIO 輸入觸發開合狀態回報。

# 原始碼位置

主要功能：

  • BooleanState Cluster — 開合狀態回報（GPIO 輸入觸發）

Matter All-Clusters App（開發中）

包含多種標準 Matter Cluster 的測試應用程式，目前仍在開發中，尚未提供可建構的 IPRO7 移植版本。如需 Matter 認證測試的相關進度與支援，請聯絡原廠。

Thread FTD CLI

Full Thread Device 參考應用，提供完整的 OpenThread CLI 介面，適合 Thread 網路開發與測試。

建構 Thread FTD CLI 
# 使用 Make
make -C apps/networking/thread/ipro_thread_ftd_cli

# 使用建構腳本

# 建構產出

主要功能：

  • Full Thread Device（Router / Leader）
  • 完整 OpenThread CLI 命令

NPU 嵌入式視訊串流 over Thread（能力展示）

⚠ Release SDK 注意事項：本節為能力展示。NPU 嵌入式視訊串流參考應用（ipro_embed_*）未包含於 Release SDK v1.0.1，如需評估請聯絡原廠取得。

IEEE 802.15.4 的實體層速率僅 250 kbps，傳統視訊編碼（MJPEG、H.264）即使在最低位元率下也無法於 Thread 網路串流。IPRO7-AI 改以 NPU 執行 autoencoder 神經網路，將整張 640×320 RGB 影格直接壓縮成 400 bytes 的 embedding（壓縮比超過 1500:1），接收端再以 NPU 解碼還原影像——讓視訊串流在標準 Thread mesh 上成為可能。

端到端管線
傳送端（IPRO7-AI）
Camera
DVP, 640×320 RGB
NPU Encoder
encoder .blai → 400 B embedding / frame
UDP unicast
over Thread
Thread UDP
接收端（IPRO7-AI）
NPU Decoder
decoder .blai → 還原 640×320 RGB 影格
USB UVC webcam
輸出至 PC

主要設計：

  • NPU 編解碼 — 編碼器與解碼器模型（.blai）部署於 mfg flash 分割區（與其他 AI 模型相同的部署流程），開機時自 XIP 載入
  • 單播傳輸 + 輕量探索 — 接收端以 link-local beacon（ff02::1，每秒 1 封包）廣播自身位址，傳送端學得位址後全程 UDP 單播；視訊流量不經 mesh 多播洪泛，避免 CSMA 通道競爭與訊息緩衝耗盡
  • 實測速率 — 標準 Thread 鏈路約 2–3 fps（受 802.15.4 鏈路頻寬限制，非 NPU 運算瓶頸）

參考應用（位於 apps/networking/thread/，未含於 release）：

應用角色
ipro_embed_sender攝影機擷取 + NPU 編碼 + Thread UDP 傳送
ipro_embed_rx接收 embedding 並由序列埠輸出（供主機端解碼驗證）
ipro_embed_uvc_rx接收 + NPU 解碼 + USB UVC webcam 輸出至 PC

適用場景：電池供電或佈線困難環境的低頻寬視覺監控、Thread mesh 內的影像感測節點、事件觸發的遠端畫面確認。

配置說明

Matter 配置

在應用程式的 .config 中設定 Matter 相關選項（以 lighting-app ipro7 為例）：

Matter 配置選項 
# 啟用 Matter（IPRO7 port）
CONFIG_MATTER_ENABLE=y
CONFIG_MATTER_DEMO_CHIP_IPRO7=y
CONFIG_MATTER_APP_VARIANT="lighting-app"

# 裝置資訊
CONFIG_MATTER_VENDOR_ID=0xFFF1          # CSA 測試用 Vendor ID
CONFIG_MATTER_PRODUCT_ID=0x8005         # 產品 ID
CONFIG_MATTER_DEVICE_TYPE=256           # 裝置類型（256 = On/Off Light）

# 必要依賴
CONFIG_FREERTOS_SUPPORT=y               # FreeRTOS
CONFIG_COMPONENTS_MBEDTLS_ENABLE=y      # 安全層
CONFIG_LWIP_ENABLE=y                    # IP 網路棧
CONFIG_LWIP_IPV6=y                      # IPv6（Thread 必要）

Thread / OpenThread 配置

OpenThread 配置選項 
# 啟用 Thread
CONFIG_THREAD_ENABLE=y
CONFIG_OPENTHREAD_ENABLE=y
CONFIG_IEEE802154_ENABLE=y

# 裝置類型（擇一）
CONFIG_OPENTHREAD_FTD=y                 # Full Thread Device
# CONFIG_OPENTHREAD_MTD=y              # Minimal Thread Device

# CLI 介面
CONFIG_OPENTHREAD_CLI=y

# 802.15.4 射頻
CONFIG_IEEE802154_DEFAULT_TXPOWER=20    # TX 功率（dBm）

# 功能啟用（依需求選擇）
CONFIG_OPENTHREAD_COMMISSIONER=y        # Commissioner 角色
CONFIG_OPENTHREAD_JOINER=y              # Joiner 角色
CONFIG_OPENTHREAD_DHCP6_CLIENT=y        # DHCPv6 Client
CONFIG_OPENTHREAD_DHCP6_SERVER=y        # DHCPv6 Server
CONFIG_OPENTHREAD_DNS_CLIENT=y          # DNS Client
CONFIG_OPENTHREAD_BORDER_ROUTER=y       # Border Router 功能

# 記憶體配置
CONFIG_OPENTHREAD_NUM_MESSAGE_BUFFERS=44
CONFIG_OPENTHREAD_MESSAGE_BUFFER_SIZE=128
CONFIG_OPENTHREAD_MLE_MAX_CHILDREN=16

# 日誌等級（0=NONE, 1=CRIT, 2=WARN, 3=NOTE, 4=INFO, 5=DEBG）
CONFIG_OPENTHREAD_LOG_LEVEL=3
停用未使用的功能可顯著節省記憶體：Commissioner/Joiner 約需 150KB（DTLS/SSL），Border Router 約需 30KB，ECDSA 約需 15KB，SRP Client 約需 20KB。

開發流程

1. 選擇參考應用

根據目標裝置類型選擇合適的參考應用作為起點：

  • 照明裝置 — 以 apps/matter/lighting-app/ipro7 為基礎
  • 感測器裝置 — 以 apps/matter/contact-sensor/ipro7 為基礎
  • Thread 網路開發 — 以 apps/networking/thread/ipro_thread_ftd_cli 為基礎

2. 建構韌體

建構步驟 
# 建構 Matter Lighting App
make -C apps/matter/lighting-app/ipro7

# 建構 Thread FTD CLI
make -C apps/networking/thread/ipro_thread_ftd_cli

# 清除建構
make -C apps/networking/thread/ipro_thread_ftd_cli clean

3. 燒錄與測試

燒錄韌體 
# 燒錄到開發板（序列埠名稱依實際裝置而定）
tools/ipro_iot_tool_lite/ipro_iot_tool_lite \
    --chipname ipro7 \
    --port /dev/cu.usbserial-XXXX \
    --firmware apps/networking/thread/ipro_thread_ftd_cli/build/build_out/ipro_thread_ftd_cli_IPRO7.bin \
    --baudrate 921600 \
    --flash-pin 0x02

# 連接序列埠監控
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX

4. Matter 配網測試

  1. 使用 Google Home App、Apple Home App 或 chip-tool 進行配網
  2. 掃描裝置 QR Code 或手動輸入配對碼
  3. 裝置加入 Matter Fabric 後即可控制
使用 chip-tool 測試（開發用） 
# 配網（Commissioning）
chip-tool pairing ble-thread <node-id> <thread-dataset> <setup-pin-code> <discriminator>

# 控制 On/Off
chip-tool onoff toggle <node-id> 1

# 讀取屬性
chip-tool onoff read on-off <node-id> 1

# 設定亮度
chip-tool levelcontrol move-to-level <level> 0 0 0 <node-id> 1
