Windows 安裝與更新

從完整安裝包建立開發環境，或獨立更新 SDK 與 VS Code Extension。

Online Installer 3.4.0

使用 IPRO-SDK-Online-Setup-3.4.0.exe從公開元件清單安裝，不需 GitHub 登入。提供 Full、SDK、toolchain、build tools、IntelProCube、OpenOCD 與 Extension 七種模式。

選擇全新目的目錄、元件及版本，安裝前核對實際選取結果。latest 指向各套件維護的 stable／相容版本，並非倉庫最新 Release。Full 模式檢查宣告的依賴；單一元件模式不會驗證既有環境是否相容。

2026-09-10 核對結果：套件清單仍以 SDK 1.2.1 為 stable，未登錄 2.0.1，因此選 latest 不會安裝 V2.0.1。最新版請依下方手動更新流程取得。

設定與 PATH 更新預設不勾選。SDK 模式可只切換 ipro.sdkRoot；toolchain／build tools／IntelProCube 模式可只切換對應工具路徑。OpenOCD 僅安裝檔案；Extension 可選安裝 VSIX。保留舊版目錄以便回復。

Start-Process .\IPRO-SDK-Online-Setup-3.4.0.exe -Wait -ArgumentList '/MODE=sdk', '/SDKVERSION=1.2.1', '/DIR="C:\IPRO\versions\sdk-1.2.1-new"', '/TASKS=""'

此例明確固定安裝已登錄的 SDK 1.2.1，目的目錄必須尚不存在。/OFFLINE=1 使用快取清單／ZIP（或內附初始清單），離線時無法得知新版本。ZIP 會依清單檢查 SHA-256，後續設定失敗時請查看安裝紀錄。

SDK V2.0.1 手動更新

由 V2.0.1 Release 下載 IPRO-SDK-V2.0.1.tar.gz 及其 checksum，解壓至新的 SDK 目錄。確認 VERSION.txt 的 IPRO7／IPRO6 皆為 V2.0.1，選取的根目錄包含 CMakeLists.txt、apps/ 與 bsp/。

Get-FileHash .\IPRO-SDK-V2.0.1.tar.gz -Algorithm SHA256
Get-Content .\IPRO-SDK-V2.0.1.tar.gz.sha256

比對下載的 checksum 與計算結果。Extension 3.3.0 可由 IPRO Setup: Update Components 匯入解壓後資料夾，或直接選擇該 SDK 根目錄；壓縮檔匯入入口接受 ZIP，.tar.gz 請先解壓。重新開啟新 SDK 並執行 IPRO Setup: Run Diagnostics。

SDK README 指定 GCC 14；目前 Windows 清單僅對 SDK 1.2.1 宣告 GCC 13.1.1 的相容組合，V2.0.1 請另行取得並驗證相容工具鏈。原生 Windows Make 請明確傳入 CMAKE=，因 project.build 預設引用未隨附的 tools/cmake_win-x86_64/。在完成新版本建置及板端驗證前，保留可用的 1.2.1 環境。

固定版 Installer 3.3.0（SDK 1.2.1）

以下保留舊版離線完整安裝器與隨附版本的操作方式，供維護既有 3.3.0 環境使用；其 SDK-only 模式安裝的是內含的 1.2.1。

Windows 完整安裝包將韌體開發所需的 SDK、編譯工具與 VS Code 整合集中安裝。安裝包、SDK 與 Extension 的版本分開管理；只更新其中一項時，不必一起更換其他元件。

安裝前準備

  • 使用 Windows x64 或 ARM64 對應的交付包；VSIX 架構依執行 VS Code 的 Windows 主機選擇，不依板端 RISC-V 架構選擇。ARM64 套件存在不代表所有工具已完成 ARM64 實機驗證。
  • VS Code 需 1.102 或以上。完整安裝時若未偵測到一般版 VS Code，可選擇從 Microsoft 下載，該步需要網路；Extension-only 需先安裝 VS Code。
  • 選擇可寫入的安裝根目錄，預設為 C:\IPRO。完整環境約 2 GB，另預留解壓暫存與建構空間；單獨 SDK 約 333 MB。
  • 停止 Build、Flash、Debug 與 Monitor。若目的地已有個人程式，先備份 SDK、專案與設定；版本升級建議使用新的 SDK 目錄。
  • 安裝與首次建構不需要連接開發板；燒錄與串口驗證時才需要板子及相容 Probe／UART。

選擇安裝模式

需求／模式變更範圍操作重點
Full installationSDK、Extension、GCC、CMake、Ninja、Python、IntelProCube 與隨附 OpenOCD依附加工作設定路徑、安裝 VS Code 與更新 user PATH；現有 SDK 同名檔案可能被覆寫
Extension only複製並安裝 VSIX；保留 SDK、工具、設定與 PATH需要已安裝一般版 VS Code；完成後 Reload Window
SDK only將 EXE 內的 SDK 放入新的版本目錄拒絕覆蓋既有目錄；可選擇只設定 User 層 ipro.sdkRoot，預設不勾選

首次完整安裝

  1. 執行 IPRO-SDK-Setup-3.3.0.exe，指定安裝根目錄（例如 C:\IPRO），不要選到個別 SDK 專案內。
  2. 在 Choose installation mode 選擇 Full installation。
  3. 依需求勾選安裝 VS Code、安裝 IPRO Extension、設定 ipro.* 工具路徑與加入 user PATH。工具路徑依選定的安裝目錄產生。
  4. 在 Ready to Install 核對目的地及工作，再按 Install；現有 SDK 的同名檔案可能被覆寫。
  5. 等待複製與後處理完成。如出現 Some steps did not complete，查看 installer\updates\3.3.0\install.log。
  6. 完全關閉並重開原本的 VS Code／Terminal，讓程序取得新的 PATH。開啟 C:\IPRO\sdk\IPRO-IPRO7-SDK-V1.2.1。
  7. 確認可信工作區後，執行 IPRO: Open Control Center，再執行 IPRO Setup: Run Diagnostics。

只更新 Extension

可選擇 EXE 的 Extension only，或直接安裝 VSIX：

  1. 保留舊版 VSIX，停止建構、燒錄與監看。
  2. 在目標 VS Code 視窗按 Ctrl+Shift+X → … → Install from VSIX…，選擇符合主機架構的 3.3.0 套件。
  3. 執行 Developer: Reload Window；在 Extensions 搜尋 @installed IPRO，確認 ipro.ipro-sdk-extension 的版本。
  4. 執行 Diagnostics，檢查 SDK Root 與工具設定。使用 Profiles 或遠端視窗時，確認 VSIX 安裝在正確環境。
code --install-extension .\ipro-sdk-extension-win32-x64-3.3.0.vsix

VSIX 安裝不會複製 SDK 或工具鏈。需要回復時，重新安裝保留的相容舊版 VSIX 並重新載入視窗。

只更新 SDK

EXE 的 SDK only 使用安裝包內的 SDK；選擇全新的目錄名稱，SDK 會放在 <安裝根目錄>\sdk\<新名稱>。既有目錄即使是空的也不會重用。

Set only ipro.sdkRoot… 預設不勾選；勾選時只更新 User 層的 SDK Root，不修改其他工具路徑。工作區設定仍可能優先。外部 ZIP、已解壓資料夾或 Git 來源，請使用 Extension 的元件更新入口。

工具路徑與設定

預設安裝在 C:\IPRO 時，核心設定如下；自訂安裝目錄請換成實際路徑，合併必要欄位即可。

{
  "ipro.sdkRoot": "C:\\IPRO\\sdk\\IPRO-IPRO7-SDK-V1.2.1",
  "ipro.toolchainPath": "C:\\IPRO\\toolchain\\riscv_ipro7_win32\\bin\\riscv64-unknown-elf-",
  "ipro.cmakePath": "C:\\IPRO\\tools\\cmake\\bin\\cmake.exe",
  "ipro.ninjaPath": "C:\\IPRO\\tools\\ninja\\ninja.exe",
  "ipro.pythonPath": "C:\\IPRO\\tools\\python\\python.exe",
  "ipro.flashToolPath": "C:\\IPRO\\IntelProCube",
  "ipro.generator": "ninja"
}

ipro.toolchainPath 必須是含最後連字號的編譯器前綴。安裝器設定寫入一般版 VS Code 的 User settings；工作區 .vscode/settings.json 或其他 Profile 可覆寫。SDK 切換後請以 Diagnostics 顯示的實際根目錄為準。

安裝後驗證

& "C:\IPRO\tools\cmake\bin\cmake.exe" --version
& "C:\IPRO\tools\ninja\ninja.exe" --version
& "C:\IPRO\tools\python\python.exe" -c "import serial; print(serial.__version__)"
& "C:\IPRO\toolchain\riscv_ipro7_win32\bin\riscv64-unknown-elf-gcc.exe" --version
  • SDK 根目錄應同時包含 CMakeLists.txt、apps 與 bsp。
  • 執行 IPRO: Go to Project… 選擇 ipro7_demo，再執行 IPRO: Build。
  • 檢查 Terminal 的實際編譯器路徑與建構結果；預期 BIN 位於 apps\platform\ipro7_demo\build\build_out\ipro7_demo_IPRO7.bin。
  • 需要上板時，再核對 UART、晶片配置、分割表及 Monitor baud rate。建構成功不代表已燒錄或已通過硬體驗證。

問題排查與回復

現象處理方式
沒有 Extension／安裝後有警告查看 installer\updates\3.3.0\install.log，確認 VS Code 位置與 Profile，再以 VSIX 安裝。
設定檔無法解析保留原檔並檢查 installer\ipro-settings.json；在 settings.json 旁查找 .ipro-backup 備份後，合併所需設定。
切換後仍使用舊 SDK檢查開啟的資料夾、工作區 ipro.sdkRoot 與 User 設定；執行 Diagnostics。
rules.ninja: lexing error確認 ipro.cmakePath／ipro.ninjaPath 指向套件工具；工具修正後 Clean 並重新 Build。
SDK 更新失敗／取消保留更新紀錄，重試時使用新的目錄名稱；確認新版本前繼續使用舊 SDK。

回復 SDK 時重新開啟保留的舊版本並核對工具路徑。單一 SDK 版本需個別管理；完整包解除安裝不是 SDK 回復功能，也不會同步移除 VS Code 與 Extension。
