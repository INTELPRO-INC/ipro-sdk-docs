應用範例

IPRO SDK Release 版本提供多個完整的參考應用，展示各種功能的最佳實踐。每個應用都可以直接建構、燒錄並測試。

應用概覽

本 Release SDK 包含 10 個參考應用，分為 BLE 應用（4 個）、LE Audio 應用（3 個）、多媒體應用（1 個）、網路應用（1 個）與平台應用（1 個）五大類：

統一建構工作流程

除了在各應用目錄執行 make，SDK 根目錄的 build_freertos.sh 提供統一的建構入口，可串接建構、燒錄與監看：

build_freertos.sh 工作流程 
# 列出所有可建構的專案
./build_freertos.sh -l

# 建構單一應用（專案名稱或完整路徑皆可）
./build_freertos.sh ipro_ble_remote build
./build_freertos.sh bluetooth/ble/ipro_ble_remote build

# 完整開發循環：建構 + 燒錄 + 序列埠監看
./build_freertos.sh ipro_ble_remote build flash monitor

建構輸出位於 apps/<category>/<name>/build/build_out/，二進位檔名包含晶片後綴，例如 ipro_ble_remote_IPRO7.bin。

ipro_ble_remote

互動式 BLE 遙控器應用，專為手機 App 開發設計，提供 6 個 GATT 服務。

功能特色

  • 6 個 GATT 服務：LED 控制、按鈕、環境感測、UART、PIR 圖片、OTA 更新
  • 手機友好：完整的協定規格，適合 Android/iOS App 開發；應用目錄隨附 Android demo App（ipro_remote_demo.apk）可直接安裝測試
  • 圖片傳輸：JPEG 影像透過 BLE 分塊傳輸，MTU 517 下實測 101.4 KB/s（56KB 影像 542ms 完成）
  • 高速 OTA：MTU 517 自動協商，12.3 KB/s 傳輸速度

服務列表

服務 UUID 功能
LED Control 0xFF10 開關、亮度 (0-100%)、閃爍模式
Button 0xFF20 狀態通知、按壓計數
Environment 0xFF30 溫度、濕度（模擬）
UART 0xFF40 雙向文字通訊
PIR Image 0xFF50 動態偵測 + JPEG 傳輸
OTA 0xFF60 韌體更新 (800KB max, 12.3 KB/s)

ipro_throughput_test

高效能 BLE 傳輸測試應用，使用原生 Zephyr bt_* API，在兩個 IPRO7 開發板之間達到 999 Kbps 傳輸速度。

功能特色

  • 原生 Zephyr API：直接使用 bt_gatt_notify/bt_gatt_write_without_response
  • 雙角色支援：Slave（Peripheral）與 Master（Central），使用自訂 GATT 服務雙向傳輸
  • 即時統計：每秒更新 Kbps 傳輸速度
  • PHY 選擇：1M/2M/Coded
  • DLE 最佳化：Data Length Extension 251 bytes，ATT MTU 247 bytes
  • 連線間隔可調：7.5ms ~ 4s

效能測試結果

PHY 連線間隔 封包大小 傳輸速度
1M 7.5 ms 244 B 507 Kbps
2M 7.5 ms 244 B 999 Kbps
2M 15 ms 244 B 984 Kbps
2M 7.5 ms 100 B 610 Kbps
2M 7.5 ms 20 B 187 Kbps

快速開始

測試流程 
# 開發板 1 (Slave)
tp slave

# 開發板 2 (Master)
tp master

# 連線後開始測試（244 bytes, 10 秒）
tp start 244 10

# 最佳化速度
tp phy 2         # 使用 2M PHY
tp conn 6 6      # 最小連線間隔

ipro_ble_img_capture

BLE 影像擷取應用，結合 PIR 動作感測、ISP 影像擷取與 BLE 影像傳輸，適合低功耗影像感測節點開發。GATT 服務架構承襲 ipro_ble_remote。

功能特色

  • PIR 觸發擷取：PIR 感測器 GPIO 中斷偵測動作，事件通知手機並觸發影像擷取
  • 低功耗循環：睡眠/喚醒循環運作，平時進入低功耗模式，動作觸發後喚醒擷取
  • ISP + JPEG：ISP 攝影機擷取搭配 JPEG 壓縮，解析度可設定（QVGA/VGA/720p/1080p）
  • 影像分塊傳輸：依協商 MTU 動態調整 chunk 大小，MTU 517 下實測 101.4 KB/s（56KB 影像）
  • 影像上傳服務：手機端可反向上傳影像至裝置，含 PAUSE/RESUME 流量控制
  • OTA 更新：與 ipro_ble_remote 相同的 OTA 服務（0xFF60）

服務列表

服務 UUID 功能
PIR Image 0xFF50 動作事件通知、影像擷取控制與分塊傳輸
Image Upload 0xFF70 手機→裝置影像上傳（流量控制）
OTA 0xFF60 韌體更新

ipro_le_audio_headset

LE Audio Unicast 耳機參考應用，基於 GAF (Generic Audio Framework) 實作完整的無線耳機，透過 CIS (Connected Isochronous Stream) 與手機/PC 等 Unicast Client（CAP）來源端進行雙向音訊串流。

功能特色

  • BAP Unicast Server：CIS 雙向音訊串流（Basic Audio Profile）
  • LC3 Codec：低複雜度通訊編解碼
  • VCP Server：Volume Control Profile，由來源端遠端控制音量
  • MCP：Media Control Profile 媒體播放控制（預留，供後續開發）
  • CCP：Call Control Profile 通話控制（預留，供後續開發）

ipro_agora_sentino

嵌入式 AI 語音對話閘道器。透過 AMIC 差分麥克風擷取語音，經由網路傳送至 Agora RTC 雲端，與 AI 對話機器人進行即時雙向語音通話，並透過 LCD 顯示狀態、USB CDC 虛擬串口輸出語音辨識（STT）文字。

功能特色

  • 即時雙向語音：AMIC 擷取（16 kHz / 16-bit / 單聲道）→ Agora RTC 雲端 ↔ AI 對話機器人，Opus 編解碼由 SDK 內部處理
  • 音訊輸出：DAC 喇叭播放，含 soft limiter、TPDF dither 與自動靜音（auto-mute）
  • 連網方式：乙太網路（RMII）或 USB NCM 網路共享，lwIP + DHCP
  • LCD 狀態顯示：ILI9341 SPI LCD 即時顯示 IP、頻道、連線狀態、AI 狀態、音量與統計
  • STT 文字輸出：USB CDC ACM 虛擬串口將語音辨識文字輸出至 Host
  • 自動連線：開機後自動初始化網路、取得 Token、加入 RTC 頻道並啟動 AI 對話

硬體連接

功能 介面 說明
AMIC 麥克風 GPIO4 / GPIO7 差分輸入（正/負）
DAC 輸出 GPIO23 類比音訊輸出，GPIO22 喇叭致能
LCD SPI0 ILI9341 狀態顯示
網路 RMII / USB NCM 乙太網路或 USB 網路共享

ipro_voice_assistant

運行在 IPRO7 上的 AI 語音助理，結合即時語音對話與 Telegram 文字聊天機器人：可透過麥克風與 AI 對話，或透過 Telegram 傳送文字訊息。

功能特色

  • 語音對話：AMIC 麥克風收音 → VAD 語音偵測 → 語音辨識 → AI 回覆 → TTS 語音合成 → DAC 喇叭播放
  • AI Agent：支援多家雲端 AI 供應商，具備 ReAct 工具呼叫能力（網路搜尋、排程任務、持久記憶）
  • Telegram 聊天：透過 Telegram Bot API 長輪詢接收訊息，AI 回覆後自動傳送
  • LCD 動態顯示：ILI9341 SPI LCD（240×320）顯示狀態動畫（閒置、聆聽中、思考中、說話中）
  • 持久記憶：LittleFS 檔案系統儲存 AI 人格、使用者資料與對話記憶
  • 網路連線：乙太網路（RMII）或 4G LTE Modem（PPPoS）二擇一，交付組態預設為 LTE；IPRO7 不內建 Wi-Fi

# 方式二：執行時透過 Shell 指令設定（免重新燒錄）

程式碼範例

GPIO 使用範例 
#include "hal_gpio.h"

void gpio_example(void)
{
    // 配置 GPIO 為輸出
    gpio_set_mode(GPIO_PIN_0, GPIO_OUTPUT_MODE);

    // 設置輸出
    gpio_write(GPIO_PIN_0, 1);

    // 讀取輸入
    gpio_set_mode(GPIO_PIN_1, GPIO_INPUT_PP_MODE);
    int value = gpio_read(GPIO_PIN_1);

    // 切換輸出
    gpio_toggle(GPIO_PIN_0);
}

建立新應用

按照以下步驟建立您自己的應用程式。建議以 ipro_ble_remote 為範本複製後修改。

提示：最快的方式是複製現有應用作為起點：

cp -r apps/bluetooth/ble/ipro_ble_remote apps/bluetooth/ble/my_app
rm -rf apps/bluetooth/ble/my_app/build

然後修改 CMakeLists.txt 末行 setup_project() 的名稱與 Makefile 中的 PROJECT_NAME，並保留複製來的 .config 即可。

步驟 1：建立目錄

應用需放在 apps/ 下的分類子目錄中（apps/<category>/<name>），例如 BLE 應用放在 apps/bluetooth/ble/。

建立應用目錄 
mkdir -p apps/bluetooth/ble/my_app/include
mkdir -p apps/bluetooth/ble/my_app/src

步驟 2：建立 CMakeLists.txt

應用的 CMakeLists.txt 由 SDK 根目錄的 project.build 驅動，不需要 cmake_minimum_required() 或 project()，直接使用 SDK 提供的建構函式即可：

apps/bluetooth/ble/my_app/CMakeLists.txt 
# 添加頭文件目錄
__component_add_include_dirs(include)

# 添加應用原始檔
# 注意：main.c 不可加入 target_sources，否則會與
# --whole-archive 連結造成重複符號錯誤
target_sources(app PRIVATE
    src/my_module.c
)

# 將 app 函式庫加入 SDK 連結清單
set_property(GLOBAL APPEND PROPERTY SDK_LIBS app)
# 若應用有註冊 Shell 命令，需強制 whole-archive 連結
set_property(GLOBAL APPEND PROPERTY SDK_WHOLE_ARCHIVE_LIBS app)

# 指定主程式檔案並完成專案設置
__set_main_file(main.c)
setup_project(my_app)

步驟 3：建立主程式

所有 FreeRTOS 應用共用 freertos_app_hooks 元件提供的預設 heap、FreeRTOS hooks 與平台初始化（皆為 weak 函式，可在應用內定義同名函式覆寫），main.c 只需保留最小骨架：

apps/bluetooth/ble/my_app/main.c 
#include "freertos_app_hooks.h"
#include "ipro_log.h"
#include <FreeRTOS.h>
#include <task.h>

#define TAG "MY_APP"

static void app_task(void *params)
{
    IPRO_LOGI(TAG, "My App Started!");

    while (1) {
        IPRO_LOGI(TAG, "Running...");
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}

int main(void)
{
    // 平台初始化：heap + boot2 + log + shell（共用 weak 預設）
    ipro_platform_init();

    // 建立應用任務
    xTaskCreate(app_task, "app", 1024, NULL, 5, NULL);

    // 啟動排程器
    vTaskStartScheduler();

    while (1) {}
}

步驟 4：建立組態 (.config)

建構系統會以應用目錄下的 .config 產生 generated/autoconf.h，沒有 .config 將無法建構。最簡單的做法是從範本應用複製：

建立組態 
# 從範本應用複製組態
cp apps/bluetooth/ble/ipro_ble_remote/.config apps/bluetooth/ble/my_app/.config

關鍵組態項目：

  • CONFIG_IPRO7=y — SoC 選擇
  • CONFIG_CPU_ID="intelpro_ipro7" — 工具鏈目標
  • CONFIG_FREERTOS_SUPPORT=y — RTOS 選擇

範本應用的 Makefile 內建組態管理 target：make defconfig（載入預設組態）、make savedefconfig（儲存目前組態為 defconfig）、make show-config（顯示目前組態）、make list-defconfigs（列出可用 defconfig）。這些 target 需在步驟 5 複製範本 Makefile 後才可使用；新應用尚無 defconfig 來源檔，請先以 make savedefconfig 從目前 .config 產生。

步驟 5：建立 Makefile

應用 Makefile 採委派模式，將建構轉交給 SDK 根目錄的 project.build。注意 IPRO_SDK_BASE 的相對深度需依應用位置調整（apps/bluetooth/ble/my_app/ 需向上 4 層）。建議直接複製範本應用的 Makefile（內含完整組態管理 target），只修改 PROJECT_NAME：

apps/bluetooth/ble/my_app/Makefile 
# 依應用目錄深度設定 SDK 根目錄
# apps/bluetooth/ble/my_app/ -> 向上 4 層
IPRO_SDK_BASE ?= $(abspath ../../../../)
export IPRO_SDK_BASE

PROJECT_PATH ?= $(abspath .)
PROJECT_NAME ?= my_app

all:
	$(MAKE) -C $(IPRO_SDK_BASE) -f project.build PROJECT_PATH=$(CURDIR)

clean:
	$(MAKE) -C $(IPRO_SDK_BASE) -f project.build PROJECT_PATH=$(CURDIR) clean

# 組態管理 target（defconfig / savedefconfig 等）請從範本應用的 Makefile 複製
.PHONY: all clean

步驟 6：建構

建構新應用 
make -C apps/bluetooth/ble/my_app

# 或使用統一建構入口
./build_freertos.sh my_app build

建構輸出位於 apps/bluetooth/ble/my_app/build/build_out/my_app_IPRO7.bin。
