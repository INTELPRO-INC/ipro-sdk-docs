常見問題 FAQ

快速解決開發過程中遇到的問題

Build

make -C apps/<project> 和 build_freertos.sh 有什麼區別？

build_freertos.sh 是推薦的統一建構入口：支援 build、flash、monitor 等動作串接、以 -l 列出所有專案，並可用短專案名稱自動解析路徑。make -C apps/<category>/<project> 是等效的單一建構方式，需要提供完整巢狀路徑。

# 推薦：統一 CLI
./build_freertos.sh ipro_ble_remote build

# 串接 build + flash + monitor
./build_freertos.sh ipro_ble_remote build flash monitor

# 列出所有可建構專案
./build_freertos.sh -l

# 等效的單一建構方式（需完整巢狀路徑）
make -C apps/bluetooth/ble/ipro_ble_remote

# 清除編譯
make -C apps/bluetooth/ble/ipro_ble_remote clean

建構產出位於 apps/<category>/<project>/build/build_out/，二進位檔名包含晶片後綴（如 ipro_ble_remote_IPRO7.bin）。

Build

.config 檔案格式是什麼？如何設定 CONFIG_* 變數？

.config 使用 Linux Kernel Kconfig 格式。每個應用程式都有自己的 .config，建構時會自動生成 generated/autoconf.h。

# 基本格式
CONFIG_IPRO7=y                          # 布林值：啟用
CONFIG_CPU_ID="intelpro_ipro7"          # 字串值
CONFIG_FREERTOS_SUPPORT=y               # RTOS 選擇
CONFIG_BLUETOOTH_LE_ENABLE=y            # BLE 啟用
# CONFIG_COMPONENTS_LWIP_ENABLE is not set                # 布林值：停用

修改 .config 後需要重新建構。常用的 CONFIG 變數包括 SoC 選擇（CONFIG_IPRO7）、RTOS（CONFIG_FREERTOS_SUPPORT）和元件啟用（CONFIG_BLUETOOTH_LE_ENABLE、CONFIG_COMPONENTS_LWIP_ENABLE、CONFIG_COMPONENTS_MBEDTLS_ENABLE 等）。

Build

編譯時出現 "toolchain not found" 錯誤怎麼辦？

請確認 RISC-V 工具鏈已正確安裝並設定路徑：

# 檢查工具鏈路徑
ls /opt/toolchain/riscv_ipro7/bin/

# 如果不存在，請設定正確的 CROSS_COMPILE 路徑
export CROSS_COMPILE=/your/toolchain/path/bin/riscv64-unknown-elf-

# 或在編譯指令中指定
cmake -DCROSS_COMPILE=/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- ...

確保 .config 中的 CONFIG_CPU_ID 已正確設定，否則工具鏈無法偵測架構旗標。

Build

編譯時 Flash 或 RAM 空間不足？

先確認 IPRO7 的記憶體配置基準，再判斷哪個區域不足：

區域大小位址
Flash依板型而定（例：IPRO7AI Reef EVK 為 2 MB）0x13000000
PSRAM8 MB0x1e000000
OCRAM256 KB0x11010000
HBNRAM4 KB0x20090000

可以透過以下方式最佳化：

  1. 在 .config 中關閉不需要的功能
  2. 使用 -Os 最佳化等級
  3. 檢查是否有未使用的元件被編譯進去
# 查看 ELF 大小與各記憶體區域使用率
./build_freertos.sh ipro_ble_remote size

# 查看各模組大小
riscv64-unknown-elf-size apps/bluetooth/ble/ipro_ble_remote/build/build_out/*.elf

# 詳細分析
riscv64-unknown-elf-nm --size-sort apps/bluetooth/ble/ipro_ble_remote/build/build_out/*.elf | tail -50

也可以檢查 linker 輸出的各 region 使用率，以及 build/build_out/ 下的 .map 檔，找出佔用最大的模組。

Build

如何燒錄韌體到開發板？燒錄失敗怎麼辦？

使用 build_freertos.sh 的 flash 動作即可建構並燒錄。燒錄工具為另行取得的 IntelProCube v0.6.3 命令列工具，請設定 IPRO_FLASH_TOOL 指向它或將其目錄加入 PATH（序列埠名稱依實際裝置而定）：

# 建構 + 燒錄 + 監看序列輸出
./build_freertos.sh ipro_ble_remote build flash monitor -p /dev/cu.usbserial-XXXX

燒錄失敗時請依序檢查：

  1. 確認工具輸出中有 [All Success]：燒錄失敗時工具仍回傳 0
  2. macOS 上必須使用 /dev/cu.* 裝置節點，且序列埠名稱正確
  3. 確認沒有其他程式佔用序列埠（可用 lsof 檢查）
  4. 確認晶片型號：IPRO7 EVB 使用 --chip-variant IPRO7，IPRO7AI EVK 與 Reef 使用 IPRO7AI（工具沒有 --flash-pin 選項）
  5. 若板子未自動進入下載模式，可在板端 shell 輸入 reboot_dl 重啟進入下載模式後重試
  6. IPRO7AI Reef EVK：確認已插上 JP1 跳線，並使用 2 MB 分割表（以應用 README 為準）
  7. 檢查 USB 線材與供電是否穩定

V2.1.0 支援 IPRO6S 嗎？

不支援。V2.1.0 的應用皆以 IPRO7 為目標（IPRO7 EVB、IPRO7AI EVK、IPRO7AI Reef EVK），未附 IPRO6S 應用（ipro6_demo、ipro6_if_wifi、ipro6_btdm_phyrf 僅在 V2.0.1 中提供）、IPRO6S BLE Controller 函式庫與 ipro6_rf。樹中仍保留部分 IPRO6S 驅動與 Wi-Fi 協定堆疊原始碼，但本版不支援 IPRO6S 建構。

IPRO6S 開發（BR/EDR A2DP／HFP、晶片內建 Wi-Fi 6、IPRO6S EVB）請使用 V2.0.1。

BLE

BLE Controller 的 linkN 變體該如何選擇？

根據應用需求選擇合適的 Controller 變體：

LIBACL角色
link1_periph1Peripheral
link11Central + Peripheral
link22Central + Peripheral
link44Central + Peripheral

基本 BLE 選擇 CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"；BLE 5.4 與兩路 ISO 串流（CIS/BIS）選擇 "bt54_iso2"，後者要求 CONFIG_EM_SIZE 至少 32 KB。Host 連線上限不可超過控制器容量；PDM 請保留 link2／CONFIG_BT_CONN=1 配置。

在應用程式的 .config 中以 CONFIG_IPRO_BLE_CTLR_LIB 選擇變體：

# 選擇 Controller 變體
CONFIG_BT_CTLR_IPRO=y
CONFIG_BT_HOST_IPRO_V44=y
CONFIG_IPRO_BLE_CTLR_LIB="link1"
CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"
CONFIG_IPRO_BLE_CTLR_CFG_DBG=n
CONFIG_BT_CONN=1
CONFIG_EM_SIZE=32

V2.1.0 預設值：Remote 使用 link1_periph / bt52；Transparent 與 HID Keyboard 使用 link1 / bt52；Throughput Test 使用 link2 / bt52；Headset 使用 link1_periph / bt54_iso2。只有 link1、link2 與 link4 支援 Central 與 Peripheral 雙角色。

BLE

BLE Controller 是以原始碼還是預編譯函式庫提供？

BLE Controller 僅以預編譯靜態函式庫（.a）形式提供，依 ACL 連線數、功能配置與 CFG_DBG 選擇，存放在 components/wireless/bluetooth/ipro_ble_controller/lib/ 目錄。Controller 原始碼不包含在 SDK 中。V2.1.0 僅提供 IPRO7 的 16 個函式庫（link1_periph／link1／link2／link4 × bt52／bt54_iso2 × debug／release）。

在應用程式的 .config 中設定要連結的變體即可：

# 選擇 Controller 變體
CONFIG_BT_CTLR_IPRO=y
CONFIG_BT_HOST_IPRO_V44=y
CONFIG_IPRO_BLE_CTLR_LIB="link1"
CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"
CONFIG_IPRO_BLE_CTLR_CFG_DBG=n
CONFIG_BT_CONN=1
CONFIG_EM_SIZE=32

注意

預編譯函式庫不可修改。若需要客製化的 Controller 變體（例如不同連線數或功能組合），請聯絡 INTELPRO 取得支援。

BLE

多連線如何實現不同角色組合？

IPRO SDK 使用統一連線池模型。以 link4 為例，4 個連線可以是任意 Central/Peripheral 組合：

  • 4 個 Peripheral（被動連線）
  • 4 個 Central（主動連線）
  • 2 Central + 2 Peripheral（混合）
  • 任何其他組合，只要總數不超過連線上限

同一裝置可以同時廣播和掃描，用於 Relay、類 Mesh 拓撲等進階場景。

手機搜尋不到 BLE 裝置？

請檢查以下項目：

  1. 確認 Advertising 已啟動
  2. 檢查 Advertising Data 是否正確設定
  3. 確認包含正確的 Service UUID
  4. 檢查 RF 是否正常工作
// 確保 Advertising Data 包含必要資訊
static const struct bt_data ad[] = {
    BT_DATA_BYTES(BT_DATA_FLAGS,
                  BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR),
    BT_DATA_BYTES(BT_DATA_NAME_COMPLETE, 'I','P','R','O'),
};

bt_le_adv_start(BT_LE_ADV_CONN_FAST_1, ad, ARRAY_SIZE(ad),
                NULL, 0);

LE Audio 音訊有雜音或斷斷續續？

音訊品質問題可能來源：

  • ISO Interval 設定不當
  • LC3 編碼參數不匹配
  • Buffer underrun/overrun
  • RF 干擾或訊號弱
// 建議的 LE Audio 參數（48_4 設定集）：
// 48kHz 取樣率、10ms frame duration、每 frame 120 octets
// ipro_bt_host 提供對應的巨集（include/bluetooth/audio/lc3.h）：
BT_CODEC_LC3_CONFIG_48_4(loc, stream_context)

完整的 codec 設定流程請參考 LE Audio headset 範例：apps/bluetooth/le_audio/ipro_le_audio_headset。

BLE

BLE 配對（bonding）資訊無法保存，或 Controller 連結失敗？

配對金鑰由 Bluetooth Host 的 Settings 後端保存；NVDS 是 Controller 設定儲存，不能單獨取代 Host bonding。參考 PDM 或 headset 範例：

CONFIG_BT_SMP=y
CONFIG_BT_SETTINGS=y
CONFIG_EASYFLASH4=y

在 bt_enable() 完成後、開始廣播前呼叫 settings_load_subtree("bt") 並檢查錯誤。沿用範例的 Flash 分區與儲存初始化；重新燒錄時若清除儲存區，裝置及手機兩端都需要重新配對。

BLE

BLE throughput 如何最佳化？

提升 BLE 資料吞吐量的關鍵設定：

  1. 切換到 2M PHY
  2. 啟用 DLE（Data Length Extension）
  3. 協商較大的 ATT MTU
  4. 使用較短的 connection interval

SDK 的 throughput 測試範例（apps/bluetooth/ble/ipro_throughput_test）在 2M PHY + DLE 條件下實測可達 999 Kbps，可作為參數調校的參考實作。

BLE

如何進行 OTA 韌體升級？

ipro_ble_remote 範例（apps/bluetooth/ble/ipro_ble_remote）內建 OTA GATT service，提供透過 BLE 傳輸並更新韌體的完整參考實作，可直接套用到自己的應用中。

V2.1.0 隨附 tools/create_ota.py，可將合併後的韌體映像檔打包為 boot2 的 .xz.ota 格式。Zephyr RTOS 下則以 sysbuild 搭配 MCUboot（zephyr/samples/mcuboot_app），並透過 BLE 的 MCUmgr SMP 上傳映像檔（zephyr/samples/ble_ota），詳見 Zephyr RTOS。

Debug

macOS 上序列埠 cu.* 和 tty.* 有什麼區別？

在 macOS 上，每個序列裝置都有兩個裝置節點（以下序列埠名稱依實際裝置而定）：

  • /dev/cu.* (Calling Unit) - 必須使用此裝置。不等待 DCD 訊號，可直接開啟。
  • /dev/tty.* (Teletype) - 會等待 DCD 訊號，導致程式卡住無法使用。
# V2.1.0 隨附；鮑率依應用的 CONFIG_PLATFORM_UART_BAUDRATE（未設定為 115200）
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --baud 115200 --timeout 60

# 或另行安裝 pyserial
python3 -m pip install pyserial
python3 -m serial.tools.miniterm /dev/cu.usbserial-XXXX 115200
Debug

序列埠出現 "Resource busy" 錯誤怎麼辦？

這通常是因為其他程式（包括 stty）正在占用序列埠。解決方法：

  1. 檢查並關閉占用埠的程式：lsof /dev/cu.usbserial-XXXX（序列埠名稱依實際裝置而定）
  2. 避免使用 stty -f，它會保持埠忙碌
  3. 同一時間僅使用一個序列埠監看工具（tools/serial_monitor.py、外部終端或 Extension Monitor）

build_freertos.sh 的 monitor／test 動作也會開啟序列埠；燒錄或開啟另一個終端前，請先停止目前的序列埠監看。

遇到 Hard Fault 如何分析？

Hard Fault 通常由以下原因造成：

  • 空指標存取
  • Stack overflow
  • 非對齊記憶體存取
  • 非法指令
# 使用 addr2line 解析 backtrace
# ELF 檔名包含晶片後綴（如 ipro_ble_remote_IPRO7.elf）
riscv64-unknown-elf-addr2line -e apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.elf 0x12345678
RF

CFO (載波頻率偏移) 過大怎麼調整？

CFO 問題通常有兩個原因：

  1. rf_kcal 未執行： 檢查 RF_CAL_STATE_CTRL 暫存器
  2. XTAL 頻率偏差： 調整 capcode

使用 AON 驅動 API（bsp/drivers/ipro7_soc/std_drv/inc/drv_aon.h）調整 XTAL capcode：

// 調整 XTAL capcode
// CFO 為負值（頻率太低）: 降低 capcode
// CFO 為正值（頻率太高）: 提高 capcode
AON_Set_Xtal_CapCode(70, 70);          // 設定 capcode（in / out）

uint8_t cap = AON_Get_Xtal_CapCode();  // 讀回目前 capcode
RF

TX Power 如何設定？

IPRO7 支援的 TX Power 範圍為 -3dBm ~ +10dBm（1dB step）：

// 參數為目標功率 (dBm)，函式自動選擇最接近的功率表項
rf_set_tx_power(10);   // +10dBm（最大）
rf_set_tx_power(0);    // 0dBm
rf_set_tx_power(-3);   // -3dBm（最小）

更進階的 RF 調校（例如客製功率表）請聯絡 INTELPRO 取得支援。

RF

IPRO7 支援 Wi-Fi 嗎？

IPRO7 本身不內建 Wi-Fi。V2.1.0 提供以下連網方式：

  • IPRO6S 作為 SDIO Wi-Fi：ipro7_sdio_wifi 是 IPRO7 端的 SDIO 主機範例（ipronet_host，lwIP netif iproeth0、DHCP、iperf）；IPRO6S 端的 ipro6_if_wifi 不在 V2.1.0 內，請使用 V2.0.1 或聯絡 INTELPRO。
  • ATBM6162 SDIO 模組：ipro_atbm_probe（模組驗證程式）。
  • IPRO7AI Reef EVK 搭配 IPRO6S FIN 卡（SDIO）：主控端為 ipro7ai_reef_demo 的 defconfig_wifi_ipro6s（Wi-Fi 與 RTSP 攝影機串流）。FIN 卡上的 IPRO6S 韌體不在 V2.1.0 內，請聯絡 INTELPRO。
  • Ethernet：ipro_enc28j60_test（SPI 介面的 ENC28J60），以及 ipro7_demo 中的 IPRO7 EMAC（RMII）。

IPRO6S 本身的開發請使用 V2.0.1。

RTOS

SDK 支援哪些 RTOS？BLE Host 是 Zephyr 嗎？

SDK 以 FreeRTOS 作為主要作業系統，V2.1.0 的 34 個應用程式都以 FreeRTOS 建構：

# 所有應用程式的 .config 都使用
CONFIG_FREERTOS_SUPPORT=y

BLE Host 協定疊（GAP、GATT、L2CAP、SMP、ISO、LE Audio）源自 Zephyr 專案，應用層使用 Zephyr 風格的 bt_* callback API——在 FreeRTOS 應用中它執行於 FreeRTOS 之上，不需要安裝或建構 Zephyr。

# 建構 BLE 應用（FreeRTOS + Zephyr-based BLE Host）
./build_freertos.sh ipro_ble_remote build

此外，V2.1.0 起 SDK 同時是 Zephyr v4.4.0 模組，可在 IPRO7 EVB（ipro7_evb）與 IPRO7AI EVK（ipro7ai_evk）上以 west 建構 Zephyr 應用。本版 Zephyr 未提供低功耗模式，以及顯示、攝影機、音訊 codec、USB、SD host、Ethernet 與 NPU 驅動，這些功能請使用 FreeRTOS。詳見 Zephyr RTOS。

RTOS

可以使用 Thread（IEEE 802.15.4）或 Matter 嗎？

Thread 僅於 Zephyr RTOS 下提供：使用 Zephyr 的 IEEE 802.15.4 驅動（IPRO7 radio）與 OpenThread，範例為 Zephyr 的 samples/net/openthread/shell 搭配 SDK 的 zephyr/samples/ieee802154_shell/ot.conf 與 app.overlay。RF 驅動與 802.15.4 MAC 以預編譯函式庫連結。

V2.1.0 的 FreeRTOS 應用不含 Thread，本版也未包含 Matter。詳見 Zephyr RTOS。

RTOS

Task Stack Overflow 如何解決？

增加 Task 的 Stack 大小：

// FreeRTOS
xTaskCreate(
    task_function,
    "TaskName",
    2048,  // 增加 Stack 大小 (words)
    NULL,
    tskIDLE_PRIORITY + 1,
    &task_handle
);

也可以啟用 Stack 監控功能來追蹤使用量。
