常見問題 FAQ

快速解決開發過程中遇到的問題

Build

make -C apps/<project> 和 build_freertos.sh 有什麼區別？

build_freertos.sh 是推薦的統一建構入口：支援 build、flash、monitor 等動作串接、以 -l 列出所有專案，並可用短專案名稱自動解析路徑。make -C apps/<category>/<project> 是等效的單一建構方式，需要提供完整巢狀路徑。

# 推薦：統一 CLI
./build_freertos.sh ipro_ble_remote build

# 串接 build + flash + monitor
./build_freertos.sh ipro_ble_remote build flash monitor

# 列出所有可建構專案
./build_freertos.sh -l

# 等效的單一建構方式（需完整巢狀路徑）
make -C apps/bluetooth/ble/ipro_ble_remote

# 清除編譯
make -C apps/bluetooth/ble/ipro_ble_remote clean

建構產出位於 apps/<category>/<project>/build/build_out/，二進位檔名包含晶片後綴（如 ipro_ble_remote_IPRO7.bin）。

Build

.config 檔案格式是什麼？如何設定 CONFIG_* 變數？

.config 使用 Linux Kernel Kconfig 格式。每個應用程式都有自己的 .config，建構時會自動生成 generated/autoconf.h。

# 基本格式
CONFIG_IPRO7=y                          # 布林值：啟用
CONFIG_CPU_ID="intelpro_ipro7"          # 字串值
CONFIG_FREERTOS_SUPPORT=y               # RTOS 選擇
CONFIG_BLUETOOTH_LE_ENABLE=y            # BLE 啟用
# CONFIG_LWIP is not set                # 布林值：停用

修改 .config 後需要重新建構。常用的 CONFIG 變數包括 SoC 選擇（CONFIG_IPRO7）、RTOS（CONFIG_FREERTOS_SUPPORT）和元件啟用（CONFIG_BLUETOOTH_LE_ENABLE、CONFIG_LWIP、CONFIG_MBEDTLS 等）。

Build

編譯時出現 "toolchain not found" 錯誤怎麼辦？

請確認 RISC-V 工具鏈已正確安裝並設定路徑：

# 檢查工具鏈路徑
ls /opt/toolchain/riscv_ipro7/bin/

# 如果不存在，請設定正確的 CROSS_COMPILE 路徑
export CROSS_COMPILE=/your/toolchain/path/bin/riscv64-unknown-elf-

# 或在編譯指令中指定
cmake -DCROSS_COMPILE=/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf- ...

確保 .config 中的 CONFIG_CPU_ID 已正確設定，否則工具鏈無法偵測架構旗標。

Build

編譯時 Flash 或 RAM 空間不足？

先確認 IPRO7 的記憶體配置基準，再判斷哪個區域不足：

區域大小位址
Flash1 MB0x13000000
PSRAM8 MB0x1e000000
OCRAM256 KB0x11010000
HBNRAM4 KB0x20090000

可以透過以下方式優化：

  1. 在 .config 中關閉不需要的功能
  2. 使用 -Os 優化等級
  3. 檢查是否有未使用的組件被編譯進去
# 查看 ELF 大小與各記憶體區域使用率
./build_freertos.sh ipro_ble_remote size

# 查看各模組大小
riscv64-unknown-elf-size apps/bluetooth/ble/ipro_ble_remote/build/build_out/*.elf

# 詳細分析
riscv64-unknown-elf-nm --size-sort apps/bluetooth/ble/ipro_ble_remote/build/build_out/*.elf | tail -50

也可以檢查 linker 輸出的各 region 使用率，以及 build/build_out/ 下的 .map 檔，找出佔用最大的模組。

Build

如何燒錄韌體到開發板？燒錄失敗怎麼辦？

使用 build_freertos.sh 的 flash 動作即可建構並燒錄（序列埠名稱依實際裝置而定）：

# 建構 + 燒錄 + 監看序列輸出
./build_freertos.sh ipro_ble_remote build flash monitor -p /dev/cu.usbserial-XXXX

燒錄失敗時請依序檢查：

  1. macOS 上必須使用 /dev/cu.* 裝置節點，且序列埠名稱正確
  2. 確認沒有其他程式佔用序列埠（可用 lsof 檢查）
  3. 若板子未自動進入下載模式，可在板端 shell 輸入 reboot_dl 重啟進入下載模式後重試
  4. 檢查 USB 線材與供電是否穩定
BLE

BLE Controller 的 linkN 變體該如何選擇？

根據應用需求選擇合適的 Controller 變體：

LIBACL角色
link1_periph1Peripheral
link11Central + Peripheral
link22Central + Peripheral
link44Central + Peripheral

基本 BLE 選擇 CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"；BLE 5.4 與兩路 ISO 串流（CIS/BIS）選擇 "bt54_iso2"，後者要求 CONFIG_EM_SIZE 至少 32 KB。CONFIG_BT_CONN 應與所選 ACL 連線數一致。

在應用程式的 .config 中以 CONFIG_IPRO_BLE_CTLR_LIB 選擇變體：

# 選擇 Controller 變體
CONFIG_BT_CTLR_IPRO=y
CONFIG_BT_HOST_IPRO_V44=y
CONFIG_IPRO_BLE_CTLR_LIB="link1"
CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"
CONFIG_IPRO_BLE_CTLR_CFG_DBG=n
CONFIG_BT_CONN=1
CONFIG_EM_SIZE=32

V1.2.1 預設值：Remote 使用 link1_periph / bt52；Transparent 與 HID Keyboard 使用 link1 / bt52；Throughput Test 使用 link2 / bt52；Headset 使用 link1_periph / bt54_iso2。只有 link1、link2 與 link4 支援 Central 與 Peripheral 雙角色。

BLE

BLE Controller 是以原始碼還是預編譯函式庫提供？

BLE Controller 僅以預編譯靜態函式庫（.a）形式提供，依 ACL 連線数、功能配置與 CFG_DBG 選擇，存放在 components/wireless/bluetooth/ipro_ble_controller/lib/ 目錄。Controller 原始碼不包含在 SDK 中。

在應用程式的 .config 中設定要連結的變體即可：

# 選擇 Controller 變體
CONFIG_BT_CTLR_IPRO=y
CONFIG_BT_HOST_IPRO_V44=y
CONFIG_IPRO_BLE_CTLR_LIB="link1"
CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"
CONFIG_IPRO_BLE_CTLR_CFG_DBG=n
CONFIG_BT_CONN=1
CONFIG_EM_SIZE=32

注意

預編譯函式庫不可修改。若需要客製化的 Controller 變體（例如不同連線數或功能組合），請聯絡原廠取得支援。

BLE

多連線如何實現不同角色組合？

IPRO SDK 使用統一連線池模型。以 link4 為例，4 個連線可以是任意 Central/Peripheral 組合：

  • 4 個 Peripheral（被動連線）
  • 4 個 Central（主動連線）
  • 2 Central + 2 Peripheral（混合）
  • 任何其他組合，只要總數不超過連線上限

同一裝置可以同時廣播和掃描，實現 Relay、Mesh-like 拓撲等進階場景。

手機搜尋不到 BLE 裝置？

請檢查以下項目：

  1. 確認 Advertising 已啟動
  2. 檢查 Advertising Data 是否正確設定
  3. 確認包含正確的 Service UUID
  4. 檢查 RF 是否正常工作
// 確保 Advertising Data 包含必要資訊
static const struct bt_data ad[] = {
    BT_DATA_BYTES(BT_DATA_FLAGS,
                  BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR),
    BT_DATA_BYTES(BT_DATA_NAME_COMPLETE, 'I','P','R','O'),
};

bt_le_adv_start(BT_LE_ADV_CONN, ad, ARRAY_SIZE(ad),
                NULL, 0);
BLE

LE Audio 音訊有雜音或斷斷續續？

音訊品質問題可能來源：

  • ISO Interval 設定不當
  • LC3 編碼參數不匹配
  • Buffer underrun/overrun
  • RF 干擾或訊號弱
// 建議的 LE Audio 參數（48_4 設定集）：
// 48kHz 取樣率、10ms frame duration、每 frame 120 octets
// ipro_bt_host 提供對應的巨集（include/bluetooth/audio/lc3.h）：
BT_CODEC_LC3_CONFIG_48_4(loc, stream_context)

完整的 codec 設定流程請參考 LE Audio headset 範例：apps/bluetooth/le_audio/ipro_le_audio_headset。

BLE

BLE 配對（bonding）資訊無法保存，或 Controller 連結失敗？

BLE 應用需要啟用 NVDS（Non-Volatile Data Storage）才能把配對金鑰等資訊保存到 flash。在 .config 中設定：

# 啟用 NVDS 儲存
CONFIG_ENABLE_NVDS=y
CONFIG_CFG_NVDS=y

注意：BLE 應用若未啟用 NVDS，連結階段會因缺少 NVDS 相關符號而失敗。SDK 出貨的 BLE 範例（如 ipro_ble_remote）已預設啟用。

BLE

BLE throughput 如何最佳化？

提升 BLE 資料吞吐量的關鍵設定：

  1. 切換到 2M PHY
  2. 啟用 DLE（Data Length Extension）
  3. 協商較大的 ATT MTU
  4. 使用較短的 connection interval

SDK 的 throughput 測試範例（apps/bluetooth/ble/ipro_throughput_test）在 2M PHY + DLE 條件下實測可達 999 Kbps，可作為參數調校的參考實作。

BLE

如何進行 OTA 韌體升級？

ipro_ble_remote 範例（apps/bluetooth/ble/ipro_ble_remote）內建 OTA GATT service，提供透過 BLE 傳輸並更新韌體的完整參考實作，可直接套用到自己的應用中。

Debug

macOS 上序列埠 cu.* 和 tty.* 有什麼區別？

在 macOS 上，每個序列裝置都有兩個裝置節點（以下序列埠名稱依實際裝置而定）：

  • /dev/cu.* (Calling Unit) - 必須使用此裝置。不等待 DCD 信號，可直接開啟。
  • /dev/tty.* (Teletype) - 會等待 DCD 信號，導致程式掛起無法使用。
# 正確做法
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX

# 錯誤做法（會掛住）
python3 tools/serial_monitor.py /dev/tty.usbserial-XXXX
Debug

序列埠出現 "Resource busy" 錯誤怎麼辦？

這通常是因為其他程式（包括 stty）正在占用序列埠。解決方法：

  1. 檢查並關閉占用埠的程式：lsof /dev/cu.usbserial-XXXX（序列埠名稱依實際裝置而定）
  2. 避免使用 stty -f，它會保持埠忙碌
  3. 使用 tools/serial_monitor.py 取代 cat 或 screen

serial_monitor.py 使用 Python3 termios，以 O_NOCTTY | O_NONBLOCK 旗標開啟埠，不需要 pyserial 依賴。

如何啟用 Debug Log？

在 .config 中設定：

# 將預設 Log Level 設為 DEBUG
# （choice 符號，對應 CONFIG_LOG_DEFAULT_LEVEL=4）
CONFIG_LOG_DEFAULT_LEVEL_DEBUG=y

# 啟用 BLE Host 詳細 log
CONFIG_BT_DEBUG_LOG=y
Debug

遇到 Hard Fault 如何分析？

Hard Fault 通常由以下原因造成：

  • 空指標存取
  • Stack overflow
  • 非對齊記憶體存取
  • 非法指令
# 使用 addr2line 解析 backtrace
# ELF 檔名包含晶片後綴（如 ipro_ble_remote_IPRO7.elf）
riscv64-unknown-elf-addr2line -e apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.elf 0x12345678
RF

CFO (載波頻率偏移) 過大怎麼調整？

CFO 問題通常有兩個原因：

  1. rf_kcal 未執行： 檢查 RF_CAL_STATE_CTRL 寄存器
  2. XTAL 頻率偏差： 調整 capcode

使用 AON 驅動 API（bsp/drivers/ipro7_soc/std_drv/inc/drv_aon.h）調整 XTAL capcode：

// 調整 XTAL capcode
// CFO 為負值（頻率太低）: 降低 capcode
// CFO 為正值（頻率太高）: 提高 capcode
AON_Set_Xtal_CapCode(70, 70);          // 設定 capcode（in / out）

uint8_t cap = AON_Get_Xtal_CapCode();  // 讀回目前 capcode
RF

TX Power 如何設定？

IPRO7 支援的 TX Power 範圍為 -3dBm ~ +10dBm（1dB step）：

// 參數為目標功率 (dBm)，函式自動選擇最接近的功率表項
rf_set_tx_power(10);   // +10dBm（最大）
rf_set_tx_power(0);    // 0dBm
rf_set_tx_power(-3);   // -3dBm（最小）

更進階的 RF 調校（例如客製功率表）請聯絡原廠取得支援。

RF

IPRO7 支援 Wi-Fi 嗎？

IPRO7 本身不內建 Wi-Fi。需要 Wi-Fi 連網的應用，請透過 IPRO6 companion 晶片（經 SDIO 介面）提供連線能力：IPRO7 作為主控 SoC 負責應用邏輯、BLE 與運算，IPRO6 作為 Wi-Fi 連線晶片。

雙晶片參考設計與相關資料請聯絡原廠取得。

RTOS

SDK 用的是哪個 RTOS？BLE Host 是 Zephyr 嗎？

SDK 以 FreeRTOS 作為作業系統，所有應用程式都以 FreeRTOS 建構：

# 所有應用程式的 .config 都使用
CONFIG_FREERTOS_SUPPORT=y

BLE Host 協定疊（GAP、GATT、L2CAP、SMP、ISO、LE Audio）源自 Zephyr 專案，應用層使用 Zephyr 風格的 bt_* callback API——但它運行在 FreeRTOS 之上，不需要安裝或建構 Zephyr。

# 建構 BLE 應用（FreeRTOS + Zephyr-based BLE Host）
./build_freertos.sh ipro_ble_remote build
RTOS

Task Stack Overflow 如何解決？

增加 Task 的 Stack 大小：

// FreeRTOS
xTaskCreate(
    task_function,
    "TaskName",
    2048,  // 增加 Stack 大小 (words)
    NULL,
    tskIDLE_PRIORITY + 1,
    &task_handle
);

也可以啟用 Stack 監控功能來追蹤使用量。
