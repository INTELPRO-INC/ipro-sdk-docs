AI 與 NPU

IPRO7 的 NPU 提供邊緣推論加速；以下依 V2.1.0 實際附帶的 IPROAI 與 TFLite Micro 範例說明模型格式及整合方式。

本版 AI 功能

本章以 IPRO7 的已附模型與範例為主，包含人物／寵物辨識、手勢分類（剪刀石頭布）、語音及推論效能測試，以及 IPRO7AI EVK 的攝影機＋LCD 範例與 IPRO AI Studio 的板端韌體。先使用範例所搭配的模型建立可重現結果，再調整輸入與後處理。

NPU 與推論執行環境

IPROAI 透過 components/ai/lib/libai.a 提供推論執行環境；公開標頭定義模型載入、輸入／輸出及推論介面。實際的 CPU／NPU 分派、量化方式與算子限制由模型及相容的執行函式庫決定。

不要假設任意 TFLite 模型都能交給 NPU，或所有不支援的算子都會自動轉到 CPU。原生 .inm 與 TFLite Micro 範例使用不同載入路徑；自訂模型需先確認轉換工具、張量形狀、量化參數及算子支援。

模型部署流程

先使用套件內模型及其配套應用。NPU 範例使用 IPROAI .inm 模型；TensorFlow Lite Micro 範例於 CPU 執行 .tflite。套件未附模型轉換工具；ipro7ai_evk_rps 另附其分類模型的訓練腳本（train/）。

ipro_npu_yolo 由 model_inm.S 將 src/person_pet_detect.inm 嵌入韌體。ipro_meeting_poc 預設從 mfg Flash 分割區載入模型，需依應用 README、相容燒錄工具及分割表另外配置，不能只把模型複製到任意檔案系統。

ipro7ai_evk_rps 預設以 src/model_blob.S 將 model/rps_v3.inm 連結進韌體（CONFIG_RPS_EMBED_MODEL=y）。ipro7ai_evk_person_detect 與 ipro7ai_evk_launcher 的模型放在 mfg 分割區，由應用目錄內的 flash.sh 寫入：--full 寫入分割表、韌體與模型，--model 只更換模型。

libai.a 也可從 SD 卡載入模型：iproai_load_model_from_file() 以 FatFS 將整個 .inm 讀入 PSRAM，路徑使用 sd:/（例如 sd:/models/person.inm）。應用需設定 CONFIG_AI_MODEL_FROM_FILE=y 並先掛載卡片；ipro_ai_link、ipro_ai_bench 與 ipro7ai_evk_launcher 的偵測頁使用此方式。

自訂模型請向 INTELPRO 取得相容轉換工具，部署前確認算子、tensor 維度、量化及記憶體需求。

IPROAI 框架

IPROAI 是 IPRO SDK 自研的 AI 推理框架，位於 components/ai/。提供模型載入、層排程、NPU 加速與後處理等完整功能。

核心 API

IPROAI 核心 API (iproai_core.h) 
/* 建立模型實例 */
iproai_model_hdl_t iproai_create(void);

/* 從記憶體緩衝區載入 .inm 模型 */
IPROAI_Status_e iproai_load_model_from_buffer(iproai_model_hdl_t hdl, const uint8_t *buffer);

/* 以 FatFS 從檔案載入 .inm 模型（例如 "sd:/model.inm"） */
IPROAI_Status_e iproai_load_model_from_file(iproai_model_hdl_t hdl, const char *name);

/* 取得模型輸入解析度 */
IPROAI_Status_e iproai_getInputResolution(iproai_model_hdl_t hdl, uint32_t *width, uint32_t *height);

/* 設定來源影像解析度（用於座標映射） */
IPROAI_Status_e iproai_setSourceResolution(iproai_model_hdl_t hdl, uint32_t width, uint32_t height);

/* 取得輸入緩衝區位址（用於填入影像資料） */
uint8_t* iproai_getInputBuffer(iproai_model_hdl_t hdl);

/* 取得輸出緩衝區位址 */
uint8_t* iproai_getOutputBuffer(iproai_model_hdl_t hdl, uint32_t *size);

/* 執行推理（同步，阻塞直到完成） */
IPROAI_Status_e iproai_startCompute(iproai_model_hdl_t hdl);

/* 取得網路資訊（用於後處理） */
struct iproai_net_info_t *iproai_getNetInfo(iproai_model_hdl_t hdl);

/* 設定推理結果回呼 */
IPROAI_Status_e iproai_setResultCB(iproai_model_hdl_t hdl, iproai_inference_cb cb);

/* 釋放模型資源 */
IPROAI_Status_e iproai_free(iproai_model_hdl_t hdl);

使用檔案載入的範例先將模型讀入記憶體，再交由 iproai_load_model_from_buffer() 載入；SD 卡上的模型也可直接以 iproai_load_model_from_file() 載入。請使用隨附的配套模型，並確認應用預期的載入路徑。

Kconfig 設定

.config 相關設定 
CONFIG_AI_SUPPORT=y
CONFIG_USE_PSRAM=y
# 由 SD 卡載入模型的應用另需設定（並啟用 FatFS 與 SD 卡驅動）
CONFIG_AI_MODEL_FROM_FILE=y

Release 元件的 CMake 檔直接連結 components/ai/lib/libai.a，無需另設 PREBUILT 路徑。應用配置無法修改函式庫內部的編譯選項；如需不同配置，請向 INTELPRO 取得相容函式庫。

IPRO AI Studio 板端執行（ipro_ai_link）

apps/test/ipro_ai_link 是 IPRO AI Studio「Run on board」使用的板端韌體。燒錄一次後，更換模型與測試資料、執行推論及取回結果都由主機端下指令，不需重新燒錄。模型與輸入從 SD 卡（FatFS 路徑 sd:/）讀取，推論輸出原樣經 USB 傳回主機。預設配置為 IPRO7 EVB；DEFCONFIG=defconfig_reef 用於 IPRO7AI Reef EVK。IPRO AI Studio 本身不在 SDK 套件內。

ai_mount                  掛載 SD 卡
ai_ls [dir]               列出檔案
ai_load  sd:/model.inm    載入模型
ai_input sd:/input.bin    載入輸入資料
ai_run   [reps]           執行推論
ai_out   [max_bytes]      輸出推論結果
ai_info                   顯示模型資訊

整合與記憶體規劃

以 apps/test/ipro_npu_yolo/ 的 person_pet_detect.inm 與 model_inm.S 為原生模型整合起點；需要檔案載入流程時參考 apps/platform/ipro7_demo/demo/ai/。沿用範例的時脈、PSRAM、影像格式與後處理設定。

IPRO7AI EVK 的攝影機 → ISP → NPU 餵入可參考 components/board/ipro7ai_evk 與 ipro7ai_evk_person_detect：同一時間只交一張影格給 NPU，避免 ISP 覆寫推論中的緩衝區。

檢查 iproai_create()、iproai_load_model_from_buffer() 與 iproai_startCompute() 的結果；失敗時釋放已建立的模型與應用緩衝區。外部影像緩衝區必須在推論結束前保持有效，並符合範例的格式與快取同步要求。

記憶體預算須包含權重、中間張量、輸入影像、後處理與其他任務。量測載入前後及連續推論時的剩餘 heap；不能用固定的「每像素位元組數」推算所有模型。若要睡眠後重用模型，另驗證所選模式的 PSRAM 保留及 NPU 恢復流程。

效能量測與除錯

使用 apps/test/ipro_ai_bench/、ipro_npu_yolo 或 TFLite 測試範例，記錄模型檔案、輸入尺寸、CPU 時脈、編譯設定、heap 用量及重複推論時間。分別量測前處理、推論與後處理，避免把單層運算時間當成端到端延遲。啟用 CONFIG_AI_MODEL_FROM_FILE 時，ipro_ai_bench 另提供 bench_file <path> <w> <h> <c>，量測已掛載 SD 卡上的模型。

偵測門檻、NMS 上限與輸入格式都是模型／範例設定，並非 NPU 的固定規格。增加解析度或更換模型後，重新確認輸出正確性、記憶體峰值與長時間穩定性。

本版連結預編譯 libai.a；應用的 .config 無法重新編譯函式庫內部的 profiling 或 debug 功能。以實際範例輸出為準，需要額外診斷資訊時取得對應的函式庫版本。
