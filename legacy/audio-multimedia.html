音訊與多媒體

IPRO SDK 提供完整的音訊與多媒體功能，涵蓋 LE Audio 藍牙音訊、USB 音訊裝置、攝影機影像處理及視訊串流。本頁面介紹各子系統的架構、API 及參考應用程式。

概述

IPRO7 SoC 整合多種音訊與多媒體硬體加速器，搭配 SDK 軟體堆疊，支援以下功能：

LE Audio

LE Audio (BLE 5.2+)

  • LC3 編解碼器（liblc3）
  • 單播 (CIS) 與廣播 (BIS)
  • BAP / CAP / VCP / MCP 協定
  • Auracast 廣播音訊
USB

USB 音訊 (UAC)

  • USB Audio Class 裝置
  • USB 轉 BLE 音訊橋接
  • CherryUSB 整合
  • 低延遲音訊傳輸
CAM

攝影機與視訊

  • ISP 影像訊號處理
  • MJPEG 硬體編碼
  • UVC USB 攝影機裝置
  • LCD 顯示輸出

LE Audio 音訊管線

LE Audio 是 BLE 5.2 引入的次世代藍牙音訊標準，使用 ISO Channel（等時通道）傳輸音訊資料，取代傳統 Classic Audio 的 A2DP/HFP。

傳送端管線

1
Audio Input
AUADC / I2S PCM 取樣
2
LC3 編碼
音訊編碼 16-320 kbps
3
ISO Channel
CIS 或 BIS 等時通道
4
BLE PHY
2M PHY 無線傳輸

接收端管線

1
BLE PHY
2M PHY 無線接收
2
ISO Channel
CIS 或 BIS 資料重組
3
LC3 解碼
音訊解碼 PCM 還原
4
Audio Output
DAC / I2S 喇叭輸出

關鍵特性

特性說明
編碼器LC3（由 prebuilt 函式庫 liblc3 提供）
位元率16 - 320 kbps（LE Audio 常用 16-124 kbps/聲道）
取樣率8 / 16 / 24 / 32 / 48 kHz
聲道單聲道、立體聲
延遲依串流設定與緩衝量測 端到端
傳輸模式CIS（單播）、BIS（廣播）

下方初始化函式節錄自本版 bap_server.c；能力宣告與回呼由同一檔案提供，請在完整 headset 專案中使用。

單播音訊 (CIS)

Connected Isochronous Stream（CIS）提供點對點的雙向音訊傳輸，適用於耳機、助聽器等需要穩定連線的場景。

CIS 架構

Unicast Server (耳機端)
BAP Acceptor VCP Renderer MCC Client CAP Acceptor
CIS (LC3 Audio Stream)
Unicast Client (手機端)
BAP Initiator VCP Controller MCS Server CAP Initiator

BAP 單播流程

Basic Audio Profile（BAP）負責管理音訊串流的建立與控制，流程如下：

1
Discover PACS
查詢支援的音訊能力
2
PAC Records
回傳編碼器/取樣率
3
Configure ASE
設定音訊串流端點
4
Establish CIS
建立等時通道
5
Enable Stream
啟動音訊傳輸

耳機端範例程式碼

BAP Server 初始化 (apps/bluetooth/le_audio/ipro_le_audio_headset/src/bap_server.c) 
int bap_server_init(void)
{
	int err;
	struct bt_pacs_register_param pacs_param = {
#if defined(CONFIG_BT_PAC_SNK)
		.snk_pac = true,
#endif
#if defined(CONFIG_BT_PAC_SNK_LOC)
		.snk_loc = true,
#endif
	};
	struct bt_bap_unicast_server_register_param server_param = {
		.snk_cnt = CONFIG_BT_ASCS_MAX_ASE_SNK_COUNT,
		.src_cnt = CONFIG_BT_ASCS_MAX_ASE_SRC_COUNT,
	};

	IPRO_LOGI(LOG_TAG, "Initializing BAP Unicast Server");

	/* 1. Register PACS service (must be done before publishing caps) */
	err = bt_pacs_register(&pacs_param);
	if (err != 0 && err != -EALREADY) {
		IPRO_LOGE(LOG_TAG, "Failed to register PACS (err %d)", err);
		return err;
	}
	IPRO_LOGI(LOG_TAG, "PACS service registered");

	/* 2. Register LC3 sink codec capability with PACS */
	err = bt_pacs_cap_register(BT_AUDIO_DIR_SINK, &lc3_sink_cap);
	if (err != 0) {
		IPRO_LOGE(LOG_TAG, "Failed to register sink cap (err %d)", err);
		return err;
	}
	IPRO_LOGI(LOG_TAG, "LC3 sink capability registered");

	/* 3. Set audio location (mono front left for single headset) */
	err = bt_pacs_set_location(BT_AUDIO_DIR_SINK, BT_AUDIO_LOCATION_FRONT_LEFT);
	if (err != 0) {
		IPRO_LOGE(LOG_TAG, "Failed to set sink location (err %d)", err);
		return err;
	}

	/* 4. Set supported and available audio contexts */
	bt_pacs_set_supported_contexts(BT_AUDIO_DIR_SINK,
				       BT_AUDIO_CONTEXT_TYPE_MEDIA |
				       BT_AUDIO_CONTEXT_TYPE_CONVERSATIONAL |
				       BT_AUDIO_CONTEXT_TYPE_UNSPECIFIED);

	bt_pacs_set_available_contexts(BT_AUDIO_DIR_SINK,
				       BT_AUDIO_CONTEXT_TYPE_MEDIA |
				       BT_AUDIO_CONTEXT_TYPE_CONVERSATIONAL |
				       BT_AUDIO_CONTEXT_TYPE_UNSPECIFIED);

	/* 5. Register ASCS ASE instances, then BAP callbacks. */
	err = bt_bap_unicast_server_register(&server_param);
	if (err != 0 && err != -EALREADY) {
		IPRO_LOGE(LOG_TAG, "Failed to register ASCS (err %d)", err);
		return err;
	}

	err = bt_bap_unicast_server_register_cb(&unicast_server_cb);
	if (err != 0) {
		IPRO_LOGE(LOG_TAG, "Failed to register BAP callbacks (err %d)", err);
		return err;
	}

	IPRO_LOGI(LOG_TAG, "BAP Unicast Server initialized successfully");
	return 0;
}

廣播音訊（BIS）

Zephyr 4.4 Host 在 zephyr/bluetooth/audio/bap.h 提供 bt_bap_broadcast_source_* 與 bt_bap_broadcast_sink_* API。控制器需選用 bt54_iso2，並於應用配置啟用對應 BAP 角色。

V2.1.0 的 FreeRTOS 應用未包含獨立 BIS source/sink 參考應用；已隨附的耳機應用供單播開發參考。Zephyr 範例 zephyr/samples/bap_broadcast_source（IPRO7 EVB 廣播 LC3 串流）與 zephyr/samples/bap_broadcast_sink（IPRO7AI EVK 接收並由喇叭播放）提供廣播參考，見 Zephyr RTOS。

音訊協定

LE Audio 定義了多個協作的協定（Profile），共同管理音訊串流的各個面向：

協定全稱功能原始碼
BAP Basic Audio Profile 音訊串流建立與管理（CIS/BIS） ipro_bt_host/upstream/zephyr/subsys/bluetooth/audio/bap_*.c
CAP Common Audio Profile 協調集合音訊操作（左右耳同步） ipro_bt_host/upstream/zephyr/subsys/bluetooth/audio/cap_*.c
VCP Volume Control Profile 音量控制與靜音 ipro_bt_host/upstream/zephyr/subsys/bluetooth/audio/vcp_*.c
MCP Media Control Profile 媒體播放控制（播放/暫停/曲目） ipro_bt_host/upstream/zephyr/subsys/bluetooth/audio/mcc.c, mcs.c
CSIP Coordinated Set Identification Profile 識別裝置集合（如一對耳機） ipro_bt_host/upstream/zephyr/subsys/bluetooth/audio/csip_*.c

LC3 編解碼器

LC3（Low Complexity Communication Codec）是 LE Audio 的必備編解碼器，以較低位元率提供優於 SBC 的音質。SDK 以 prebuilt 函式庫 components/3rdparty/liblc3 提供 LC3 編解碼；ipro_bt_host/upstream/zephyr/subsys/bluetooth/audio/codec.c 負責 LE Audio codec 能力與設定的解析。

  • 取樣率：8 / 16 / 24 / 32 / 48 kHz
  • 位元率：16 - 320 kbps（LE Audio 常用 preset 為每聲道 16 - 124 kbps）
  • 幀長度：LE Audio 標準為 7.5ms 或 10ms；隨附的 liblc3 另支援 2.5ms 與 5ms
  • 聲道：單聲道、立體聲
Opus: 交付包包含 components/3rdparty/opus，供應用音訊編解碼使用。LE Audio ISO 串流使用 LC3。

音訊硬體

IPRO7 SoC 整合多個音訊硬體周邊，透過 HAL 層提供統一的存取介面：

硬體功能HAL 標頭說明
AUADC 音訊 ADC hal_auadc.h 內建音訊類比數位轉換器，直接連接麥克風
DAC 數位類比轉換器 hal_dac.h 音訊輸出至喇叭或耳機
I2S Inter-IC Sound hal_i2s.h 連接外部音訊編解碼晶片的數位音訊介面
DMA 直接記憶體存取 hal_dma.h 零 CPU 負載的音訊資料搬移

音訊硬體資料流

音訊硬體資料路徑 
錄音路徑（輸入）：
  麥克風 → AUADC → DMA → 記憶體緩衝區 → LC3 編碼器 / USB

播放路徑（輸出）：
  LC3 解碼器 / USB → 記憶體緩衝區 → DMA → DAC → 喇叭

外部編解碼器路徑：
  外部 Codec ↔ I2S ↔ DMA ↔ 記憶體緩衝區

Audio Output 抽象層

components/audio 提供統一的音訊輸出抽象層 audio_output，以同一組 API 操作 DAC、I2S、UAC 與 PCM dump 等多種後端，是 LE Audio 參考應用實際使用的輸出介面。同元件另提供 audio_capture（AUADC + DMA 音訊擷取）與 mp3_decoder（MP3 解碼）：

音訊輸出抽象層 (components/audio/include/audio_output.h) 
#include "audio_output.h"

audio_output_cfg_t cfg = {
    .type        = AUDIO_OUTPUT_DAC,            /* DAC / UAC / I2S / DUMP */
    .mode        = AUDIO_OUTPUT_MODE_STREAMING,
    .sample_rate = 48000,
    .channels    = 2,
};

audio_output_t *out = audio_output_create(&cfg);
audio_output_start(out);
audio_output_write(out, pcm, samples);   /* interleaved int16_t PCM */
audio_output_stop(out);
audio_output_destroy(out);

Wi-Fi 與 RTSP 攝影機串流

IPRO7 未內建 Wi-Fi。defconfig_wifi_ipro6s 建置透過插在卡槽上的 IPRO6S FIN 卡（SDIO）連網，並以 RTSP 提供攝影機 MJPEG 串流。SDK 隨附主機端元件 components/network/ipronet_host（SDIO 網路介面）與 components/network/rtsp_server。JP3 設為 2-3 時，可用 fin cycle 重新為 FIN 卡上電。

ipronet_up <ssid> <psk>     啟動 FIN 卡並連線至 AP
rtsp_cam on                  開始串流：rtsp://<ip>:8554/av0_0
rtsp_cam stats               串流統計
rtsp_cam off                 停止串流
V2.1.0 未包含 IPRO6S FIN 卡端的韌體，請洽 INTELPRO 取得。

基本 BLE 選擇 CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"；BLE 5.4 與兩路 ISO 串流（CIS/BIS）選擇 "bt54_iso2"，後者要求 CONFIG_EM_SIZE 至少 32 KB。Host 連線上限不可超過控制器容量；請保留各應用隨附配置。

V2.1.0 的 FreeRTOS 應用未包含獨立 BIS source/sink 應用；Zephyr 廣播範例見上方廣播音訊一節。

PDM 錄音

支援 16 kHz／16-bit 單聲道 PDM 擷取、LC3 串流、SMP 配對儲存與 PDS31 喚醒重連。自 V2.0.1 起邏輯錄音最長 4 小時；實體 PSRAM ring 僅保留 240 秒，需透過 CHUNK_READY／GET_CHUNK 每 30 秒取回一段。覆寫後 GET_AUDIO 只能取得最後 240 秒。

使用隨附的 link2 / bt52、16 KB EM 配置；Host 的 CONFIG_BT_CONN=1 與控制器的兩連線容量不同，請保留完整板型配置，不要強制將兩個數值改成一致。

make -C apps/multimedia/ipro_pdm_mic_demo
make -C apps/multimedia/ipro_pdm_mic_demo BOARD=evk

EVB 輸出位於 build/build_out/；EVK 位於 build_config_evk/build_out/，檔名皆為 ipro_pdm_mic_demo_IPRO7.bin。Android 原始碼位於 tools/android/IproMicDemo/；配套 APK 與測試韌體見 V2.0.1 Release。
