Networking

IPRO7 is the main application SoC in the system, handling application logic, NPU inference, and BLE connectivity. It has no built-in Wi-Fi. IPRO SDK V2.1.0 integrates the lwIP TCP/IP stack and the mbedTLS cryptographic library and provides these network paths on IPRO7:

  • Ethernet — IPRO7 has a built-in Ethernet MAC controller (EMAC, RMII) that pairs with lwIP for wired networking; the reference application is ipro7_demo. ipro_enc28j60_test (ENC28J60 over SPI) is also included.
  • Wi-Fi (IPRO6S as the SDIO radio) — IPRO7 drives an IPRO6S running Wi-Fi firmware over SDIO and presents the link as the lwIP netif iproeth0. The IPRO7 side ships with the SDK: ipro7_sdio_wifi (the SDIO host example for ipronet_host: transport, netif, DHCP, iperf) and, on the IPRO7AI Reef EVK with the IPRO6S FIN card, ipro7ai_reef_demo (defconfig_wifi_ipro6s, with an RTSP camera stream). The IPRO6S-side firmware is not in V2.1.0: ipro6_if_wifi ships with V2.0.1, and the FIN-card firmware is available from INTELPRO.
  • ATBM6162 SDIO module — V2.1.0 includes only the module probe ipro_atbm_probe.

The LTE modem component components/network/lte_modem/ is not included in V2.1.0. IPRO6S builds are not supported in V2.1.0; for development with the IPRO6S on-chip Wi-Fi 6, use V2.0.1. This page covers FreeRTOS applications; Zephyr RTOS has no Ethernet driver yet, and Thread is covered in Matter & Thread.

Overview

TCP/IP Stack

  • lwIP lightweight TCP/IP stack
  • TCP / UDP Socket API (BSD-style)
  • DHCP client and server
  • DNS / SNTP / Ping

Ethernet

  • Built-in Ethernet MAC controller on IPRO7 (RMII)
  • Wired networking with an external PHY
  • Automatic IP via DHCP
  • ENC28J60 (SPI) example also included

Security & Encryption

  • mbedTLS 2.28.2 (TLS 1.2 / DTLS 1.2)
  • X.509 certificate management
  • Hardware-accelerated bignum operations
  • HTTPS / secure IoT communication

Wi-Fi (External SDIO)

  • No built-in Wi-Fi on IPRO7
  • IPRO6S as the SDIO radio (incl. the Reef FIN card)
  • ATBM6162 module probe
  • Data plane into IPRO7's lwIP

Network Configuration

Enable networking features in your application's .config file:

.config - Network Configuration 
# Enable lwIP TCP/IP stack
CONFIG_COMPONENTS_LWIP_ENABLE=y
CONFIG_COMPONENTS_LWIP_APP_ENABLE=y

# Enable ping command (network diagnostics)
CONFIG_PING=y

# Enable Ethernet (EMAC)
CONFIG_ETHERNET=y

# Enable mbedTLS encryption support
CONFIG_COMPONENTS_MBEDTLS_ENABLE=y
Tip: The configuration above matches apps/platform/ipro7_demo in the Release SDK — you can use that project's .config as a starting point.

lwIP Integration

The IPRO SDK integrates lwIP (Lightweight IP) as its TCP/IP stack, providing a standard BSD Socket API that allows developers to use familiar socket programming interfaces.

Socket API Example

TCP Client Connection 
#include <lwip/sockets.h>
#include <lwip/netdb.h>

int tcp_client_example(const char *host, uint16_t port)
{
    struct sockaddr_in server_addr;
    int sock;

    /* Create TCP socket */
    sock = socket(AF_INET, SOCK_STREAM, 0);
    if (sock < 0) {
        printf("Socket creation failed\r\n");
        return -1;
    }

    /* DNS resolve hostname */
    struct hostent *hp = gethostbyname(host);
    if (!hp) {
        printf("DNS resolution failed: %s\r\n", host);
        close(sock);
        return -1;
    }

    /* Connect to server */
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(port);
    memcpy(&server_addr.sin_addr, hp->h_addr, hp->h_length);

    if (connect(sock, (struct sockaddr *)&server_addr,
                sizeof(server_addr)) < 0) {
        printf("Connection failed\r\n");
        close(sock);
        return -1;
    }

    /* Send data */
    const char *msg = "Hello from IPRO7!";
    send(sock, msg, strlen(msg), 0);

    /* Receive response */
    char buf[256];
    int len = recv(sock, buf, sizeof(buf) - 1, 0);
    if (len > 0) {
        buf[len] = '\0';
        printf("Received: %s\r\n", buf);
    }

    close(sock);
    return 0;
}
UDP Send Example 
#include <lwip/sockets.h>

int udp_send_example(const char *dest_ip, uint16_t port)
{
    int sock = socket(AF_INET, SOCK_DGRAM, 0);
    if (sock < 0) return -1;

    struct sockaddr_in dest;
    memset(&dest, 0, sizeof(dest));
    dest.sin_family = AF_INET;
    dest.sin_port = htons(port);
    inet_aton(dest_ip, &dest.sin_addr);

    const char *data = "UDP packet from IPRO7";
    sendto(sock, data, strlen(data), 0,
           (struct sockaddr *)&dest, sizeof(dest));

    close(sock);
    return 0;
}

Ethernet

The IPRO7 features a built-in EMAC (Ethernet MAC) controller. Paired with an external Ethernet PHY over RMII, it provides wired networking suitable for gateways, industrial controllers, and other applications requiring a wired connection. In V2.1.0 this is the network path that needs no external Wi-Fi module.

EMAC Initialization with lwIP 
#include <hal_emac.h>
#include <hal_ethernetif.h>
#include <lwip/tcpip.h>

static struct netif emac_netif;

static void emac_netif_setup(void *arg)
{
    struct netif *netif = (struct netif *)arg;
    ip4_addr_t ipaddr, netmask, gw;

    /* Use DHCP (set addresses to zero) */
    ip_addr_set_zero(&ipaddr);
    ip_addr_set_zero(&netmask);
    ip_addr_set_zero(&gw);

    /* Register network interface */
    netif_add(netif, &ipaddr, &netmask, &gw,
              NULL, ethernetif_init, tcpip_input);
    netif_set_default(netif);
    ethernet_link_status_updated(netif);

    /* Start DHCP client */
    netifapi_dhcp_start(netif);
}

void emac_init(void)
{
    memset(&emac_netif, 0, sizeof(emac_netif));
    tcpip_init(emac_netif_setup, &emac_netif);
}

To enable Ethernet, set CONFIG_ETHERNET=y in your .config. The driver is located at bsp/drivers/ipro7_soc/std_drv/src/drv_emac.c. The reference application apps/platform/ipro7_demo runs the emac_lwip command automatically at boot to perform the flow above.

For boards without an RMII PHY, see apps/test/ipro_enc28j60_test/ (ENC28J60 Ethernet controller over SPI). The example identifies the chip, configures the MAC/PHY and sends and receives raw Ethernet frames from the shell; it does not integrate lwIP. Wiring is in the example's README.

TLS/DTLS (mbedTLS)

The release bundles mbedTLS 2.28.2, enabled by CONFIG_COMPONENTS_MBEDTLS_ENABLE=y. The selected configuration header determines available algorithms. This identifies the bundled version.

For a TLS client, start with the included components/crypto/mbedtls/mbedtls/programs/ssl/ssl_client1.c and adapt the following steps:

  1. Initialize entropy and CTR-DRBG with a working platform entropy source; check every initialization and connection result.
  2. Load the target service’s trusted CA certificates with mbedtls_ssl_conf_ca_chain() and require MBEDTLS_SSL_VERIFY_REQUIRED.
  3. Set the real server name with mbedtls_ssl_set_hostname() and provide correct platform time for certificate validity checks.
  4. Handle MBEDTLS_ERR_SSL_WANT_READ/MBEDTLS_ERR_SSL_WANT_WRITE, partial transfers and timeouts during handshake and I/O; verify the certificate result.
  5. Match the HTTP Host to the connection target, process the response, and release TLS/socket resources on success and every error path.

Replace upstream test certificates and hostnames with your application’s configuration. This is a porting reference; it does not automatically configure board networking or trusted certificates.

HTTP Client

V2.1.0 does not include the high-level components/http_client/ client. Build transport on bundled lwIP and mbedTLS or integrate a compatible HTTP library. Handle HTTP status codes, chunked transfer, size limits and timeouts.

Wi-Fi (IPRO6S as the SDIO Radio)

IPRO7 has no built-in Wi-Fi. components/network/ipronet_host/ is the IPRO7-side SDIO host: through its SDH controller, IPRO7 drives an IPRO6S running Wi-Fi firmware and presents the link as the lwIP netif iproeth0, while IPRO7 owns the IP stack. V2.1.0 includes two IPRO7-side applications:

  • apps/platform/ipro7_sdio_wifi/: the SDIO host example for ipronet_host (transport, netif, DHCP, iperf). The IPRO6S-side firmware ipro6_if_wifi is not in V2.1.0; build it with V2.0.1 or contact INTELPRO.
  • defconfig_wifi_ipro6s of apps/platform/ipro7ai_reef_demo/: with the IPRO6S FIN card in the card slot of the IPRO7AI Reef EVK, adds Wi-Fi and an RTSP camera stream (components/network/rtsp_server/). The firmware for the FIN card is not in V2.1.0 — contact INTELPRO.
./build_freertos.sh ipro7_sdio_wifi build
make -C apps/platform/ipro7ai_reef_demo DEFCONFIG=defconfig_wifi_ipro6s

Outputs: apps/platform/ipro7_sdio_wifi/build/build_out/ipro7_sdio_wifi_IPRO7.bin and apps/platform/ipro7ai_reef_demo/build_wifi_ipro6s/build_out/. Flash the Reef with --chip-variant IPRO7AI and partition_cfg_2M.toml; board settings are in the Hardware Reference. Verify board wiring and the IPRO6S power control before flashing.

ipronet_up <SSID> <PASSWORD>
ipronet_down
rtsp_cam on

Run those commands on the IPRO7 console (115200 baud); rtsp_cam on exists only in the Reef's defconfig_wifi_ipro6s build and starts the camera stream at rtsp://<ip>:8554/av0_0. The API in components/network/ipronet_host/ipronet_host.h provides ipronet_config_default(), ipronet_start() and ipronet_connect(). Wait for on_got_ip before using sockets. Hand work from RX-task callbacks to an application task; do not block or call connection-control APIs there.

ATBM6162 SDIO Module

With an external ATBM6162 Wi-Fi module, IPRO7 is the SDIO host through its SDH controller; the module driver is in components/wireless/wifi_atbm6162/. V2.1.0 includes only the module probe apps/test/ipro_atbm_probe/, which checks module power-up, SDIO enumeration, firmware download and the handshake.

./build_freertos.sh ipro_atbm_probe build

Module power, enable and SDIO wiring depend on the carrier board; check them against the board settings in the probe source before flashing.

IPRO6S Wi-Fi 6 (V2.0.1)

V2.1.0 includes no IPRO6S applications and does not support IPRO6S builds; for standalone networking with the IPRO6S on-chip Wi-Fi 6, use V2.0.1. In V2.0.1, start from apps/platform/ipro6_demo/, whose configuration enables CONFIG_WIFI6=y and CONFIG_USE_MACSW=y.
