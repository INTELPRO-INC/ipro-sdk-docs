Windows Installation & Updates

Set up a development environment with the full installer, or update the SDK and VS Code extension independently.

Online Installer 3.4.0

Use IPRO-SDK-Online-Setup-3.4.0.exe for installation from the public component catalog; no GitHub login is required. It supports Full, SDK, toolchain, build tools, IntelProCube, OpenOCD and Extension modes.

Choose a new destination directory, select components and review their resolved versions before installing. latest follows each package's maintained stable / compatible version, not the newest repository release. Full mode checks declared dependencies; single-component mode does not validate your existing environment.

Checked 2026-10-15: the catalog still lists SDK 1.2.1 as stable and does not register any V2.x release. Selecting latest therefore does not install SDK V2.1.0. Follow the manual V2.1.0 steps below.

Settings and PATH changes are unchecked by default. SDK mode can switch only ipro.sdkRoot; toolchain / build-tools / IntelProCube modes can switch their corresponding paths. OpenOCD mode only installs files; Extension mode optionally installs VSIX. Retain the old directories for rollback.

Start-Process .\IPRO-SDK-Online-Setup-3.4.0.exe -Wait -ArgumentList '/MODE=sdk', '/SDKVERSION=1.2.1', '/DIR="C:\IPRO\versions\sdk-1.2.1-new"', '/TASKS=""'

This example deliberately pins the cataloged SDK 1.2.1 and requires a destination that does not exist. /OFFLINE=1 uses cached metadata / ZIPs (or the initial bundled catalog); it cannot discover new releases while offline. ZIPs are checked against catalog SHA-256 values. Check installation logs if any follow-up step fails.

SDK V2.1.0 Manual Update

Download IPRO-SDK-V2.1.0.tar.gz and its .sha256 from the V2.1.0 Release and extract the archive into a new SDK directory. Verify that VERSION.txt reports V2.1.0, then confirm CMakeLists.txt, apps/ and bsp/ are at the selected root. FreeRTOS applications in V2.1.0 target IPRO7 only; keep V2.0.1 for IPRO6S development.

Get-FileHash .\IPRO-SDK-V2.1.0.tar.gz -Algorithm SHA256
Get-Content .\IPRO-SDK-V2.1.0.tar.gz.sha256

Compare the hash with the downloaded checksum. In Extension 3.3.0, import the extracted folder using IPRO Setup: Update Components, or select the extracted SDK root. The archive importer accepts ZIP; extract .tar.gz first. Reopen the new SDK and run IPRO Setup: Run Diagnostics.

The SDK README specifies GCC 14. The current Windows catalog only declares its GCC 13.1.1 combination for SDK 1.2.1; obtain and validate a toolchain for V2.1.0. With native Windows Make, project.build falls back to the cmake on PATH when the unbundled tools/cmake_win-x86_64/ is absent; check the CMake version on PATH or pass CMAKE= explicitly. Keep your working 1.2.1 installation until the new build and board workflow are verified.

Fixed Installer 3.3.0 (SDK 1.2.1)

The remaining sections describe the older offline full installer and its bundled versions. They are useful for maintaining existing 3.3.0 installations; its SDK-only mode installs the embedded 1.2.1 package.

Before installation

  • Use the package for your Windows x64 or ARM64 host. Select the VSIX architecture for the Windows host running VS Code, not the target RISC-V chip. An ARM64 package does not imply hardware validation of every bundled tool.
  • VS Code 1.102 or later is required. A full installation can download standard VS Code from Microsoft if it is missing; that step requires internet access. Extension-only requires VS Code to be installed first.
  • Choose a writable installation root, defaulting to C:\IPRO. Allow roughly 2 GB for the full environment plus extraction and build space; the SDK alone is about 333 MB.
  • Stop Build, Flash, Debug and Monitor operations. Back up SDK edits, projects and settings before using an existing destination; use a new SDK directory for an upgrade.
  • Installation and the first build do not require a board; flashing and serial validation require the board and a compatible Probe / UART.

First full installation

  1. Run IPRO-SDK-Setup-3.3.0.exe and select an installation root such as C:\IPRO, outside individual SDK projects.
  2. Choose Full installation on the Choose installation mode page.
  3. Select the optional tasks for VS Code, the IPRO extension, ipro.* tool paths and user PATH. Tool paths are generated from the selected installation root.
  4. Review the destination and tasks on Ready to Install, then select Install. Existing SDK files with matching paths may be overwritten.
  5. Wait for copying and post-install steps. If Some steps did not complete appears, check installer\updates\3.3.0\install.log.
  6. Completely close and restart existing VS Code and terminal processes to pick up PATH changes. Open C:\IPRO\sdk\IPRO-IPRO7-SDK-V1.2.1.
  7. Trust the SDK workspace after confirming its source, then run IPRO: Open Control Center and IPRO Setup: Run Diagnostics.

Update only the extension

Choose Extension only in the EXE, or install the VSIX directly:

  1. Keep the previous VSIX and stop builds, flashing and monitoring.
  2. In the target VS Code window, press Ctrl+Shift+X → … → Install from VSIX… and choose the 3.3.0 package for the host architecture.
  3. Run Developer: Reload Window. Search for @installed IPRO in Extensions and check the version of ipro.ipro-sdk-extension.
  4. Run Diagnostics and check the SDK root and tool settings. With Profiles or remote windows, verify that the VSIX was installed in the intended environment.
code --install-extension .\ipro-sdk-extension-win32-x64-3.3.0.vsix

VSIX installation does not copy the SDK or toolchain. To roll back, reinstall a compatible previous VSIX and reload the window.

Update only the SDK

SDK only in the EXE uses its bundled SDK. Choose a new directory name under <installation root>\sdk\<new name>. An existing directory is rejected even if empty.

Set only ipro.sdkRoot… is unchecked by default. Selecting it updates only the user-level SDK root; workspace settings can still take precedence. Use the extension component updater for an external ZIP, extracted folder or Git source.

See the VS Code component update workflow

Tool paths and settings

For the default C:\IPRO installation, the core settings are shown below. Substitute your installation path and merge the relevant fields into existing settings.

{
  "ipro.sdkRoot": "C:\\IPRO\\sdk\\IPRO-IPRO7-SDK-V1.2.1",
  "ipro.toolchainPath": "C:\\IPRO\\toolchain\\riscv_ipro7_win32\\bin\\riscv64-unknown-elf-",
  "ipro.cmakePath": "C:\\IPRO\\tools\\cmake\\bin\\cmake.exe",
  "ipro.ninjaPath": "C:\\IPRO\\tools\\ninja\\ninja.exe",
  "ipro.pythonPath": "C:\\IPRO\\tools\\python\\python.exe",
  "ipro.flashToolPath": "C:\\IPRO\\IntelProCube",
  "ipro.generator": "ninja"
}

ipro.toolchainPath is the compiler prefix including its trailing hyphen. Installer settings target standard VS Code user settings; workspace .vscode/settings.json or another Profile can override them. Check the effective SDK root in Diagnostics after switching.

Verify the installation

& "C:\IPRO\tools\cmake\bin\cmake.exe" --version
& "C:\IPRO\tools\ninja\ninja.exe" --version
& "C:\IPRO\tools\python\python.exe" -c "import serial; print(serial.__version__)"
& "C:\IPRO\toolchain\riscv_ipro7_win32\bin\riscv64-unknown-elf-gcc.exe" --version
  • The SDK root must contain CMakeLists.txt, apps and bsp.
  • Run IPRO: Go to Project…, select ipro7_demo, then run IPRO: Build.
  • Check the actual compiler path and build result in Terminal. The expected BIN is apps\platform\ipro7_demo\build\build_out\ipro7_demo_IPRO7.bin.
  • When using hardware, verify the UART, chip variant, partition table and monitor baud rate. A successful build does not mean the board has been flashed or validated.

Troubleshooting and rollback

SymptomAction
Missing extension / post-install warningRead installer\updates\3.3.0\install.log, check the VS Code location and Profile, then install the VSIX manually.
Settings cannot be parsedKeep the original file, check installer\ipro-settings.json and look for .ipro-backup files next to settings.json before merging settings.
Old SDK still selectedCheck the opened folder, workspace ipro.sdkRoot and user settings, then run Diagnostics.
rules.ninja: lexing errorCheck that ipro.cmakePath / ipro.ninjaPath select the packaged tools; clean and rebuild after correcting them.
SDK update failed / cancelledKeep the update logs and retry using a new directory name; continue using the old SDK until the new one is verified.

To roll back the SDK, reopen the retained version and check its tool paths. Manage individual SDK directories separately; uninstalling the full package is not an SDK rollback and does not also remove VS Code or the extension.
