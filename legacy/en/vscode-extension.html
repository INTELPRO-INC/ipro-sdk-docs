IPRO SDK VS Code Extension

Configure, build, flash and monitor from VS Code, and manage SDK and extension updates independently.

Extension overview

IPRO SDK Extension 3.3.0 (identifier ipro.ipro-sdk-extension) brings FreeRTOS project discovery, CMake builds, IntelProCube flashing, serial monitoring and memory analysis into VS Code. Windows users can start with the complete installer.

This page describes Extension 3.3.0 (VS Code 1.102+). SDK V2.1.0 and Online Installer 3.4.0 are versioned separately; the current catalog still selects SDK 1.2.1. For V2.1.0, download it from the GitHub Release, import its extracted folder and verify toolchain compatibility.

Windows installation and update guide

Install and configure

  1. Use the full EXE for initial Windows setup, or install ipro-sdk-extension-win32-x64-3.3.0.vsix (or its ARM64 counterpart) into an existing tool environment.
  2. Install through Extensions → … → Install from VSIX…, then run Developer: Reload Window.
  3. Use File → Open Folder… to open the SDK root containing CMakeLists.txt, apps and bsp. Enable Workspace Trust after verifying the source.
  4. Use IPRO Setup: Set SDK Root and IPRO Setup: Run Diagnostics to check the environment. The full Windows installer configures ipro.* paths.
code --install-extension .\ipro-sdk-extension-win32-x64-3.3.0.vsix
Full tool settings example

3.x settings use the ipro.* namespace. Replace the devtool.* settings and IPRO SDK: command names from older documentation with the settings and command table on this page.

Control Center

Press F1 → IPRO: Open Control Center. The panel shows the active SDK / project, UART and configured / actual monitor baud rate, and enables actions according to session state. Opening the panel does not flash or reset the board.

Supports light, dark and high-contrast themes, narrow editors and keyboard focus. Animations can be paused and follow reduced-motion preferences.

First build

  1. Run IPRO: Go to Project… and select ipro7_demo in the platform category.
  2. Run IPRO Config: Select Build Profile and choose debug, release or size.
  3. Run IPRO Setup: Run Diagnostics and check the effective SDK, compiler, CMake, Ninja and Python paths.
  4. Run IPRO: Build and watch Terminal for the result; use Problems to navigate to diagnostics.
  5. Confirm that BIN and ELF outputs were produced. Clean and rebuild after changing SDK or tool paths to avoid stale caches.
apps/platform/ipro7_demo/build/build_out/ipro7_demo_IPRO7.bin

The installer selects Ninja; ipro.generator also supports auto, make or ninja. IPRO: Batch Build builds multiple selected projects.

Flashing, UART and monitoring

  1. Use IPRO Setup: Select Flash Tool to select IntelProCube, or set ipro.flashToolPath to C:\IPRO\IntelProCube.
  2. Connect the board and run IPRO: Select Serial Port to select the Probe UART. The CCI port is for register access, not console or flashing.
  3. Use IPRO Config: Configure Flash… to check the chip variant, flash target, partition table and baud rate against the actual board.
  4. Run IPRO: Flash and confirm the tool verification and success messages. The extension releases its own monitor before flashing; close any other program holding the port.
  5. Set the firmware console rate with IPRO Config: Set Monitor Baud Rate, then run IPRO: Serial Monitor. After changing the rate, close and reopen the monitor or use the offered reconnect action.
SettingMeaning
ipro.baudRateFlash transfer rate; default 921600
ipro.monitorBaudRateConsole rate; default 115200, must match the firmware
ipro.chipVariantBoard flash configuration, independent of the build profile
Since 3.2.0, the extension uses its own serialport console. Windows monitoring does not depend on the SDK POSIX serial_monitor.py script and does not automatically reboot on opening. Use IPRO: Reset Board or the firmware console reboot command when needed.

Memory and debug tools

After building, run IPRO Analyse: Memory Map to inspect regions, component usage and changes between builds, with CSV / Markdown export. Compare capacity decisions with linker output and the actual partition table.

IPRO Analyse: Decode Crash Report maps exception backtraces to source locations; IPRO Debug: Pin Function Lookup searches pins. Register Explorer requires a compatible Probe, a working CCI link and board configuration. Extension 3.3.0 does not provide a general GDB debug adapter; installing OpenOCD alone does not enable source debugging with F5.

Independent component updates

Extension 3.3.0 provides F1 → IPRO Setup: Update Components, also accessible from Control Center.

SourceBehavior
Extension VSIXSelect the VSIX and reload the window after installation; the SDK and tools are not updated.
SDK ZIPSelect a ZIP, optionally provide the vendor SHA-256, then extract and validate the SDK structure.
SDK FolderSelect an extracted root containing CMakeLists.txt, apps and bsp; extract .tar.gz / .7z first.
SDK GitCreate a snapshot from an authorized HTTPS / SSH repository and branch / tag, recording its commit; configure SSH trust and authentication beforehand.
  1. After choosing a source, select the parent storage directory and a new version name that does not already exist.
  2. Confirm the source and destination; Output → IPRO SDK shows progress and logs.
  3. On completion, optionally open the SDK in a new window. The SDK root, toolchain and original window are not automatically switched.
  4. Run Diagnostics and build an official example before migrating personal changes; retain the old SDK for rollback.
C:\IPRO\sdk\<version-name>\
  sdk\          SDK root: CMakeLists.txt, apps, bsp
  update.json   Source, timestamp, checksum / Git commit
  update.log    Update result

For VS Code imports, the SDK root is the sdk\ child of the version directory; EXE SDK-only uses the selected new directory directly. Failed or cancelled imports retain the incomplete directory and logs; retry with a new name. Git imports are snapshots rather than working trees for subsequent pulls; submodules, unresolved LFS pointers and symbolic links are unsupported, and toolchains are not updated automatically.

Troubleshooting

SymptomAction
IPRO commands are missingCheck the VSIX version, Profile, Workspace Trust and SDK root, then reload the window.

Garbled monitor / old baud rateCheck the firmware console rate and ipro.monitorBaudRate, then close and reopen the monitor.
Probe detected but CCI does not workUSB pairing does not prove DUT CCI communication; check wiring and board configuration separately.
Flash tool not foundUse IPRO Setup: Select Flash Tool and verify that IntelProCube contains ipro_iot_tool.exe.

IntelProCube and command line

C:\IPRO\IntelProCube\IProCube.exe is the GUI tool. ipro_iot_tool.exe provides command-line flashing, while ipro_ota_creator.exe and ipro_ota_update_tool.exe create and apply OTA packages. The GUI manual is IntelProCube\docs\USER_GUIDE.html.

& "C:\IPRO\IntelProCube\ipro_iot_tool.exe" --help

Use the tool version’s --help and the actual board configuration when forming commands. Native Windows development can use the extension CMake / Ninja workflow; build_freertos.sh is the SDK Bash entry point.

Versions and delivery scope

3.3.0 adds independent component updates; 3.2.4 introduced Control Center; 3.2.3 improved monitor / flash port handover and UART / CCI selection; 3.2.2 added a separate monitor baud setting; 3.2.1 pinned Windows tool paths; 3.2.0 introduced the built-in serialport monitor.

The SDK source package, extension VSIX and full Windows installer are versioned separately. A standalone SDK without a VSIX does not mean the full Windows installer omits the extension; check the delivered manifest and the installed version in Extensions.

SDK V2.1.0

Download IPRO-SDK-V2.1.0.tar.gz and its .sha256 from the V2.1.0 Release and extract the archive into a new SDK directory. Verify that VERSION.txt reports V2.1.0, then confirm CMakeLists.txt, apps/ and bsp/ are at the selected root. FreeRTOS applications in V2.1.0 target IPRO7 only; keep V2.0.1 for IPRO6S development.

Get-FileHash .\IPRO-SDK-V2.1.0.tar.gz -Algorithm SHA256
Get-Content .\IPRO-SDK-V2.1.0.tar.gz.sha256

Compare the hash with the downloaded checksum. In Extension 3.3.0, import the extracted folder using IPRO Setup: Update Components, or select the extracted SDK root. The archive importer accepts ZIP; extract .tar.gz first. Reopen the new SDK and run IPRO Setup: Run Diagnostics.

The SDK README specifies GCC 14. The current Windows catalog only declares its GCC 13.1.1 combination for SDK 1.2.1; obtain and validate a toolchain for V2.1.0. With native Windows Make, project.build falls back to the cmake on PATH when the unbundled tools/cmake_win-x86_64/ is absent; check the CMake version on PATH or pass CMAKE= explicitly. Keep your working 1.2.1 installation until the new build and board workflow are verified.
