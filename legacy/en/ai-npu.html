AI & NPU

V2.1.0 includes the prebuilt AI runtime components/ai/lib/libai.a, public headers, example sources, selected .inm / .tflite models and the model training scripts of ipro7ai_evk_rps. AI runtime implementation sources and model conversion tools are separate. Choose a model supported by the example; changing its extension does not convert it.

The IPRO7 NPU accelerates edge inference. The following sections describe model formats and integration using the IPROAI and TFLite Micro examples actually included in V2.1.0.

AI in This Release

This chapter covers bundled IPRO7 models and examples for person/pet detection, gesture classification (rock-paper-scissors), speech and inference benchmarks, plus the IPRO7AI EVK camera + LCD examples and the board firmware for IPRO AI Studio. Reproduce an example with its matching model before changing input processing or post-processing.

NPU and Inference Runtime

IPROAI provides inference through components/ai/lib/libai.a. Public headers define model loading, input/output and execution interfaces. CPU/NPU dispatch, quantization and operator constraints depend on the model and compatible runtime.

Do not assume arbitrary TFLite models run on the NPU or that every unsupported operator falls back to the CPU. Native .inm and TFLite Micro examples use different loading paths. Confirm conversion tooling, tensor shapes, quantization and operator support for custom models.

Model Deployment

Start with a bundled model and its matching application. NPU examples use IPROAI .inm binaries; TensorFlow Lite Micro examples execute .tflite models on the CPU. Model conversion tools are not bundled; ipro7ai_evk_rps includes the training scripts for its classifier (train/).

ipro_npu_yolo embeds src/person_pet_detect.inm through model_inm.S. ipro_meeting_poc defaults to loading a model from the mfg flash partition. Provision that model separately using the application README and the matching flash tool / partition layout; copying it onto an arbitrary filesystem is insufficient.

ipro7ai_evk_rps links model/rps_v3.inm into the firmware through src/model_blob.S by default (CONFIG_RPS_EMBED_MODEL=y). ipro7ai_evk_person_detect and ipro7ai_evk_launcher keep their models in the mfg partition, written by the flash.sh in the application directory: --full writes the partition table, firmware and model; --model replaces only the model.

libai.a can also load models from the SD card: iproai_load_model_from_file() reads a whole .inm into PSRAM through FatFS, using sd:/ paths (for example sd:/models/person.inm). The application sets CONFIG_AI_MODEL_FROM_FILE=y and mounts the card first; ipro_ai_link, ipro_ai_bench and the detection page of ipro7ai_evk_launcher use this path.

For custom models, obtain a compatible converter from INTELPRO and verify operators, tensor dimensions, quantization and memory requirements before deployment.

IPROAI Framework

IPROAI is the custom AI inference framework in the IPRO SDK, located at components/ai/. It provides model loading, layer scheduling, NPU acceleration, and post-processing capabilities.

Core API

IPROAI Core API (iproai_core.h) 
/* Create a model instance */
iproai_model_hdl_t iproai_create(void);

/* Load the matching .inm model from a memory buffer */
IPROAI_Status_e iproai_load_model_from_buffer(iproai_model_hdl_t hdl, const uint8_t *buffer);

/* Load an .inm model from a file through FatFS (e.g. "sd:/model.inm") */
IPROAI_Status_e iproai_load_model_from_file(iproai_model_hdl_t hdl, const char *name);

/* Get model input resolution */
IPROAI_Status_e iproai_getInputResolution(iproai_model_hdl_t hdl, uint32_t *width, uint32_t *height);

/* Set source image resolution (for coordinate mapping) */
IPROAI_Status_e iproai_setSourceResolution(iproai_model_hdl_t hdl, uint32_t width, uint32_t height);

/* Get input buffer address (for filling image data) */
uint8_t* iproai_getInputBuffer(iproai_model_hdl_t hdl);

/* Get output buffer address */
uint8_t* iproai_getOutputBuffer(iproai_model_hdl_t hdl, uint32_t *size);

/* Run inference (synchronous, blocks until completion) */
IPROAI_Status_e iproai_startCompute(iproai_model_hdl_t hdl);

/* Get network info (for post-processing) */
struct iproai_net_info_t *iproai_getNetInfo(iproai_model_hdl_t hdl);

/* Set inference result callback */
IPROAI_Status_e iproai_setResultCB(iproai_model_hdl_t hdl, iproai_inference_cb cb);

/* Free model resources */
IPROAI_Status_e iproai_free(iproai_model_hdl_t hdl);

The examples load the model using filesystem APIs, then pass its buffer to iproai_load_model_from_buffer(); a model on the SD card can also be loaded directly with iproai_load_model_from_file(). Use the matching bundled model and verify the application's loading path.

Kconfig Options

.config Settings 
CONFIG_AI_SUPPORT=y
CONFIG_USE_PSRAM=y
# Additionally, for applications that load models from the SD card
# (with FatFS and the SD card driver enabled)
CONFIG_AI_MODEL_FROM_FILE=y

The release component CMake file links components/ai/lib/libai.a directly. No separate PREBUILT path setting is required. Library-internal options cannot be changed by application configuration; use a compatible library supplied by INTELPRO.

IPRO AI Studio Run on Board (ipro_ai_link)

apps/test/ipro_ai_link is the board firmware behind IPRO AI Studio "Run on board". Flash it once; changing models and test data, running inference and collecting results are then driven from the host without reflashing. Models and inputs are read from the SD card (FatFS path sd:/) and the raw inference output is sent back to the host over USB. The default configuration targets the IPRO7 EVB; DEFCONFIG=defconfig_reef targets the IPRO7AI Reef EVK. IPRO AI Studio itself is not part of the SDK package.

ai_mount                  mount the SD card
ai_ls [dir]               list files
ai_load  sd:/model.inm    load a model
ai_input sd:/input.bin    load input data
ai_run   [reps]           run inference
ai_out   [max_bytes]      print the inference output
ai_info                   show model information

Integration and Memory Planning

For native model integration, start with person_pet_detect.inm and model_inm.S in apps/test/ipro_npu_yolo/. For file-based loading, see apps/platform/ipro7_demo/demo/ai/. Preserve the example’s clock, PSRAM, image format and post-processing configuration.

For the IPRO7AI EVK camera → ISP → NPU feed, see components/board/ipro7ai_evk and ipro7ai_evk_person_detect: only one frame is handed to the NPU at a time, so the ISP never overwrites a buffer under inference.

Check results from iproai_create(), iproai_load_model_from_buffer() and iproai_startCompute(). Release allocated models and application buffers on failure. Keep external image buffers valid until inference completes and follow the example’s format and cache synchronization requirements.

Budget for weights, intermediate tensors, input images, post-processing and other tasks. Measure free heap before/after loading and during repeated inference; a fixed bytes-per-pixel formula is not valid for all models. Reusing a model after sleep also requires verifying PSRAM retention and NPU restoration for that mode.

Performance Measurement and Debugging

Use apps/test/ipro_ai_bench/, ipro_npu_yolo or the TFLite test examples. Record the model file, input dimensions, CPU clock, build configuration, heap use and repeated inference timings. Measure preprocessing, inference and post-processing separately; per-layer timings do not represent end-to-end latency. With CONFIG_AI_MODEL_FROM_FILE enabled, ipro_ai_bench also provides bench_file <path> <w> <h> <c> to time a model on a mounted SD card.

Detection thresholds, NMS limits and input format are model/example settings, not fixed NPU specifications. After changing resolution or models, recheck output correctness, peak memory use and sustained operation.

This release links prebuilt libai.a. Application .config settings cannot rebuild profiling or debug features inside that archive. Use the output available in the example and obtain a matching diagnostic library when additional detail is needed.

Cloud AI Availability

components/ai_client/ and cloud-agent reference applications are not included in V2.1.0. Contact INTELPRO for availability. For released on-device inference, use the NPU and TFLM examples above. Network clients can build on the bundled lwIP and mbedTLS components.
