Getting Started

This guide will walk you through setting up the IPRO SDK Release package and building your first application.

Release SDK Notice: The source archive omits the flash tool (the IntelProCube v0.6.3 command-line tool is obtained separately), the board_test.sh board-test script and the VS Code extension; the tools/serial_monitor.py serial console reader is included from V2.1.0. For separately versioned Windows tools, see Installation & Updates.

Online Installer 3.4.0 reads the component catalog; the fixed 3.3.0 installer bundles SDK 1.2.1. The catalog still selects SDK 1.2.1 and does not install V2.1.0. Download V2.1.0 from its GitHub Release and select its extracted directory explicitly. Installation and version selection

SDK V2.1.0

Download IPRO-SDK-V2.1.0 (2026-10-16): the release provides IPRO-SDK-V2.1.0.tar.gz and its .sha256 checksum; the source is also on the main branch of the GitHub repository. The package contains 35 IPRO7 applications (IPRO7 EVB, IPRO7AI EVK, IPRO7AI Reef EVK); use the shipped configuration for your board.

New in this release: Zephyr RTOS support (see Zephyr RTOS); six applications ipro7ai_reef_demo, ipro7ai_evk_launcher, ipro7ai_evk_person_detect, ipro7ai_evk_rps, ipro_ai_link and ipro7_uvc_cam; and tools/serial_monitor.py, tools/zephyr/ and tools/create_ota.py. Not included in this release: Matter, Thread for FreeRTOS applications (Thread is available under Zephyr only) and model conversion tools.

IPRO6S: V2.1.0 does not support IPRO6S and ships no IPRO6S applications or IPRO6S BLE controller libraries. For IPRO6S development (BR/EDR, on-chip Wi-Fi 6, IPRO6S EVB) use V2.0.1.

Extract IPRO-SDK-V2.1.0.tar.gz into a new directory and verify VERSION.txt. Obtain the matching RISC-V toolchain separately; the release README specifies GCC 14. The catalog's Windows GCC 13.1.1 package is declared for SDK 1.2.1, so do not assume that declaration covers 2.1.0.

Prerequisites

Before starting, ensure your development environment meets the following requirements:

Hardware Requirements

  • IPRO7 development board: IPRO7 EVB, IPRO7AI EVK or IPRO7AI Reef EVK
  • USB Cable (for flashing and serial communication)
IPRO7AI Reef EVK: The board has 2 MB of flash; flash it with a 2 MB partition table (e.g. partition_cfg_2M.toml; use the one the application README names). Fit jumper JP1 before power-up. Most applications select the Reef with DEFCONFIG=defconfig_reef* or carry a Reef .config (e.g. ipro7ai_reef_demo).

Software Requirements

  • Operating System: Linux (Ubuntu 20.04+ recommended) or macOS
  • Toolchain: RISC-V GCC Cross Compiler (/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-*)
  • Build Tools: CMake 3.19+, Ninja, Make
  • Python: Python 3.8+ (for development tools and scripts)
  • tar: For extracting the SDK release package
  • Zephyr (optional): Python 3.10+, CMake 3.20+, Ninja, git, dtc; see Zephyr RTOS
Install Basic Tools (Ubuntu/Debian) 
# Install build tools
sudo apt update
sudo apt install -y cmake ninja-build python3 python3-pip git

# Verify installation
cmake --version
ninja --version
python3 --version
Install Basic Tools (macOS) 
# Install via Homebrew
brew install cmake ninja python3 git

# Verify installation
cmake --version
ninja --version
python3 --version

Installation

1. Extract the Release SDK Package

Note: This is the Release version of the SDK package; you do not need Git to obtain the source code. Download the package and its .sha256 checksum from the GitHub Release, verify it, then extract it.
Extract Release SDK 
# Verify and extract the SDK release package (on Linux: sha256sum -c)
shasum -a 256 -c IPRO-SDK-V2.1.0.tar.gz.sha256
tar xzf IPRO-SDK-V2.1.0.tar.gz

# Enter the extracted release directory
cd IPRO-SDK-V2.1.0
cat VERSION.txt

2. Setup Toolchain

IPRO SDK uses a RISC-V cross compiler. The default path is /opt/toolchain/riscv_ipro7/.

Verify Toolchain 
# Verify toolchain exists
ls /opt/toolchain/riscv_ipro7/bin/

# You should see files like:
# riscv64-unknown-elf-gcc
# riscv64-unknown-elf-g++
# riscv64-unknown-elf-objcopy
# ...

# Verify the compiler runs
/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-gcc --version
Note: If your toolchain is in a different location, specify the CROSS_COMPILE parameter during build, e.g.: CROSS_COMPILE=/your/path/bin/riscv64-unknown-elf-.

Quick Start Build

FreeRTOS is the SDK's main development path; all 35 applications in V2.1.0 build with FreeRTOS.

Use Make Build (Recommended)

Make Build 
# Build BLE Remote application
make -C apps/bluetooth/ble/ipro_ble_remote

# Build LE Audio Headset application
make -C apps/bluetooth/le_audio/ipro_le_audio_headset

# Build IPRO7 Demo application
make -C apps/platform/ipro7_demo

# Build the IPRO7AI Reef EVK demo
make -C apps/platform/ipro7ai_reef_demo

# Select an alternate configuration with DEFCONFIG (output in build_<name>/)
make -C apps/multimedia/ipro7_uvc_cam DEFCONFIG=defconfig_reef_ov5640

# Clean build
make -C apps/bluetooth/ble/ipro_ble_remote clean

Use Build Script

FreeRTOS Build Script 
# List all buildable projects
./build_freertos.sh -l

# Build BLE Remote application
./build_freertos.sh ipro_ble_remote build

# Build IPRO7 Demo application
./build_freertos.sh ipro7_demo build

Manual CMake Build

CMake Build Commands 
# Configure project (nested apps require CONFIG_APP_CATEGORY)
cmake -S . -B apps/bluetooth/ble/ipro_ble_remote/build \
    -G "Ninja" \
    -DIPRO_SDK_BASE=$(pwd) \
    -DCONFIG_BUILD_PORJECT=ipro_ble_remote \
    -DCONFIG_APP_CATEGORY=bluetooth/ble \
    -DCMAKE_PREFIX_PATH=$(pwd)/cmake \
    -DCUSTOM_CONFIG_DIR=$(pwd)/apps/bluetooth/ble/ipro_ble_remote \
    -DCONFIG_APPS=1 \
    -DCROSS_COMPILE=/opt/toolchain/riscv_ipro7/bin/riscv64-unknown-elf-

# Execute build
cmake --build apps/bluetooth/ble/ipro_ble_remote/build

Zephyr RTOS Quick Start

From V2.1.0 the SDK is also a Zephyr v4.4.0 module (zephyr/module.yml); west.yml at the SDK root makes it the west manifest repository. Supported boards are ipro7_evb (IPRO7 EVB) and ipro7ai_evk (IPRO7AI EVK); there is no Zephyr board definition for the IPRO7AI Reef EVK in this release.

Zephyr Build and Flash 
tools/zephyr/bootstrap.sh          # west workspace in zephyr-workspace/
source zephyr-workspace/env.sh     # ZEPHYR_BASE, CROSS_COMPILE, west
cd zephyr-workspace
west build -b ipro7_evb zephyr/samples/hello_world
west build -b ipro7_evb ../zephyr/samples/periph_smoke -d build/smoke
west flash                         # IntelProCube CLI: $IPRO_FLASH_TOOL or on PATH

The first bootstrap downloads Zephyr v4.4.0 and the modules west.yml lists from GitHub. It needs Python 3.10+, CMake 3.20+, Ninja, git, dtc and the IPRO RISC-V toolchain (/opt/toolchain/riscv_ipro7; override with IPRO_TOOLCHAIN). The Zephyr console runs at 2,000,000 baud on UART0. Zephyr in this release provides no low-power modes and no display, camera, audio codec, USB, SD host, Ethernet or NPU drivers; use FreeRTOS for those. See Zephyr RTOS for the full guide.

Kconfig Configuration System

The SDK uses a Linux kernel-style Kconfig system to manage project configuration. Each application has its own .config file, and the build system automatically generates a generated/autoconf.h header file.

Configuration File Hierarchy

  • Root config: Kconfig - aggregates all option definitions (pulls in lower-level Kconfig files via source)
  • Per-layer option definitions: bsp/Kconfig and components/Kconfig - option definitions for the BSP and middleware components
  • App config: apps/<category>/<project>/.config - the complete build configuration for each application, from which generated/autoconf.h is generated at build time
  • Alternate configurations: some applications also carry defconfig_<name> or config_<board> files, selected with make DEFCONFIG=defconfig_<name> (output in build_<name>/) or make BOARD=<board>; most applications select the IPRO7AI Reef EVK with defconfig_reef*

Common Configuration Options

.config Example 
# SoC selection
CONFIG_IPRO7=y
CONFIG_CPU_ID="intelpro_ipro7"

# RTOS selection
CONFIG_FREERTOS_SUPPORT=y

# Wireless features
CONFIG_BLUETOOTH_LE_ENABLE=y

# BLE controller prebuilt library variant selection
CONFIG_BT_CTLR_IPRO=y
CONFIG_BT_HOST_IPRO_V44=y
CONFIG_IPRO_BLE_CTLR_LIB="link2"
CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"
CONFIG_IPRO_BLE_CTLR_CFG_DBG=n
CONFIG_BT_CONN=2
CONFIG_EM_SIZE=32

# Component enables
CONFIG_COMPONENTS_LWIP_ENABLE=y
CONFIG_COMPONENTS_MBEDTLS_ENABLE=y
Tip: CONFIG_CPU_ID must be correctly set in .config for the toolchain to detect the proper architecture flags. cmake/toolchain.cmake auto-detects vendor GCC vs standard GCC and adjusts compiler flags accordingly.

Flashing Firmware

Release SDK Notice: The flash tool and the automated test script board_test.sh are not included in this Release SDK package. Flashing uses the command-line tool of IntelProCube v0.6.3 (ipro_iot_tool.exe, ipro_iot_tool_macos or ipro_iot_tool_linux); contact INTELPRO to obtain it.

Flashing with the IntelProCube CLI

Flash Commands 
# IPRO7 EVB (--chip-variant IPRO7)
ipro_iot_tool_macos --chipname ipro7 --chip-variant IPRO7 --port /dev/cu.usbserial-XXXX \
    --baudrate 2000000 --firmware apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.bin

# IPRO7AI Reef EVK (--chip-variant IPRO7AI; run from the IntelProCube directory, 2 MB partition table)
ipro_iot_tool_macos --chipname ipro7 --chip-variant IPRO7AI --port /dev/cu.usbserial-XXXX \
    --baudrate 921600 --pt chips/ipro7/partition/partition_cfg_2M.toml \
    --firmware <SDK>/apps/platform/ipro7ai_reef_demo/build/build_out/ipro7ai_reef_demo_IPRO7.bin
  • The tool has no --flash-pin option: --chip-variant IPRO7 selects flash_pin 0x2 and IPRO7AI selects 0x9 (IPRO7AI EVK and Reef), written to chips/ipro7/eflash_loader/eflash_loader_cfg.ini in the IntelProCube directory.
  • The tool exits 0 even when flashing fails; look for [All Success] in its output.
  • ./build_freertos.sh <project> flash calls this tool: set IPRO_FLASH_TOOL to it, or put its directory on PATH.

Serial Port Tips (General Knowledge)

macOS Note: Serial ports must use /dev/cu.* devices, not /dev/tty.*. The tty.* devices block waiting for the DCD signal. Linux users should use /dev/ttyUSB0 or similar devices.

Serial Monitoring

V2.1.0 includes tools/serial_monitor.py (built on the Python standard-library termios module; no pyserial needed), which the monitor and test actions of build_freertos.sh use. You can also run it directly:

serial_monitor.py 
# Monitor the console (--baud defaults to 115200; match the app's CONFIG_PLATFORM_UART_BAUDRATE)
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --baud 115200 --timeout 60

# Send a command, then monitor and wait for a pattern (regex)
python3 tools/serial_monitor.py /dev/cu.usbserial-XXXX --send reboot --wait-for "ALL TESTS PASSED|SOME TESTS FAILED"

Console baud rate: each app's .config sets CONFIG_PLATFORM_UART_BAUDRATE (115200 when unset). Most apps use 115200; ipro7ai_evk_demo, ipro7ai_evk_launcher, ipro7ai_evk_rps, ipro_meeting_poc, ipro7_uvc_cam and ipro_epd_el036 use 921600. The Reef console is on the U6 connector; Zephyr images use 2,000,000 on UART0. On macOS use /dev/cu.*. Stop monitoring before flashing to release the port. The extension's IPRO: Serial Monitor or any serial terminal also works.

Board Testing

The SDK includes apps/test/ipro_unit_test/ for HAL and shared-component tests; it prints ALL TESTS PASSED or SOME TESTS FAILED on the console.

make -C apps/test/ipro_unit_test

# Build + flash + monitor and evaluate the result (needs the IntelProCube CLI)
./build_freertos.sh test ipro_unit_test -p /dev/cu.usbserial-XXXX

The test action builds, flashes, then waits for the result with the bundled tools/serial_monitor.py; exit code 0 means pass, 1 fail, 2 timeout. The flash tool is obtained separately, and tools/board_test.sh is not bundled.

Debugging Setup

Using GDB

Start GDB Debugging 
# Use RISC-V GDB for debugging (the ELF name includes the chip suffix)

    apps/bluetooth/ble/ipro_ble_remote/build/build_out/ipro_ble_remote_IPRO7.elf

Serial Debugging

Most applications support real-time debugging via serial CLI. After connecting to the serial port, use the following commands:

  • reboot - Normal reset
  • reboot_dl - Enter download mode (for reflashing)
Note: Install the VS Code extension separately. Follow the Extension guide to configure SDK, toolchain and debugger paths.

Troubleshooting

macOS Serial Port Issues (General Knowledge)

Note: V2.1.0 includes tools/serial_monitor.py; an external serial terminal also works.
Problem Solution
Serial connection unresponsive or blocked Use /dev/cu.* instead of /dev/tty.*. The tty.* devices block waiting for the DCD signal.
cat command shows no output cat has buffering issues with serial ports on macOS. Use tools/serial_monitor.py or a dedicated serial terminal tool (e.g., minicom, screen, or picocom) instead.
Serial port shows "Resource busy" Ensure no other program is using the port (e.g., stty, other serial monitors). Try unplugging and replugging the USB cable if needed.

Toolchain Issues

Problem Solution
Toolchain not found Verify that /opt/toolchain/riscv_ipro7/bin/ exists and contains riscv64-unknown-elf-gcc.
Toolchain in a different path Set the CROSS_COMPILE environment variable to point to the correct path.

Build Errors

Problem Solution
Architecture flag detection fails Ensure CONFIG_CPU_ID is correctly set to "intelpro_ipro7" in the .config file.
CMake configuration errors Try cleaning the build directory: make -C apps/<project> clean, then rebuild.
The bundled tools/cmake/ does not run on macOS The bundled CMake is a Linux x86-64 build. Install CMake 3.19+ for your host OS (3.20+ for Zephyr) and put it on PATH.
