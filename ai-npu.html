AI 與 NPU

IPRO7AI 內建 0.1 TOPS 神經網路處理器 (NPU)，專為邊緣 AI 推理設計。搭配 IPROAI 推理框架與 YOLOv8 後處理引擎，可在低功耗環境下實現物件偵測、影像分類與關鍵字辨識等應用。

功能概覽

IPRO SDK 提供 AI 推理 API 與整合範例；模型與轉換工具需另行取得：

NPU

硬體加速

  • 0.1 TOPS 峰值算力
  • INT8 量化推理
  • CPU + NPU 混合排程
  • DMA 直接記憶體存取
AI

IPROAI 框架

  • 支援 SD 卡 / Flash 載入

  • 人形 + 寵物偵測
  • 人臉偵測 (Face Detection)
  • PIR + AI 智慧攝影機

NPU 架構

IPRO7 的 NPU 與 RISC-V CPU 協同工作，支援 CPU 與 NPU 混合執行模式。每一層 (layer) 可依據其算子類型自動分配至最佳執行裝置：

AI 系統架構
Application Layer
ipro7_demo Custom App
IPROAI Framework (components/ai/)
iproai_core — Model Load iproai_inst — Layer Sched postprocess — YOLOv8 / NMS
Execution Backend
CPU Backend：Softmax, YOLO, Route, Reshape, NMSIS DSP Ops NPU Backend：Conv, Pool, FC, DW-Conv, MatMul, Activation (HW)
Memory / DMA Interface
PSRAM (8 MB) OCRAM (256 KB) Flash

支援的算子

NPU 硬體加速支援以下算子，其餘算子由 CPU 端 fallback 執行：

執行端 支援算子
NPU Convolution, Depthwise Conv, MaxPool, AvgPool, Fully Connected, MatMul, Activation (ReLU/ReLU6/Leaky)
CPU Softmax, YOLO, Route, Shortcut, Upsample, Reshape, Transpose, Pad, ArgMax, Resize Bilinear, SSD, Gather, Mean, Dequantize
Activation Leaky, ReLU, Linear, ReLU6, Mish, ELU, Logistic, Swish, GELU, Tanh, PReLU

量化格式

IPROAI 使用 INT8 定點 (fixed_point_t = int8_t) 進行推理。支援 TFLite 風格的 per-channel 量化參數（multiplier + shift），可直接從 TensorFlow Lite 量化模型轉換。

.blai 模型格式

IPROAI 使用自訂的 .blai 二進位模型格式。模型檔案包含以下區段：

  • Header（32 bytes）：8 個 uint32 欄位，記錄各區段大小
  • CPU 指令區段：層定義、連接關係、量化參數
  • NPU 指令區段：NPU 硬體指令（每條 16 bytes）
  • 權重區段：INT8 量化權重資料
  • 偏置區段：INT32 偏置資料
  • Multiplier/Shift 區段：per-channel 量化參數

模型載入方式

從 SD 卡載入 
/* 模型儲存於 SD 卡 /sdcard/ai_model/person_pet_detect.blai */
iproai_model_hdl_t hdl = iproai_create();
uint8_t *buf = load_file_to_buffer("/sdcard/ai_model/person_pet_detect.blai");
IPROAI_Status_e status = iproai_load_model_from_buffer(hdl, buf);
vPortFree(buf);  /* 載入後可釋放暫存區 */
從 Flash 分割區載入 
/* 模型燒錄於 "mfg" 分割區，模型 blob 位於分割區起始位址 + 0x1000 */
uint32_t flash_addr, part_size;
hal_boot2_partition_addr_active("mfg", &flash_addr, &part_size);

uint8_t *buf = pvPortMalloc(model_size);
flash_read(flash_addr + 0x1000, buf, model_size);

iproai_model_hdl_t hdl = iproai_create();
iproai_load_model_from_buffer(hdl, buf);
vPortFree(buf);

模型存放於可抽換的 mfg 分割區，與韌體分離。可使用官方燒錄工具的 AI 模型欄位單獨更新模型，不需重新編譯或重燒韌體。

低功耗 PIR 觸發 AI 攝影機設計模式

SDK 已驗證的端側 AI 攝影機設計模式，整合 PIR 感測器、ISP、NPU 推理與 USB UVC 輸出：

  • PIR 觸發喚醒 → ISP 抓取 640×360 ARGB 影像 → NPU 推理 → 結果經 SPI/USB 上報主控端
  • YOLOv8 偵測模型於啟動時載入一次後常駐 PSRAM；低功耗睡眠期間保留，喚醒後免重新載入
  • 另有命令模式變體：由外部主控 MCU 經 SPI 主從協議主動發起拍攝與推理請求，適合將 IPRO7AI 作為協同處理器整合進更大的系統

NPU 嵌入式視訊串流 over Thread

以 NPU 執行 autoencoder，將 640×320 RGB 影格壓縮為 400-byte embedding（壓縮比超過 1500:1）後經 Thread（IEEE 802.15.4）UDP 串流，接收端再以 NPU 解碼還原影像並輸出 UVC webcam 畫面——讓視訊得以在 250 kbps 的低功耗 mesh 網路上以約 2–3 fps 串流。架構與傳輸設計詳見 Matter & Thread：NPU 嵌入式視訊串流。

開發指南

將 AI 推理加入你的應用

完整推理範例 
#include <iproai_core.h>
#include <iproai_def.h>
#include "hal_npu.h"
#include "detect/yolov8_person_pet_detect.h"

static iproai_model_hdl_t g_hdl = NULL;

int my_ai_init(const uint8_t *model_data)
{
    /* Step 1: 啟用 NPU 時脈 */
    GLB_PER_Clock_UnGate(GLB_AHB_CLOCK_MM);

    /* Step 2: 建立模型實例 */
    g_hdl = iproai_create();
    if (!g_hdl) return -1;

    /* Step 3: 載入模型 */
    IPROAI_Status_e status = iproai_load_model_from_buffer(g_hdl, model_data);
    if (status != IPROAI_STATUS_NO_ERROR) return -2;

    return 0;
}

int my_ai_inference(uint32_t image_addr)
{
    /* Step 4: 設定外部影像位址（NPU 直接讀取） */
    NPU_Img_Ext_Addr_Cfg(image_addr);

    /* Step 5: 執行推理 */
    IPROAI_Status_e status = iproai_startCompute(g_hdl);
    if (status != IPROAI_STATUS_NO_ERROR) return -1;

    /* Step 6: 後處理 */
    struct iproai_net_info_t *net = iproai_getNetInfo(g_hdl);
    uint8_t *data_buf = iproai_getInputBuffer(g_hdl);

    yolov8_config_t yolo_cfg;
    yolov8_result_t result;

    yolov8_person_pet_init(&yolo_cfg, net);
    yolov8_person_pet_process(&yolo_cfg, net, data_buf, &result);
    yolov8_person_pet_print_results(&result);
    yolov8_person_pet_deinit(&yolo_cfg);

    return result.num_detections;
}

External Buffer 連續推理模式

適用於 ISP 連續輸出影像的場景。使用 FreeRTOS Queue 將影像位址推送至推理任務：

記憶體考量

  • PSRAM 為必要：CONFIG_AI_SUPPORT 會自動啟用 CONFIG_USE_PSRAM，模型權重與中間結果存放於 8 MB PSRAM
  • 模型大小：典型 YOLOv8 模型約 200 KB - 2 MB（.blai 格式）
  • 推理暫存：推理過程中需要額外的中間 buffer（自動管理），建議確保有足夠的 heap 空間
  • Activation 記憶體預算：NPU activation buffer 約為「輸入像素數 × 64 bytes」，上限為 8 MB PSRAM。提高輸入解析度前請先估算 activation 佔用
  • 睡眠保留：PSRAM 在低功耗睡眠期間保留內容，模型無需重新載入

效能與優化

效能參考

指標 數值
NPU 峰值算力 0.1 TOPS (INT8)
量化精度 INT8 (per-channel)
輸入格式 640x360 RGB888 / ARGB
YOLOv8 偵測閾值 Confidence: 0.25, IoU: 0.45
最大偵測數量 50（NMS 後）

優化建議

  • 使用 NPU 加速層：確保 Conv / Pool / FC 層在 NPU 上執行，避免不必要的 CPU fallback
  • 減少模型大小：使用更小的輸入解析度、減少通道數、裁剪不需要的類別
  • 啟用 PSRAM 睡眠保留：避免每次喚醒都重新載入模型
  • 使用 External Buffer 模式：透過 NPU_Img_Ext_Addr_Cfg() 讓 NPU 直接讀取 ISP 輸出，減少記憶體拷貝
  • 預分配記憶體池：YOLOv8 後處理使用 mem_pool 預分配 buffer，避免推理期間動態配置
  • 檢視 Profiling：每層執行時間（per-layer profiling）預設即會輸出；設定 CONFIG_AI_DEBUG=y 可額外查看算子執行細節與每層指令

雲端 LLM Agent

⚠ Release SDK 注意事項：ai_client 元件未包含於 Release SDK v1.2.1，本節內容為能力展示。需要此元件請聯絡原廠取得。

除了端側 NPU 推理之外，IPRO SDK 透過 components/ai_client/ 提供完整的雲端 LLM agent 框架。它把多家供應商封裝成統一介面，內建 ReAct 工具呼叫迴圈，可在 IPRO7AI 直接執行對話式 agent，搭配 BLE 與感測器建立 IoT × LLM 應用。請注意：IPRO7AI 本身不含 Wi-Fi，網路連線可透過內建乙太網路（RMII EMAC）或 IPRO6 companion 晶片（SDIO，Wi-Fi 擴充方案，需另行取得）提供，HTTPS 流量經 lwIP + mbedTLS 送出。

支援的供應商

每家供應商都實作為一個 ai_provider_t，負責 request 組裝、HTTP 呼叫與 streaming 解析。應用層只需要選擇 provider 並提供 API key。

  • Anthropic Claude — ai_provider_claude（ai_claude.h）
  • OpenAI — ai_provider_openai（ai_openai.h）
  • Google Gemini — ai_provider_gemini（ai_gemini.h）
  • MiniMax — ai_provider_minimax（ai_minimax.h）

ReAct 迴圈與工具呼叫

ai_agent_process() 會處理完整的 reason-act-observe 迴圈：模型回傳 tool_call → SDK 透過 ai_tool_dispatch_fn 執行 → 結果寫回 history → 再次呼叫模型，直到 AI_CLIENT_MAX_TOOL_DEPTH（預設 5）或得到最終文字。tool schema 依三種格式欄位提供（Anthropic tools_json / OpenAI tools_json_openai / Gemini tools_json_gemini），MiniMax 沿用 OpenAI 格式：

最小整合範例 
#include "ai_agent.h"
#include "ai_claude.h"

static int my_tool_dispatch(const char *name, const char *input,
                            char *output, uint32_t size)
{
    if (strcmp(name, "read_temperature") == 0) {
        snprintf(output, size, "{\"temp_c\":%.1f}", sensor_read_temp());
        return 0;
    }
    return -1;
}

void ask_ai(const char *user_text)
{
    ai_agent_ctx_t ctx = {
        .provider      = &ai_provider_claude,
        .api_key       = CONFIG_CLAUDE_API_KEY,
        .model         = "claude-sonnet-4-5",
        .system_prompt = "You are an embedded assistant.",
        .user_text     = user_text,
        .tools_json    = TOOLS_SCHEMA_ANTHROPIC,
        .tools_count   = 1,
        .tool_dispatch = my_tool_dispatch,
    };

    char reply[1024];
    if (ai_agent_process(&ctx, reply, sizeof(reply)) == 0) {
        printf("AI: %s\n", reply);
    }
}

另提供 ai_agent_process_streaming() 串流版本：回覆以逐句 callback 交付，並可透過 on_preflight callback 在工具執行前取得中間文字；供應商不支援串流時自動退回同步版 ai_agent_process()。

啟用方式

.config 
CONFIG_AI_CLIENT_ENABLE=y
CONFIG_AI_CLIENT_MAX_TOOL_DEPTH=5
CONFIG_AI_CLIENT_REQ_BUF_SIZE=16384
CONFIG_AI_CLIENT_RESPONSE_MAX=32768
# 依賴：網路連線（乙太網路 RMII，或經 IPRO6 companion 擴充 Wi-Fi）、
#       json_utils、net_utils、mbedTLS（HTTPS）

呼叫 ai_agent_init() 一次以建立序列化 mutex；之後可從多個 task 安全呼叫 ai_agent_process()。
