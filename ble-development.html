BLE 開發指南

本指南介紹如何使用 IPRO SDK 的 BLE 協定棧開發藍牙低功耗應用。SDK 採用 Zephyr BLE Host Stack 搭配 RivieraWaves 預建構控制器，功能範圍依所選 Controller profile 決定。

Zephyr BLE Host 架構

IPRO SDK 的作業系統是 FreeRTOS——Zephyr 在 SDK 中的角色是 BLE Host 協定堆疊的來源，而非 RTOS kernel。components/wireless/bluetooth/ipro_bt_host/ 移植自 Zephyr BLE Host（GAP、GATT、L2CAP、SMP、ISO、LE Audio），透過 port/ 移植層執行於 FreeRTOS 之上，應用程式一律使用 Zephyr 風格的 bt_* API 開發。

  • Host — Zephyr 4.4 原始碼：ipro_bt_host/ 自 Zephyr 移植，完整原始碼隨 SDK 提供，可直接閱讀與除錯
  • Controller: ipro_ble_controller/lib/ — 16 個 IPRO7 與 6 個 IPRO6S 預編譯函式庫，配置矩陣見下方。
  • RTOS — FreeRTOS：排程、佇列、計時器皆由 FreeRTOS 提供；Zephyr kernel 不存在於系統中
延伸閱讀：完整的 Host 架構指南（BLE Host Architecture Guide）未隨附於 release 套件，如需取得請聯絡原廠。

協定棧架構

BLE 協定棧採用 Host + Controller 雙層架構，透過片上 HCI 介面通訊（無 UART HCI 傳輸）：

Application Layer
GAP / GATT Services / Profiles
BLE Host (Zephyr 4.4)
GAP / GATT / L2CAP / SMP / ISO
HCI (On-Chip)
ipro_ble_ctlr_hcitl
BLE Controller (RivieraWaves)
Link Layer / PHY (1M/2M/Coded)

核心概念

  • Zephyr BLE Host：即使在 FreeRTOS 上也使用 Zephyr BLE Host Stack，應用程式透過標準 bt_* API 操作
  • RivieraWaves 控制器：以預建構靜態庫形式提供，負責 Link Layer 與 PHY 管理
  • 片上 HCI：Host 與 Controller 之間使用片上 HCI 通訊，無需 UART HCI 傳輸層
  • 回調驅動：所有非同步事件（連線、斷線、通知）透過回調函式處理

基本 BLE 選擇 CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"；BLE 5.4 與兩路 ISO 串流（CIS/BIS）選擇 "bt54_iso2"，後者要求 CONFIG_EM_SIZE 至少 32 KB。Host 連線上限不可超過控制器容量；PDM 請保留 link2／CONFIG_BT_CONN=1 配置。

CONFIG_BT_HOST_IPRO_V44=y
CONFIG_IPRO_BLE_CTLR_LIB="link1_periph"
CONFIG_IPRO_BLE_CTLR_FEATURE="bt52"
CONFIG_IPRO_BLE_CTLR_CFG_DBG=n
CONFIG_BT_CONN=1
CONFIG_EM_SIZE=16

IPRO6S BLE + BR/EDR

IPRO6S 共用 Zephyr 4.4 Host，另選雙模控制器。本版含六個 libipro_ble_controller_ipro6s_link{1,2,4}_br[_release].a（RivieraWaves v13.0.18），與 IPRO7 v14.0.2 分開。未附 _pawr 函式庫，單獨啟用 Kconfig 選項不會提供該變體。

以 apps/platform/ipro6_btdm_phyrf/.config 為起點：CONFIG_IPRO6=y、CONFIG_BTDM_ENABLE=y、CONFIG_BTDM_BT_ENABLE=y、CONFIG_BTDM_MAX_ACL_CONNECTIONS=4。範例示範 A2DP sink（SBC）、AVRCP、HFP-HF 與 SCO 至 I2S 音訊。

./build_freertos.sh ipro6_btdm_phyrf build
呼叫 bt_enable() 前須先初始化 Controller 與 HCI driver。完整初始化範例請見教學。

API 模式

應用程式使用 Zephyr 風格的回調驅動 BLE API。舊版 RivieraWaves ke_msg 訊息傳遞機制僅限控制器內部使用，不對應用程式暴露。

GAP：廣播與掃描

GAP 廣播操作 
#include <zephyr/bluetooth/bluetooth.h>
#include <zephyr/bluetooth/conn.h>

/* 廣播資料 */
static const struct bt_data ad[] = {
    BT_DATA_BYTES(BT_DATA_FLAGS,
                  BT_LE_AD_GENERAL | BT_LE_AD_NO_BREDR),
    BT_DATA_BYTES(BT_DATA_UUID16_ALL,
                  0x0d, 0x18),  /* Heart Rate Service */
};

static const struct bt_data sd[] = {
    BT_DATA(BT_DATA_NAME_COMPLETE, "IPRO Device", 11),
};

/* 開始可連線廣播 */
bt_le_adv_start(BT_LE_ADV_CONN_NAME,
                ad, ARRAY_SIZE(ad), sd, ARRAY_SIZE(sd));

/* 停止廣播 */
bt_le_adv_stop();

/* 開始掃描（Central 角色） */
bt_le_scan_start(BT_LE_SCAN_ACTIVE, scan_cb);

連線回調

連線管理 
static void connected(struct bt_conn *conn, uint8_t err)
{
    if (err) {
        printk("Connection failed (err %u)\n", err);
        return;
    }
    printk("Connected\n");
}

static void disconnected(struct bt_conn *conn, uint8_t reason)
{
    printk("Disconnected (reason %u)\n", reason);
}

static struct bt_conn_cb conn_callbacks = {
    .connected = connected,
    .disconnected = disconnected,
};

void app_init(void)
{
    bt_conn_cb_register(&conn_callbacks);
    bt_enable(bt_ready);
}

GATT：服務註冊

靜態 GATT 服務定義 
#include <zephyr/bluetooth/gatt.h>
#include <zephyr/bluetooth/uuid.h>

/* 自訂 UUID */
static struct bt_uuid_128 my_svc_uuid = BT_UUID_INIT_128(
    0xf0, 0xde, 0xbc, 0x9a, 0x78, 0x56, 0x34, 0x12,
    0x78, 0x56, 0x34, 0x12, 0x78, 0x56, 0x34, 0x12);

static struct bt_uuid_128 my_char_uuid = BT_UUID_INIT_128(
    0xf1, 0xde, 0xbc, 0x9a, 0x78, 0x56, 0x34, 0x12,
    0x78, 0x56, 0x34, 0x12, 0x78, 0x56, 0x34, 0x12);

static uint8_t my_value[256];

/* 讀取回調 */
static ssize_t read_my_char(struct bt_conn *conn,
                            const struct bt_gatt_attr *attr,
                            void *buf, uint16_t len, uint16_t offset)
{
    return bt_gatt_attr_read(conn, attr, buf, len, offset,
                             my_value, sizeof(my_value));
}

/* 使用巨集定義服務（編譯期靜態註冊） */
BT_GATT_SERVICE_DEFINE(my_svc,
    BT_GATT_PRIMARY_SERVICE(&my_svc_uuid),
    BT_GATT_CHARACTERISTIC(&my_char_uuid.uuid,
                           BT_GATT_CHRC_READ | BT_GATT_CHRC_NOTIFY,
                           BT_GATT_PERM_READ,
                           read_my_char, NULL, my_value),
    BT_GATT_CCC(NULL, BT_GATT_PERM_READ | BT_GATT_PERM_WRITE),
);

/* 發送 GATT 通知 */
bt_gatt_notify(conn, &my_svc.attrs[1], my_value, sizeof(my_value));
提示：舊版 RivieraWaves ke_msg API 已棄用；控制器初始化仍使用 ipro_ble_controller.h 的 ipro_ble_ctlr_controller_init()（見 API 參考），與 Zephyr bt_* Host API 並用。所有新應用程式的 Host 層功能應使用 Zephyr bt_* API。

LE Audio 生態系統

LE Audio 需設定 CONFIG_IPRO_BLE_CTLR_FEATURE="bt54_iso2"；標頭位於 ipro_bt_host/upstream/zephyr/include/zephyr/bluetooth/audio/。

LE Audio Profiles

Profile 全名 功能
BAP Basic Audio Profile 音訊串流管理（單播/廣播）
CAP Common Audio Profile 協調設備集合的音訊操作
VCP Volume Control Profile 音量控制
MCP Media Control Profile 媒體播放控制
CSIP Coordinated Set Identification Profile 協調設備識別（如左右耳機配對）

LC3 編解碼管線

LE Audio 使用 LC3 (Low Complexity Communication Codec) 作為強制編解碼器，位元率與延遲取決於協商的 codec preset、傳輸及應用緩衝。音訊資料透過 Isochronous Channels (CIS/BIS) 傳輸。

CONFIG_IPRO_BLE_CTLR_CFG_DBG=n

PAwR 與 ESL 的交付範圍

V2.0.1 的 Host 標頭包含週期性廣播相關介面，但 Release 未附 PAwR／ESL 完整應用，也沒有獨立的 _pawr Controller 函式庫。不能只因標頭或設定選項存在，就認定選用的 Controller 已支援完整功能。

若需評估此功能，先向 INTELPRO 確認對應 Controller、Host 設定與測試韌體，再依本版 zephyr/bluetooth/bluetooth.h 的 API 整合。使用一般 BLE 範例時，沿用其已附的 Controller 組合。

BLE 低功耗驗證

從已交付的設定開始：ipro_ble_remote 使用 link1_periph / bt52；ipro_pdm_mic_demo 使用 link2 / bt52，Host 設為單一連線。兩者使用 16 KB EM；bt54_iso2 至少需要 32 KB EM，不能直接套用相同的 16 KB 保留記憶體配置。

一般低功耗測試可從 apps/test/ipro_lp_test/ 開始，依該範例的 pds 命令與板級設定測試。記錄板型、電源量測位置、喚醒來源、廣播／連線狀態與外設工作狀態；電流及喚醒時間須以實測為準。

進入睡眠前處理 DMA、音訊、計時器與 Flash 寫入；依所選模式確認 OCRAM／PSRAM 保留及喚醒後外設恢復。BLE 配對資料需另由 Settings 後端保存，不能以 RAM 保留取代持久儲存。

應用框架

BLE 應用採用 Mediator 設計模式，將複雜的藍牙功能分解為可重用的元件：

元件 角色 說明
Mediator 協調者 管理 Applet 之間的互動與生命週期，負責整體流程控制
Applets 可重用元件 封裝特定功能（如廣播管理、GATT 服務、音訊串流），可在不同應用間共用
Intermediaries 協議橋接 在不同協議層之間轉換資料格式，例如將應用層命令轉為 BLE GAP/GATT 操作

此框架主要用於 LE Audio 應用（如 GAF、BAP、VCP、MCP、CAP），將複雜的音訊管理邏輯模組化。
